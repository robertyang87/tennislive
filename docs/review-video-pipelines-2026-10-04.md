# 三条视频流水线审查与减负（2026-10-04）

基线 commit：`4adb2769d4a2b41b6cc18994c0b0513d8dee618a`。范围为赛场之上、赛后开麦、网球有故事的备料、转写、TTS、渲染、质检、Actions、派发和资源生命周期。本轮修改交付为独立分支；没有触发视频生产、微信推送、重渲历史成片或改写 Git 历史。

## 结论

主要浪费来自无关输入的处理、重复外部请求、编码线程超售、失败重试与素材检出，而不是单纯画质参数过高。保持成片画幅、帧率策略、编码质量、原声与双 ASR/比分/封面检查；优先减少这些无效工作。

三条主实现合计超过 3.3 万行。大规模拆文件会扩展回归面，本轮以行为修复为单位，清掉确认失效的分支，不为行数好看重写整套系统。

## 已测收益与适用边界

- 集锦：四核 affinity、四段各四秒、1080×1440 合成样本；原自动线程 2.403/2.068 秒，新预算 1.787/2.103 秒。平均 **2.236→1.945 秒，约 13%**，逐帧 SSIM **1.000000**。样本短且有波动，不能外推完整成片承诺。
- 采访：真实 FFmpeg 将 100 秒合成 WAV 中的 10 秒正文裁为 26 秒含上下文的输入，ASR 输入量减少 **74%**。未运行在线/真实 ASR 模型；没有声称词错率不变或推理实际提速 74%。原有双 ASR 分歧和空档检查仍执行。
- 解说：N 段配字幕的组装少启动 N 次 FFprobe；导入阶段少读取/缩放 14 张选题图片；没有改变渲染照片的裁剪或压缩参数。
- artifact：3,567,085 字节 H264 合成样片，gzip level 6 耗时 0.1507 秒仅省 0.004%；level 0 耗时 0.0063 秒。这是本地压缩实验，不是网络上传 SLA。
- 官方图轮询：按相同 HEAD 的 Git blob 字节统计，检出内容 **1,200.20 MiB→52.96 MiB，减少95.59%**；不是 pack 网络流量或已上线测得的秒数。
- 资源：删除 17 个确认可再生的缓存/预览，合计 **904,958 字节**。它减少 HEAD 检出负担，不缩小历史 pack。

## 资源和历史不能混为一谈

本次完整核对 HEAD 的 `assets` 为约 **1,139 MiB**（按 Git blob 字节统计，其中 `assets/reel` 740.8 MiB）。GitHub repo 元数据 `size=17142462 KiB` 约 16.35 GiB，包括历史口径，不能将两者相减后宣称全是垃圾。核实无关检出可以直接省资源；清空旧输出或重写历史则可能破坏历史消息、CDN 和审计链。

## 验证与剩余边界

验证包括行为回归、真实 FFmpeg 合成媒体、缓存并发/损坏恢复、工作流 shell 语法及实际清理动作。一次全量 `pytest -q -n 4 --dist loadfile --durations=25` 用时 412.02 秒：5613 passed、234 skipped、70 subtests passed，另有4项失败。失败逐项处理：两项权限判据更新为实际 outbox 提交链；两项采访 Git 重试行为揭示空 `RUNNER_TEMP` 被拼成 `/workbench`，已改独立 `mktemp` 并补清理与旧图隔离。原失败项在最终定向回归中通过；未把首轮全量报告改写成零失败。

最终另跑核心新增/派发/工作流组合 **70 passed**；采访重试 **4 passed**（含环境参数化）。采访下载/ASR、派发及权限最终组合 **116 passed**；共享缓存/旧TTS重试、编排另有定向回归；`ruff --select F821` 与 `git diff --check` 通过。234项跳过不计作验证通过；历史已发诊断仍报告既有债务，不代表旧片已重新审听。

采访提交重试工作台使用 `${RUNNER_TEMP:-${TMPDIR:-/tmp}}` 下的唯一临时目录；恢复与异常退出均清理，不复用上一趟图片。

本环境没有生产 TTS/ASR 密钥，未发起收费合成，也未自动发布内容。本轮能验证代码路径、数据边界、合成媒体和既有回归；不能把这些称为已对所有历史成片进行人工听审。首条新生产片仍必须执行原有成片质检。
