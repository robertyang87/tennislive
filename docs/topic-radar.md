# 选题雷达：把每天的新闻提炼成选题

`flash-radar` 和 `topic-radar` 是两件事，共用同一批扫来的信号：

| | 出什么 | 形状 |
|---|---|---|
| `flash-radar` | 快讯候选 | 一条新闻 → 一张卡，讲「发生了什么」 |
| `topic-radar` | **选题候选** | **新闻钩子 + 底下压着的常青线**，`docs/newshook-topics.md` 那个形状 |

两步都跑在 `news-radar` 工作流里（每天 09:13 / 21:13 北京时间），各推一条微信。

---

## 机器做两件事，人做第三件

1. **聚类**——同一天里几家在报同一件事才算一个新闻点。
2. **对角度**——拿这一簇去撞 `research/topic_radar.ANGLES`，一张人工维护的表
   （2026-07-29 起 20 条：第一批十条实跑下来每天有三四个簇撞不上，
   补角度是让候选变多最直接的办法；**但每条仍然要有能翻的出处**，
   补角度不是放宽标准）。
3. **核实和写稿**——人。**角度是对上的，事实一条都没核。**

### 聚类的判据：共享至少一个专名，且总共享词不少于两个

两个条件都要，各挡一类错：

- 只看专名 → 「Washington」能把一整周的比赛全并成一簇
- 只看词数 → 「breaks」「2026」这种满天飞的虚词凑够两个就成簇

实测两个假阳性，都是只满足一个条件时并出来的：

| 并错的两条 | 共享的是 | 并完撞上 |
|---|---|---|
| `Wimbledon ... breaks attendance record` + `Atmane gains Tiafoe revenge, breaks home hearts` | `breaks` | 屋顶与天气（`rain-free` 里的 rain） |
| `US Open Mixed Doubles entries` + `Shelton on 2026 season` | `2026` | 混双改制 |

**看着像模像样，全是错的。** 加上「必须共享专名」之后两个都不成簇，而真实的
7-25 那簇（Sinner/Djokovic 退赛蒙特利尔，5 家在报）照样成立。

两个配套细节，都是踩出来的：

- **句首那个词也算专名**。一开始为了躲「句首大写不代表专名」把 position 0
  排除了，结果 `Draper withdraws from Washington` 这种最常见的标题形状
  （主语打头）直接失去主判据
- **专名和普通词要用同一把尺切**。原来专名的正则把连字符算进词里
  （`Minaur-Boulter` 是一个 token），普通词的 `_WORD` 会切成两个——两边对不上，
  `proper & shared` 就会莫名其妙地空掉

### 对角度：触发词要在簇里至少两条标题上出现

不是「组里任何一处出现过」。差别很大：一簇里只有第一条带 `mixed` / `doubles`，
按「任何一处」就会判成「混双改制」——而那一簇本身就是并错的，角度再一叠，
错上加错。

**撞不上就不猜。** 没对上的簇进 `unmatched_clusters`，高频词进 `unmatched_terms`
——那是「该往 `ANGLES` 里补什么」的线索，不是失败。

⚠️ **那份清单的排序必须是确定的。** 第一版用 `Counter.most_common`，而在计数
全部相同时它按插入顺序返回，插入顺序又来自遍历 `set`——字符串的 set 顺序取决于
`PYTHONHASHSEED`，每个进程都不一样。本地过、CI 红就是这么来的；更糟的是这份
清单本来是给人看「该补什么角度」的，**每次随机取八个等于没写**。现在按
`(-次数, 词)` 排，并且不报聚类用的拼接词（`ballkidsquad` 这种人读起来是噪点）。
判据见 `test_该补什么角度那份清单必须是确定的`——拿四个不同的 `PYTHONHASHSEED`
各跑一遍，结果必须一模一样。

---

### 触发词要挑「只有这类新闻才会用的词」

两类哑弹，都出现过，而且都**不吭声**：

- **每周都会撞上的词。**「退役与告别」原来带着 `final` 和 `last`——
  「reaches final」「into final」两条标题就够两条了，于是每个赛事周都自动
  长出一条假的「退役与告别」。同一天实跑里，「球员工会与诉讼」的 `court`
  把「Alexandrova collapses **on court**」配了进来。判据见
  `test_触发词不能是每周都会出现的词`
- **切不出来的词。**`hawk-eye`、`12-day`、`no1`、`top10` 都当过触发词，
  **一次都没匹配上**：`_WORD` 把连字符和句点当分隔符，`No. 1` 切成 no / 1，
  `Top 50` 切成 top / 50。写进表里看着像在防守，其实什么也没做。
  判据见 `test_触发词必须是切得出来的词`

## 舆论热度：四个能查的证据，不是打分模型

| 证据 | 从哪来 | 权重 |
|---|---|---|
| `outlets` 几家在报 | 簇里不同来源的家数 | ×10，最重 |
| `days_running` 连着第几天 | 读昨天的 `topic_radar_queue.json` | ×6 |
| `zh_hits` 撞上几条中文热搜 | 微博 / 抖音 / 小红书 / 微信 | ×4，封顶 3 条 |
| `trend_hits` 撞上几条大众热搜 | Google 每日热搜（4 个地区） | ×3，封顶 3 条 |

**热搜只当加成**。那一路是大众热搜，足球运动员和流行歌手都在里面，撞上说明
这件事溢出了网球圈；但它也最容易误配，不能靠它单独把一条没人报的东西顶上来。
对法是**拿专名取交集**，不是拿整句去 `in`——用整句会把 `open` 这种词配上一切。

中文那一路比 Google 热搜重一点（×4 vs ×3）：**这个号的读者就在那几个平台上**，
中文那边热等于「我们的读者正在讨论」。但同样只是加成——判据见
`test_中文热搜只是加成不能单独把一条顶上来`。

## 媒体源：现状与缺口（2026-07-29 实测）

最近 5 天各源实际产出：

| 源 | 5 天合计 | 零产天数 |
|---|---|---|
| Google 热搜 US / HK / GB / AU | 各 50 | 0 |
| Top media（`tennis when:1d`） | 46 | 0 |
| ATP Tour | 43 | 0 |
| WTA | 16 | 0 |
| US Open | 2 | 3/5 |
| Wimbledon / Roland-Garros / Australian Open | **0** | **5/5** |

**三个大满贯零产是真空，而且是季节性的，不是查询坏了。** 直接打 Google News
的 RSS 验过：四个 `site:` 查询都返回 100 条，但最新一条分别是温网 **7/10**、
法网 **7/12**、澳网 **7/13**——赛季外它们就不发稿了，被 48 小时的新鲜度闸门
正常挡掉。**不用修**。

### 中文源（2026-07-29 接上）

原来一条中文源都没有，而「是不是舆论热点」完全由英文媒体的家数决定——
**中文那边炸了而英文没报的事，这套一点都看不见**。接上的第一天就撞见了这个
情况：微博热搜第 43 位挂着「郑钦文状态怎么了」，当天**所有**英文源里一条
相关的都没有。

实现在 `research/zh_trends.py`，四个源分三档，**照实记，不拿镜像冒充官方**：

| 源 | 路 | 状态 |
|---|---|---|
| 微博热搜 | `weibo.com/ajax/side/hotSearch` | ✅ 官方、免鉴权，51 条 |
| 抖音热搜 | `iesdouyin.com/.../hotsearch/billboard/word/` | ✅ 官方、免鉴权，50 条 |
| 小红书热榜 | 官方 `edith` 域 404、`www` 域 500 → UApiPro（主）+ 今日热榜（备） | ⚠️ 第三方，20 条 |
| 微信 | 只有 24h 热文榜（镜像），见下 | ⚠️ 镜像，30 条 |

**小红书主源用 JSON，不用 HTML。** 两边是同一份上游数据（实测当天第一条一字
不差），但 `uapis.cn/api/v1/misc/hotboard?type=xiaohongshu` 是 JSON 契约，
今日热榜是一段随时会被改掉的 `<table>`。HTML 那路留作备用，**退到备用要写在
状态里**——悄悄换源等于把「主源已经坏了」藏起来。

### ⚠️「微信热搜」至少是五种不同的东西

接之前先想清楚要哪一种，第三方接口经常把它们都叫「微信热搜」：

| | 是什么 | 我们能不能拿到 |
|---|---|---|
| ① 搜一搜热点词 | 关键词 + 排名 | ❌ 只有付费接口 |
| ② 公众号热点话题榜 | 关键词 + 指数 | ❌ 聚合数据卖的是这个，无 key 返回「错误的请求KEY」 |
| ③ **公众号 24h 热文榜** | 热门**文章标题** | ✅ **我们接的是这个**（镜像） |
| ④ 微信指数 | 某个词一段时间的趋势 | ❌ 无签名 `{"code":-1}`，签名要从小程序取 |
| ⑤ 视频号热点榜 | 视频号热门话题 | ❌ |

想要的其实更接近 ①/②。**但 ④ 就算拿得到也不是发现工具**——它是「给词查数」，
你得先知道要查哪个词，回答不了「今天什么热」。③ 是标题榜，反而是这几种里
最能拿来发现话题的。

免费那几家一个都没有微信：UApiPro 的 `weixin`/`wechat`/`wxhot` 一律
`invalid hotboard type`，DailyHotApi 的公开支持列表里也没有。**这是钱的问题，
不是接口选型的问题**——先攒两周 `zh_hot` 数据，看这两路到底贡献过几条网球
热搜，再决定值不值得买。

⚠️ **403 是缺请求头，不是被封。** 微博那个接口对 `python-urllib` 的默认 UA
直接 403，同一条 URL 换成浏览器 UA + `Referer: https://weibo.com/` 就是 200。
差点据此写下「微博热搜抓不到」——「空结果先自证是真空」的又一个变种。

#### 中文词怎么和英文簇对上

**两边没有任何共享的字符串**：「郑钦文状态怎么了」和
`Zheng Qinwen reaches quarterfinal` 直接取交集永远是空的。所以抓的时候就先过
一次译名表，把英文词（`qinwen` / `zheng`）挂在那一条上，热度那一步才有东西可交。
这是整条中文线唯一的接缝，断了等于没接（`test_中文热搜要先过译名表才能和英文簇对上`）。

关键词表怎么定，两条判据都是踩出来的：

- **单字译名一律丢掉。** 排名表里有 18 条机器音译只出了姓（`Jiaqi Wang` →
  「王」、`Boyoung Jeong` → 「郑」），拿它当关键词，一轮 150 条榜单里挡出
  **7 条纯噪声**——「王楚钦」「张泽禹」「齐达内出任」全被判成网球，还给
  「郑钦文状态怎么了」配上了一个韩国球员的英文词。
  （⚠️ 表里那 18 条本身也该补全，但补的是**真人的名字**，同一个读音有好几种
  写法，不能靠猜——留着没动。）
- **两个字的译名要有网球语境。** 表里有 154 个两字条目，其中「保罗」是保罗·乔治、
  「安倍」根本不是球员、「李娜」首先是歌手。所以两字名默认要同现一个网球线索，
  例外写在 `_SHORT_OK` 里，**判据是「这两个字在中文里既不是常用词，也不是别的
  名人的通用简称」**——「辛纳」过，「德约」不过（「**道德约**束」）。
- **挡掉的也要报出来**（`zh_near_miss`）。只在成功时出声的过滤器，
  没法证明它真的看过。

`zh_hot` 那一栏**不经过角度表**，在推送里单独占一块：中文平台上热而没有一家
英文媒体在报的事，既撞不上簇也撞不上角度，只有那一栏能让它被看见。

### 还没接的英文源

Tennis Majors、Ubitennis、Tennis365、Reddit r/tennis（后者本身就是舆论热度的
代理指标）。RSSHub 各路在这个环境里一律 403（Cloudflare，站点侧），
不是代理的问题。

## 用法

```bash
tennislive topic-radar --outdir output            # 默认 5 条候选，2 家在报算数
tennislive topic-radar --min-sources 3            # 收紧：三家在报才算
tennislive topic-radar --persist-days 3           # 往前看三天判断连续性
```

产物 `output/<日期>/topic_radar/topic_radar_queue.json` 自带诊断：
`news_signals` / `trend_signals` / `zh_scanned` / `count` / `unmatched_clusters` /
`unmatched_terms` / `zh_hot` / `zh_near_miss`
——**一条候选都没有时，能自己回答是「今天没热点」还是「热点都没撞上角度」**。

中文那几个源的状态也在 `source_status` 里，两个数都报（`扫 51 条 / 网球 1 条`）：
榜上一条网球都没有是**常态**，只报「中了 0 条」的话，它和「抓挂了」长得一模一样。
