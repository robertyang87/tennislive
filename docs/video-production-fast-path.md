# 两档视频的高效制作与技战术取材

2026-09-09 用户要求实施。入口：[耗时复盘](https://github.com/robertyang87/tennislive/pull/824)。

## 制作顺序

收到链接即在请求的 `received_at`（采访）或 `_production.received_at`（reel）记 UTC 原始时刻。修改和重试保留这一时刻，修订耗时单列。先确认同场素材、封面候选和发布文案，再做昂贵处理。

`push_reel.py --stage check` 是发布与前置预检共用的一套标题、标签和正文判据，不下载、不写复制页、不发送。正式采访/reel的render和cover工作流均前置调用。请求初次生成也调用。原有的真实TTS检查、双语/视觉/比分QC继续执行；共享代码一次全量，纯文案或局部素材修订按影响范围验证。

采访请求生成保存 `_request_origin`：比较请求是否真的改了，不再拿精修 spec 与旧请求的差异当作重建理由。已审字幕或已有 pushed.json 的旧稿自动保护；新修订在请求中给不同的 `revision` 和当前正式 JSON 文件字节的 `expected_spec_sha256`。这不是新增人工审批，而是自动调用者也必须携带的版本条件。写入前比较输入/spec/字幕/文案哈希，任务提交前比较远端同路径变化。源、窗口及切行预算不变时，只应用请求中实际变动的展示字段，保留精修字幕。明确重做全文使用 `_rebuild_once`，仍须满足受保护版本的新修订条件。

第一份ASR与翻译使用内容键和校验和缓存；文本/模型/译稿实现/翻译合同变化失效。缓存不是QC证明；独立第二份ASR及最终媒体检查照常进行。音频下载300秒是所有客户端合计预算，每档最多60秒。已有reel源片/TTS缓存与cover/narration/push局部路径继续复用，不为通知文字错误重做电影。

## 固定取材源及时间预算

- 本场事实优先：赛事官方、ATP/WTA战报、赛后采访。
- 技战术候选：[Brain Game Tennis](https://braingametennis.com/features/blog/)、[Tennis Abstract](https://www.tennisabstract.com/blog/)、[Hugh Clarke](https://hughclarke.substack.com/)。ATP/WTA与四大满贯官网入口见 `tools/tactical_research.py::SOURCES`。
- 不假定每场都有深度稿，不等文章发布。原生RSS/官网直链发现和可读正文提取总预算35秒；每次最多阅读6篇、每篇保留2个相关段落。与备料/采访ASR并行；成功缓存30分钟、空结果缓存3分钟；返回各源错误与时间。获取失败仍用已有官方事实继续制作。
- 同时出现两个名字仅标记 `candidate_match_report`，不是本场认证。老文章保留球员背景身份；RSS时间只是发布时间，不能代替比赛日期。不能把预告、别轮交手或历史打法自动套成本场调整。

直接取材：

```sh
python tools/tactical_research.py --home 'Aryna Sabalenka' --away 'Linda Noskova' --event 'US Open' --year 2026 --out /tmp/tactics.json
```

自动草稿保留 `_tactical_research`。制作执行者（包括自动编辑/QC）核实同场与画面后，向同一packet增加 `claims`。每条结构：

```json
{
  "claim": "本场可证明的技战术解释",
  "url": "已读取的专业报道URL",
  "evidence_excerpt": "必须逐字存在于该报道已保存段落的证据",
  "match_verified": true,
  "footage": {"source_url": "本场源片URL", "start": 10.0, "end": 20.0}
}
```

包的 `identity` 必须与当前home/away/event/year一致；报道观点与比分冲突时回到原声、官方统计和画面核对，不给模型自行裁定。`assemble_spec.py --tactical-packet /tmp/tactics.json` 只把通过来源/引用/身份/时间窗结构校验的观点加入原有事实包；下游视觉与正式spec检查仍须通过。**结构校验不能证明语义正确，不能由抓取工具自行把 match_verified 改成 true。** 资料抓取失败和观点尚未核验均有可见状态；不虚称已经自动完成技战术分析。

采访也收集和保留资料，供理解网球术语、背景和编辑收尾使用；绝不把报道内容追加为球员原话，不改写翻译来塞分析。

## 解说稿和镜头要求

先写一个本场问题与有证据的回答，再安排开局、变化、结局。选择2–3个真正有证据的机制，不强凑数量：比分压力 → 可见的发球/接发/深度/变线/脚步选择 → 对手被限制的选项 → 下一拍或比赛后果。每条机制保留报道URL、证据原文和镜头时间码；全场结论须有全场数据，单个回合只能证明这一分。

文案与镜头对照表一次定稿：源片起止、比分/动作、旁白、依据、原声留白。每个长回合只解释关键选择，删除重复的“继续来回”“谁都不肯松手”。用短句、具体动词，真实TTS测长后锁切点，避免靠加速塞满画面。原声击球、关键分与真实表情承担情绪；封面承诺在正文兑现，不能猜心理或夸大纪录。

新采访自动冷开场目标12秒，完整cue边界通常不超过15秒；找不到合适窗口明确等待补素材，不硬截半句话。显式人工指定的窗口仍保留。新reel统计卡：完整获胜一分→庆祝/握手→全画布卡片10秒→品牌片尾。沿用用户参考图与尺寸；已发布视频不追改。

## 实测与边界

SLA v2绑定当前spec/film哈希和run，旧修订进入history；采访生成新film时不再沿用旧film的SLA。原始请求时刻有提供时另报request_to_artifact_seconds。阶段边界记录可区分预检、ASR和渲染；工作流任务日志仍是排队/安装/QC/发布用时的依据。没有记录的阶段不推算成精确数。

10分钟是待实测的正常素材出片目标，不是本次代码修改已证明的成绩。分别统计两档连续10条新片的首次通过率、请求至成片、发布等待与重试原因。QC通过按既有授权自动推送；成功回执的成片不重发。
