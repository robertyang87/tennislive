# 逐帧比分板缓存与编码前字幕预览

这两个功能用于减少同一期修订时的重复扫描和整片编码返工。现场原声的处理参数、最终编码画质、固定居中铺满画布及成片质量检查保持原有规则。

## 比分板仍然逐帧变化

缓存保存的是原生检测器生成的完整透明蒙版视频，不是比分板截图。蒙版记录每一帧哪些源像素要保留，真正的名字、比分和提示文字仍取自同一时刻的原视频。

- 板变宽或变窄，各帧仍用各自的有效外缘，不扩大成整段固定矩形。
- BREAK/SET/MATCH POINT 等提示条保持原生出现、消失及宽高变化；提示条旁的背景保持透明。
- 无板帧保持透明，不把上一帧的板延续到近景、回放或赛果图。
- 字幕落点仍用实际测量后的几何，不用原始搜索框代替比分板上缘。

`build_match_reel.render()` 对美网、纳达尔学院、ATP、WTA、比利·简·金杯、拉沃尔杯六种原生逐帧检测器统一调用 `tools/scoreboard_mask_cache.py`；旧版带式测量保持原路径。

缓存身份包含源视频完整文件 SHA、选段顺序及窗口、速度、精确帧率、溶解尾料、允许回贴窗口、搜索几何和检测实现及运行版本。仅改旁白或字幕文字不改变这些输入时可以复用。修改素材、时间窗、帧率、宽高或检测代码会重新测量。首版按整组选段缓存，改动一个测量输入会重扫整组。

读取缓存前核对文件校验和和媒体信息，并恢复检测器实际修改后的段落几何。缺失、不完整或损坏的缓存不视为通过，会重新走原生扫描；原生检测失败继续阻断。缓存中的扫描记录用于描述实际测量，不是成片 QC 凭证。

本地缓存目录由 `TENNISLIVE_SCOREBOARD_MASK_CACHE` 设置。Actions 只在 `render` 恢复独立蒙版缓存；只有本次完整写入且实际成片 QC 通过后才保存。源片、配音缓存、发布账本和微信回执走各自原有流程。

## 字幕预览的边界

预览读取真实源帧、实际配音词边界生成的最终 ASS 和实际逐帧蒙版，使用原生裁切及字幕滤镜。它帮助编码前检查字幕是否贴近比分板、是否遮挡提示条和赛果图。它不证明转场、声音、节奏或全片质量合格，不能用于发布。

预览输出必须位于独立制作目录，不能覆盖已发布产物；不会创建成片、QC 凭证或推送记录。最终影片仍须运行原生全片 QC、实际审片、发布版本校验和唯一微信发送账本。

已有源片时运行：

```bash
PYTHONPATH=src python tools/preview_reel_captions.py \
  --spec specs/reels/<slug>.json \
  --source main=/path/to/source.mp4 \
  --outdir /tmp/reel-preview-v1 --max-frames 8
```

`main` 必须是当前 spec 的真实源键；空键主源写 `--source =/path/to/source.mp4`。多源重复传参，已有文件通过链接使用，无需复制。实际配音仍按原生内容键复用，缓存缺失时合成真正的配音及词边界，不用估算时间代替。

默认最多 8 帧，优先显式字幕位置窗口中的不同高度，再看位置切换两侧和破发点、盘点、赛点相关字幕及长行字幕。检测报告里的宽度和提示条集合没有逐帧时间戳时，预览不据此虚构变化时刻，也不宣称覆盖所有变化。已核对关键时刻可显式指定：

```bash
PYTHONPATH=src python tools/preview_reel_captions.py \
  --spec specs/reels/<slug>.json --source main=/path/to/source.mp4 \
  --outdir /tmp/reel-preview-v2 --cue 1,5 --at 73.4 --max-frames 3
```

`--cue` 为原生字幕列表从 1 开始的序号；`--at` 为包含封面的成片时间，不是源片时间。输出 PNG 与 `preview_manifest.json`，记录实际源时刻、成片时刻和源片、蒙版、ASS、图像的哈希。修改后使用新的预览目录，避免混入旧样张。预览本身不产生声音。

## 真实蒙版实测

帕奥利尼对贝莱克已核源片，源 SHA `2fd4166d…`，25/1 fps，完整 17 段中 15 段回贴，沿用全部原生允许窗口和溶解尾料：

| 调用 | 本地实测 | 结果 |
|---|---:|---|
| 最终实现首次生成并校验、保存蒙版 | 78.730 秒 | 原生逐帧扫描 |
| 最终实现同输入再次调用 | 2.316 秒 | 校验并复用全部蒙版 |
| 初次实现仅修改旁白 | 2.142 秒 | 相同蒙版命中 |
| 初次实现起点从 286.96 前移至 286.92，保留合法允许窗口 | 75.979 秒 | 输入变化，重新原生扫描 |

冷／热两次的 15 份蒙版字节、全部 **7881 帧**灰度序列、最终源几何和原生扫描事实完全一致。其中 **4243 帧**有提示条、**1052 帧**为透明缺板帧，**12 段**实际透明外缘发生变化，验证并非固定宽度或常驻提示条。缓存两份成功条目共约 2.36 MB，没有复制源视频。

初次实现完整结果为 78.857→2.219 秒；接线复审补上了工作流 `~` 缓存路径展开，最终实现重新测完整冷／热调用，并核对全部解码序列与初次实现一致。原始文案及变窗实测保留其原实现 SHA，不把旧测量重标为新实现结果。字面 `~` 环境变量的实际写入及命中也有独立检查。

这是同一工作区的单次局部比较，不是 hosted runner 总耗时或整条出片 SLA；首次生成包含缓存验证与保存成本。修订改变任何蒙版输入会重扫整组，本次未修改已发布影片或发送微信。

原生最终顶栏滤镜提取前后，full／band 与脚注、角标、字幕垫有无的 **16 种组合**生成的滤镜字符串逐字节相同。证据：[最终实现冷／热实测](../data/evidence/reel-mask-caption-preview-2026-10-13/final-wrapper-mask-benchmark.json)、[初次完整蒙版与变窗实测](../data/evidence/reel-mask-caption-preview-2026-10-13/native-mask-cache-benchmark.json)、[原生滤镜等价](../data/evidence/reel-mask-caption-preview-2026-10-13/topbar-filter-equivalence.json)。

## 真实字幕预览实测

最终 CLI 对同一真实源片，复用已经核验的 9 组实际配音／WordBoundary ZIP 和完整蒙版，经过原有制作前检查，生成 **3 张样张共 13.420 秒**。样张覆盖源片 287.88 秒的真实 `MATCH POINT #2` 提示条、297.84 秒的居中 `ROUND 1` 赛果图，以及 4.92 秒的普通比分板。它们分别检查 360、480、306 的实际字幕落点；比分、提示文字和板宽均来自相应源帧。

实际最终 ASS 的 SHA 是 `e627f621c032d1a3703c5733e4a40264b8a19e13f30f598599f89f8a2155cd89`，与已发布版 60 条字幕完全一致。三个样张和额外提示条帧均独立查看：字幕未遮挡提示条、比分或 `ROUND 1`；提示条消失的近景不残留回贴蒙版。

普通板、居中赛果、真实赛点提示条及无板近景四帧，还分别与两阶段原生无损参照对比：先执行原生裁切输出 FFV1/YUV420，再执行原生最终顶栏／字幕／整屏恢复滤镜。四张 1080×1440 PNG 全图逐像素一致，最大误差为 0。这验证样张构造，不宣称最终 H.264 压缩、溶解或声音一致。证据：[无损参照对比及四张样张](../data/evidence/reel-mask-caption-preview-2026-10-13/native-caption-frame-equivalence.json)、[独立实看记录](../data/evidence/reel-mask-caption-preview-2026-10-13/visual-review.json)。

这次 CLI 计时包含制作前准备，不只是单帧抽取；条件是已有源片及已核真实配音、蒙版缓存。没有测首轮冷启动，也没有编码整片或发送微信。证据：[最终 CLI 计时](../data/evidence/reel-mask-caption-preview-2026-10-13/native-caption-cli-benchmark.json)、[真实样张输入及时间码](../data/evidence/reel-mask-caption-preview-2026-10-13/final-caption-preview-manifest.json)、[配音缓存来源](../data/evidence/reel-mask-caption-preview-2026-10-13/actual-tts-pair-cache-provenance.json)。
