# 美网记分条 vs 竖版画幅：量出来的结论是**画幅不动，动窗口**

2026-08-27，账号所有者问「美网的比分牌比较宽，视频调到多少宽高比更合适」。
拿真实素材把每一档宽高比都渲了一遍（对比图就在
`output/2026-08-27/frames/uso-board-ratio/`），答案不是某个新画幅——
**任何竖版画幅都装不下这条记分条，而比 3:4 更宽只会裁得更难看**。
突兀的根子在窗口位置，不在画幅。

## 实测几何（全分辨率帧，不是估的）

素材：`zheng-burel-us-open-2026-q2` 源片（youtu.be/iCRfxcIFAoo，1920×1080，
2026 美网世界 feed 图形包）。frame-grab 抓了 20 帧全分辨率，宽景帧逐帧量：

| | 记分条 bbox（1920 源片坐标） | 宽 | 右边缘 |
|---|---|---|---|
| **美网 2026** | x ∈ [104, 616]，y ∈ [888, 978]，浮在角落内侧 | **512px（27%）** | **616** |
| 辛辛那提（巡回赛） | x ∈ [0, ~417]，贴死左下角 | ~400px（21%） | ≤417 |

3:4 的裁切窗口（810px 宽、按球场中轴 960 居中）左边缘落在 ~555：
巡回赛的条（右缘 ≤417）**整条在画外**——所以巡回赛成片从来没突兀过；
美网的条右缘 616 越过了窗口左缘，**只剩约 40~64px 的小分格子孤零零戳在
画面左下角**（`zheng-burel` 已发成片里那两个 15/30 白框就是它）。

## 每一档宽高比的账（窗口按球场中轴 960 居中）

| 画幅 | 窗宽 | 记分条被裁成 |
|---|---|---|
| 9:16 | 608 | 整条在画外 ✅（但球场宽度比 3:4 少 25%，双打线被切） |
| 2:3 | 720 | 残条 19px |
| **3:4 现行** | 810 | **残条 ~64px（现状的突兀）** |
| 4:5 | 864 | 残条 91px，**更糟** |
| 1:1 | 1080 | 残条 199px，裁在名字中间，**更糟** |
| 16:9 | 1920 | 整条都在——但那就不是竖版了 |

**要整条装下且球场居中，窗口要 ≥1760px，即画幅 ≥1.63:1**——基本回到 16:9。
也就是说「调宽一点」这条路在几何上不存在：从 2:3 到 4:3 之间的每一档都在
裁这条 512px 宽的图形，越宽露出的残条越长、越难看。

## 结论：画幅保持 3:4，两条修法

**A（零代码，当下就能用）：宽景段写 `"cx": 0.54`**（≥0.536 即窗口左缘 ≥624），
整条记分条干净排除，和巡回赛成片同一个样子。代价是球场中轴落在窗内 ~41%
处（居中时 50%），渲出来看过，可接受。窗口左缘的判据：
`cx × 1920 − 405 ≥ 板右缘 + 6px`。⚠️ **板右缘不是常量 616，它随盘数右移**
（见下面「五盘大战」那节）：616 只是第二盘的值，**cx=0.54 只对前两盘的段成立**，
第三盘起要按那节的表加大 cx，深盘付不起——男子五盘的片子 A 不够用。

**B（可选升级，把比分留在画面里）：记分条回贴。** 从同一帧把
`crop=512:90:104:888` 抠出来、放大 ~1.3 倍 overlay 回 3:4 画面左下
（字幕区之上）。因为取自同一帧，比分逐帧天然同步，效果见
`solution_sheet.jpg` 中图——原版图形完整清晰，看着像竖版转播自带的。
要做的话得加一个 per-seg 开关，且只能开在宽景段（近景/回放时转播会把条
收掉，那时回贴出来的是一块草地）。要不要做 B 是口径选择，A 不依赖它。

## 别再重探的

- 「换个更宽的竖版画幅」——上表就是答案，别再试 4:5 / 1:1。
- `contain` 整幅能装下整条，但球场只占画布 42% 高，手机上一切都小（图 C）。
- probe 的 `scorebox_guess` 和全分辨率实测**逐像素一致**（104,888,616,978），
  以后美网片子直接信它。⚠️ 这批数量的是**资格赛/外场世界 feed**；主赛第一条
  片子拿它的 `scorebox_guess` 对一眼再沿用 cx=0.54（阿瑟阿什的转播图形
  可能另有一套）。
- 破发点时条上方 y∈[~810,888] 还会叠一条黄色 BREAK POINT 标签；方案 B 若只
  抠主条会丢这个标签，不必扩窗（旁白本来就要讲关键分）。

## 追问：「缩短高度，把比分主体放进视频里」——也量过了

账号所有者 2026-08-27 追问能不能把视频做矮、让比分牌进画面。对比图
`short_height_sheet.jpg` / `one_to_one_center.jpg`（同目录）。三档结论：

- **整条（名字+比分）+ 整个球场都要在：最矮 6:5。** 硬几何：条左缘 98 +
  近端右边线 ~1370 → 窗口 ≥1272px。中间档全不行——4:5 装了条球场只剩左半
  （窗口右缘 962 正落在中线），1:1 左移装条会把右侧砍到 1178，
  **比现行 3:4 的右界 1442 还窄**。6:5 的代价：同宽显示高 613→383px
  （−37%）、已是横版、1080×1440 整套版式（海报/顶栏/字幕锚点/画布判据）要重做。
- **只要比分数字块（名字顶栏本来就有）：1:1 居中就够，cx 都不用动。**
  切口恰好落在条中段的空白区（名字区到 ~350，数字区从 ~430 起），
  箭头+盘分+局分+小分完整保留，球场完全居中。⚠️ 脆弱点：这靠的是 ZHENG
  名字短——长名字（ALEXANDROVA 这类）会伸进空白区被切在字母中间，
  每场要先看名字长度；同宽显示 −25%，版式同样要按 1080×1080 重排。
- **不缩高度的等价物就是 B（记分条回贴）**：信息和 6:5 一样全，3:4 一点不动。
  三条路的真实改造成本：**B < 1:1 < 6:5**——改画幅不是「改个数」，
  是画布手术（`_detect_canvas` 写死 3:4，海报/字幕/顶栏/判据全随画布走）。

记分条内部结构（写 B 或 1:1 时用）：种子号+名字 [118,~350]，空白 [~355,430]，
发球箭头 [~435,485]，盘分/局分/小分 [~490,616]。抠数字块从 x≈425 起即可。

## 追问二：五盘大战——**这块板往右长，每列 +39px**，A 的账要重算

账号所有者 2026-08-27 追问五盘大战怎么办。上面所有实测都来自女单资格赛
（最多一列完成盘），去把同一条源片里「第一盘进行中（零列）」和
「第二盘进行中（一列）」两种状态并排量了（`board_set1.jpg` /
`board_5set_growth.jpg`）：**左缘和名字区不动，完成盘的列往右追加**——
右缘 577 → 616，**一列 +39px**。按此外推：

| 打到第几盘 | 板右缘 | 3:4 排除要 cx ≥ | 排除后球场轴在窗内 |
|---|---|---|---|
| 第 1 盘 | **577**（实测） | 0.515 | 47% |
| 第 2 盘 | **616**（实测） | 0.536 | 41% |
| 第 3 盘 | ~655（外推） | 0.556 | 36% |
| 第 4 盘 | ~694（外推） | 0.576 | 32% |
| 第 5 盘 | ~733（外推） | **0.596** | **27%，付不起** |

- **A 只够前两盘**：连女单决胜盘（第三盘，~655）都越过 cx=0.54 那条 632 的
  排除线；五盘深处要把球场挤到窗内 27%，不能用。**男子五盘的片子别指望 A。**
- **B 不受影响，反而更显价值**：抠的右界跟着段属于第几盘给
  （第五盘 [104,~733]，×1.32 贴出来 ~830px，仍 < 1080 画布宽）；五盘大战
  恰恰是比分最该留在画面里的片子。写 spec 的人在预览里本来就看得见板的状态。
- **1:1 居中在深盘反而更全**：列往右长是长进窗口里（窗口 [420,1500]），
  第五盘 4 列盘分全部可见；切名字的脆弱点不变。
- **6:5 结论不变**：板长到 733 仍在 [98,1394] 窗口内。

⚠️ 第 3~5 盘的右缘是**拿一次列转移（0→1 列，+39）线性外推的**，不是实测——
2026 美网还没有打满三盘的源片可验。方向是钉死的（往右长），间距差几个像素
不改上表的结论；主赛第一条三盘/五盘片子拿 probe 的 `scorebox_guess` 实测
右缘校准这张表。

## 定案方向（账号所有者 2026-08-27）：**带式版式——字幕和顶栏放到画面外，外框保持 3:4**

mock 见 `band_layout_sheet.jpg`。外框仍是 1080×1440（信息流里占的格子、
海报、推送链路全不变），里面拆成三条带：

    顶带  y[0,140]      顶栏两行（HEAD 54 / BODY 38 本来就是顶锚 18/72，原样落进来）
    画面  y[140,1040]   源片裁 6:5（1296×1080，左缘 98）→ 缩到 1080×900
    底带  y[1040,1440]  字幕顶锚 ~1080（双语 quote 两行也装得下；平台 UI 区在更下面）

为什么成立：

- **整条记分条 + 整个球场原生都在画面里**，五盘大战免疫（窗口右缘 1394，
  板长到 ~733 还有富余）——不需要 B 的回贴、不需要按盘数给参数
- **画面上再没有任何东西压着**：顶栏、字幕全在带里，比现状还干净
- 平台显示不变：3:4 的格子照占，抖音/视频号照旧 letterbox 3:4

代价与实现（都要如实记）：

- **主体缩到现在的 62.5%**（810px 窗口换 1296px 窗口，同画布宽）——这是唯一
  的内容代价，mock 里看得见；近景段不受多大影响（脸本来就大），亏的是宽景回合
- 球场轴在画面带内 66%（板在左边押着），mock 看过可接受
- 实现是 **spec 级 opt-in**（如 `"layout": "band"`，不写=现行全出血，巡回赛
  片子零影响）：段滤镜链 `crop=1296:1080` → `scale=1080:900` → `pad` 到
  1080×1440（带底色）；字幕锚 1284 → ~1080 一个常量随 layout 切；顶栏不动；
  封面海报仍全出血 1080×1440；`check_reel_landed` 画布判据不变
