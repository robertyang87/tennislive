## 已修复的可避免问题

### 自定义比分框在编码前查清

此前同源、同框、同转播的真实扫描判据只在全库 CI 中。制作预检看不到这个硬缺口，最终才花一整轮 CI 找到它。

现在 CI 和 `production_preflight.py` 共用 `probe_board.scorebox_has_probe`。只检查当前 spec 用到的自定义框，包含段级和多源框。真实有界扫描可用于校准，但日志明确只证明该扫描范围，不能宣称全片通过；选段存在与消失仍由原生蒙版检查。实测当前片前检约 **0.24 秒**，不解码源片。

runner 先按源 URL 恢复已提交的 probe JSON，再执行预检。封面和旁白检查保持原有不依赖 probe 的模式，避免引入新的误拦。

### 审听证据按真实索引提交

本期 review index 引用 `data/evidence/eala-shi/source-audio/selected/`，旧提交脚本却固定添加 `data/audio_reviews/eala-shi/`，导致整条推送在发送前失败。

新工具 `tools/reel_review_files.py` 复用原生音频门禁，核验计划、源身份、完整窗口、字幕和文件 hash，只暂存索引及其声明的 JSON。缺失或篡改在依赖安装前失败。稀疏检出只恢复标记为省略的单个已跟踪 JSON；制作人员删除或修改的证据不会被旧文件覆盖，也不会把媒体带入 Git。真实本期 **29 个声明文件**校验中位耗时约 **11 毫秒**。

### 消除重复全库扫描和重复测量

| 检查 | 本地原耗时 | 本地修复后 | 保留内容 |
|---|---:|---:|---|
| 同场重复发布全库检查 | 18.76 秒 | 0.28 秒 | 所有同场、跨栏目、URL 归一化、合集与存量断言 |

批量验证显式共享一次本批次比赛索引，避免 N 份 spec 各自重新读 N 份 spec。正常单片渲染和发布默认仍实时读取，确保并行新增稿能立即被去重门看到；不保存跨运行快照。

本轮 **没有删除有效测试 case**。慢用例保护不同的真实故障，删掉它们会丢失保护。精简的是重复执行：JSON 重扫、每个函数重复切分一万行源码，以及同一字体同一字符串重复量宽。207 个历史 skip 主要对应采访没有引语或审查账，减少它们的节点数收益很小，本轮没有为了好看改测试数量。

以上是目标测试实测，不能据此承诺全库 CI 同比例加速。runner 负载会抖动，完整 CI 必须另查当前提交的实际运行结果。

本地首轮完整回归为 5893 passed、240 skipped、2 failed，457.17 秒、两个 worker。两处失败分别是采访唤醒的静态依赖扫描误认比赛专用模块，以及 probe 最小临时仓库被无条件要求调用审听 helper；均已修复并通过对应回归。比赛校准已拆出独立模块，采访不增加四个无关唤醒路径；没有索引的 probe 不执行审听暂存。最终完整结果以 PR 当前提交的 GitHub CI 为准，本地缺人脸权重等额外 skip 不冒充云端通过。

### 原生 Edge 调用和文档一致

共享 TTS 原本已经包含端点迁移，而旧说明仍要求原生入口额外加载专用审音 shim，容易让人重复排查。现在说明已纠正，原生请求显式使用已配置的代理；只迁移已知旧端点，保留上游新端点或明确自定义配置。

一次无专用 shim 的原生短句探测在 **1.644 秒**返回可解码 MP3 与词边界。这只确认技术连通，不是姓名、声调或人工听审结论，也没有重新合成已冻结成片。见 [Edge TTS 使用说明](edge-tts-usage.md)。

## 下一条视频的执行顺序

1. 一次核准事实、关键比分和故事线；官方源片、高清封面搜索、原声整理并行，先确认可复用的已下载源 SHA。
2. 在合成和编码前执行当前片的文案、比分框、音频证据及旁白时长预检。将可以确定的故障留在这一阶段。
3. 冻结旁白后合成。未变的句子和参数复用精确内容缓存；改变的句子重新核验，不重新合成其余句子。全句、姓名、数字和疑似错读都要检查；额外控制录音应针对具体疑点，不因已有控制包存在就整包重跑。
4. 用同一份当前电影 SHA、帧编号、时间码和 PNG manifest 分配独立审片任务。联系表用于浏览，争议必须打开对应原 PNG；相邻缩略格不能作为返工依据。原帧已反证的误报当场关闭，不扩成再抽全窗口。
5. 内容检查通过后合并一次最终代码与证据，再执行当前提交完整 CI。不要先推缺证据的半成品，再用全量 CI 逐项发现可提前检查的问题。
6. Release 上传后核附件 SHA，部署复制页、执行原生发布门和推送，最后核 provider receipt、`pushed.json` 与同一电影 fingerprint 的单次发送账本。

编码参数、铺满固定竖屏、贴近比分板的字幕、完整关键回合与反应、官方来源、原声与发布去重均保持原规则。

## 仍需继续量的环节

- 本期 241 个读音控制样本和多轮整片证据打包成本较高，但日志不足以精确拆出关键路径分钟数。应先记录每次合成、转写与比较的缓存命中和新增数量，再决定哪些比较可精确复用；不能把技术 ASR 当成人工声调审核。
- 原帧证据工具已有编号与 SHA，本次误报是审查没有引用它。先改变审查取证顺序，暂不另造一套重复抽帧工具。
- 专用本地成片 importer 和传输脚本会增加每期准备成本。需要另行设计可复用的导入清单后再替换，不能把上一期封好的 hashes、审批、声证据或回执直接套到下一期。
