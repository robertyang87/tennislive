审查方法：4 个静态深读（视频链路 / 素材检索 / 历史产出证据 / 整体架构）+ 8 轮对抗核实
+ 5 个运行时实测（每条数据源和工具链真实执行）+ 对两条成片的逐帧拆解。
所有结论均附代码位置或实测证据；「实测」指在与 CI 等价的环境中真实执行的结果。

## 一、为什么"不能自动生成视频"——五个根因（全部核实）

### 1. 日报视频被工作流硬编码关闭（最直接成因，已确认）
`.github/workflows/daily.yml:89-90` 把 `TENNISLIVE_DAILY_VIDEO` / `TENNISLIVE_OFFICIAL_VIDEO`
写成字面量 `'off'`（不走 `vars`，无法在仓库设置里打开）。`cli.py:499-527` 与
`official.py:1089` 读到 off 直接跳过。证据：output/2026-07-20~23 每天都有
`video/daily-brief.mp4` 和 `official-highlight.mp4`，07-24 起消失——能力完好，只是被关了。

### 2. 昨日好球（唯一定时视频链路）闸门与现实供给严重脱节（实测）
- 过去 7 天 ATP/TennisTV/WTA 三个官方频道共 45 条 RSS，现状闸门
  `is_explicit_single_point` 通过 **0 条**；放宽接受 highlights 后可通过 **40 条**（实测对比）。
- 官方标题必须字面含 "Point/Play/Shot/Rally of the Day|Match" 或 "Hot Shot"
  （`daily_point.py:313-329`）；WTA 用 `#HotShot` 标签的短视频被正则漏判——`_clean`
  把标签清成无空格 `hotshot`，`\bhot\s+shot\b` 匹配不到（实测 bug）。
- rank-2（Point of the Match）被代码与 workflow jq 门禁双重永久排除
  （`daily_point.py:436-441`、`yesterday-point.yml:117-128`）。
- 四个班次止于北京时间 12:00，接不住欧美下午/晚间上架的官方剪辑。
- 共识分并列时整期跳过（`daily_point.py:544-554`），两条都合格反而一条不发。
- 结果：近 10 天仅 07-24 一天产出，且失败/空产完全无告警。

### 3. ATP 侧素材获取被外部依赖卡死（实测）
- Tennis TV entitlement 需 5 分钟寿命的 JWT，已放弃长期配置（`docs/yesterday-point.md:58-71`）。
- YouTube 路径实测：元数据与播放地址提取成功（无 bot-check），但 googlevideo
  下载被 403 拒绝（数据中心 IP），且 progressive-only 过滤把可用清晰度限到 360p
  （`official.py:481-498`）。
- **WTA Brightcove 实测全通**：视频 hub 解析、HLS m3u8 与 720p MP4 播放地址均真实拿到。
  ATP 难、WTA 通，这是命中率不对称的机制性原因。

### 4. 知识解说视频只有手动触发 + 单一手写剧本
`explainer.yml` 仅 `workflow_dispatch`；`_SCRIPTS` 只有 hawkeye 一个选题
（`explainer.py:143-226`）。无图 fallback 会给任何选题渲染鹰眼示意图（`explainer.py:294`），
画面与主题不符。edge-tts 无重试无兜底；07-25 一天 CI 重渲 4 次、19 个素材狩猎
commit——实质是人/agent 在环的手工作坊，瓶颈在素材而非渲染。

### 5. 除 daily.yml 外所有定时工作流失败/空产零告警
`flash.yml`、`news-radar.yml`、`yesterday-point.yml` 没有任何 `if: failure()` 通知；
skip 状态不提交回仓库，诊断只存在于会过期的 Actions 日志里。"视频静默消失"的体感由此而来。

## 二、为什么"图片和视频找不到想要的"——实测逐通道判定

| 通道 | 实测判定 | 关键证据 |
|---|---|---|
| Wikimedia Commons API | ✅ 可用 | 12 条候选带 CC 授权（含美网真实比赛照）；但对"当日比赛"结构性零覆盖（台账 15 次运行 0 候选） |
| Openverse API | ✅ 可用 | 12 条，与 Commons 高度重叠 |
| photoresources.wtatennis.com | ✅✅ 黄金通道 | 直接下载 4700×2733 原图；CDN 当前忽略裁剪参数 |
| wtatennis.com 文章/RSS 发现 | ✅ 可用 | Sherif 夺冠报道 52 条 RSS 第一条即命中 |
| WTA 赛后报道抠图整链 | ❌ 断裂 | 断点：Google News RSS 链接已改为 JS 中转页，不再 302 到 wtatennis.com，`_is_official_tour_media_url` 全拒（真根因，非检索失败） |
| Bing 图搜 | ❌ 不可靠 | 引号去留不改变候选数（实测对照）；真问题是返回垃圾且极不稳定（"Iga"→IGA 超市骗过 relevance≥6），需强球员名校验 |
| official-tennis-archive | ❌ 结构性失效 | `site:` 运算符串被整句引号包住变成短语文本（`visual_sources.py:918-924`），恒 0 候选 |
| DuckDuckGo | ❌ 对端 403 反爬 | 贡献恒为 0 |
| atptour.com | ❌ Cloudflare JS 挑战 | 换 UA 无效；需真实浏览器（仓库已有 playwright，可走 webrender 路线） |
| Flickr 公共 feed | ❌ 无效源 | 前 8 token 全 AND 匹配，3 期 0 候选 |

**闸门侧问题**（静态确认 + 台账证实）：
- 名义门槛 `minimum_score=72`，而实际入选封面分数 65~71——门槛与现实脱节；
  07-24 知识帖 8 题 × 4 轮共 32 次尝试全部倒在素材预检，聚合拒绝 628 次。
- strict 模式"缺一页整题作废"（`visual_sources.py:1497-1505`）；curated 图下载失败
  既不进排除集也不触发网络检索，同题 4 次重试逐字节相同（bug，`visual_sources.py:1291`）；
  curated 条目请求 width=1600 而原图仅 943px，MediaWiki 拒绝放大导致必败（bug）。
- exact-match 要求"双方球员+赛事+年份"同时出现在元数据文本，而代码注释自认
  WTA 官方标题经常省年份（`visual_sources.py:2266-2270` vs 1836）。
- Haar 人脸检测对运动照漏检率高，误杀真实现场图；封面分辨率卡 900×1200
  把官方 1280×720 图全杀（WTA 无豁免）。
- 唯一持续供图的 official-recap 检索被台账 gating：需"图库连续空 3 期"才放开，
  而台账才 1 期——07-25 明知全空仍跳过 recap、落到品牌兜底图。
- 官方一手源系统性网络故障未被治理：usopen.org 读超时累计 28 次、sony.com 恒 403。

**结构性底座**：选题池与人工核验素材池硬编码为 Python 常量，检索结果不落库复用，
每天从零现搜；assets.yml 素材补充纯手动。

## 三、两条成片的逐帧拆解

### hawkeye 解说视频（output/2026-07-25/explainer/hawkeye）
126 秒 ÷ 5 张静止幻灯（页均冻结 25 秒）；3:4 卡片贴 9:16 画布上下黑边；
配音无跟读字幕、每页要点第 0 秒全亮（剧透）；24kHz 单声道、无 BGM、
14 处 0.7~1.2 秒静音；总码率仅 373kbps；开场无钩子。

### 四大满贯竖屏片（output/grand-slam-vertical，PR #20）
**时间轴（方向性错误）**：分镜时长写死，配音被 `atempo` 至多 1.8 倍压进画面、
仍超长则句中截断（`tools/build_grand_slam_short.py` 音频适配段）；"音色差"一半
是 gTTS 底子、另一半是变速挤压。SRT 按计划整秒估算且不烧录；每镜黑场淡出淡入
共 14 次；全片同向缓推；无响度处理（实测 -20.1dB）；170 秒过长；4 个球场名片镜
共 24 秒设计性静音。（仓库里 explainer.py 的"画面跟随音频"方向反而是对的。）

**画面**：`cinematic_bg` 的透视球场线几何错误——中央发球线从底线贯穿到远端
（真实球场中线只在两条发球线之间），发球线用线性插值不符合透视，无单双打边线。
选图张冠李戴：澳网格用夜景外墙（无一寸球场）、温网格配置的是
`assets/players/jannik-sinner.jpg`（球员照冒充场馆卡）、"硬地"用铁丝网训练场照、
法网主画面借用 hawkeye 专题的球员特写；四格照片年代/色调/画质不统一。

**内容**：spec meta 自缚"刻意不使用统计数字、不聚焦球员"，导致全片只剩空形容词。
四大满贯最有共鸣的素材（澳网 40°C 高温规则、红土降速与纳达尔 14 冠、温网 1877
与全白着装、美网首个引入抢七与鹰眼、2.3 万人夜场）全部缺席。

**修复原型**：`tools/build_grand_slam_v2.py`（本次提交）——声音做主时钟
（配音先合成、画面时长=配音+呼吸间隙，永不变速截断）、edge-tts WordBoundary
词级时间戳生成逐句 ASS 字幕烧录（关键词品牌色高亮）、推近/拉远/横摇轮换、
0.45s 交叉叠化替代黑场、loudnorm -16 LUFS 48k 立体声。实测 WordBoundary 在
edge-tts 7.x 需显式 `boundary="WordBoundary"`（默认句级）。

## 四、技术统计与工具链实测（免鉴权前提）

- **WTA 官方统计 ✅**：`api.wtatennis.com` 免鉴权、不封数据中心 IP；实测拿到
  Ace/一发成功率/一发二发得分率/破发点/双误/总得分/用时全套数字。
- **SofaScore ❌**：403 封数据中心 IP（对端 Varnish，非代理）；GitHub Actions 同风险。
- **ESPN**：scoreboard 无逐场统计，只有 linescores（含抢七小分）——足够做
  逆转/抢七/爆冷的戏剧性检测，不够做发球统计对比。
- **ATP 免费逐场统计当前无通路**（官网 Cloudflare、infosys 需 key）：短期用
  比分级数据 + WTA 全统计；中期试 webrender 真浏览器路线。
- **工具链全通（实测）**：pytest 417 全绿（沙箱需补 cffi）；edge-tts 双音色合成、
  WordBoundary 字级时间戳、`assemble_explainer_video` 音画同步差 1 帧内；
  playwright webcards 正常；tesseract OCR 对记分牌数字/拉丁球员名全对
  （中文标题误认，混合模式更差）——记分牌核验方案可行。
- **Pillow 卡片字体 bug（实测）**：默认 `_find_font` 排序选中 Latin-only 的
  BarlowCondensed，中文全豆腐块；须显式设 `TENNISLIVE_FONT`/`TENNISLIVE_FONT_BOLD`
  才正常。CI 恰好设了所以线上没炸，本地/新环境必炸。
- **digest 数据质量**：把 Sherif vs Badosa（雅西决赛）误标为汉堡站 QF——上游
  赛事归属映射有错，会直接污染文案事实。

## 五、工程问题（架构审查摘选）

1. 7 个工作流各自 `commit+push data/*.json`，无原子写与并发保护，rebase 冲突即丢状态。
2. 触碰 `src/render` 的 push 会让 daily.yml 重新生成当日内容并删 `.pushplus_sent`，
   随后知识班次会把整份日报**重复推送**一次。
3. output/ 已 147MB、.git 221MB 且每日增长；媒体产物应出库（Releases/LFS/Pages）。
4. `cmd_digest` 约 350 行巨函数、20+ 内联 import、全 try/except 吞错，无法端到端单测。
5. 测试盲区：sofascore.py 零测试、wechat_mp.py 主体未测；无 lint/类型检查。
6. README 与现实脱节：卡片实为 .jpg、结构图缺 video/ 与 research/、工作流只列 4/13。
7. ci.yml `paths-ignore` 漏 `data/**`，每次机器人提交都触发全量 CI（含 Chromium 安装）。

## 六、改造方案（按九条需求，全部免费无鉴权、零人工预备）

**优先级 P0（一天内、立竿见影）**
1. daily.yml 两个视频开关改 `${{ vars.* || 'on' }}`；给全部定时工作流加失败+空产告警。
2. 昨日好球放宽：接受 highlights 类目（0→40 条/7 天）、修 `#HotShot` 正则、放行
   rank-2、并列 tie-break、加 16:00/21:00 班次；skip 也落盘诊断。
3. 修 Google News JS 中转页解析（解码 RSS base64 链接或直抓 wtatennis.com/news
   列表匹配）——打通唯一在供图的官方赛后抠图链。
4. `site:` 串移出引号；封面门槛 72→65 对齐现实；recap 改"候选池空即查"；
   知识帖缺页降级为示意图而非弃题；curated 失败进排除集并放开网络检索；
   官方域名候选分辨率放宽到 1280×720。
5. Pillow 字体默认值修复（无环境变量时优先 CJK 字体）。

**P1（视频质量线）**
6. 需求③⑥：全部视频链路切到"声音主时钟"（v2 已验证），WordBoundary 逐句
   ASS 烧录、YunjianNeural + 语速分层、loudnorm；四大满贯片按 v2 重制，
   加第二层（正确球场轮廓线的投影几何重画、场馆图场景规则重选、统一调色）
   与第三层（解禁数字与球员故事的脚本重写，60~90 秒）。
7. 需求⑤：WTA Brightcove 做每日视频主力（实测可下载 720p）；Tennis TV Hot
   Shots API 做 ATP 候选发现；ATP 下载被 403 时输出链接卡+缩略图降级方案。
8. 需求④：WTA 全统计对比卡（对峙式布局）；ATP 用 linescores 做比分级对比；
   戏剧性检测器（逆转/抢七/爆冷/里程碑/中国球员）同时供文案钩子（需求⑧）。

**P2（检索精准与内容线）**
9. 需求①②：三层检索-核验管线——官方渠道优先（photoresources 直取 4700px、
   大满贯 10 域名复用、webrender 过 Cloudflare）；机器核验三要素（InsightFace
   球员人脸比对、日期窗口、OCR 背景板/记分牌——tesseract 已实测可行）；评分
   排序+证据 JSON，授权只记录不拦截（署名进发布文案，成片不烧录）。
10. 素材池数据化：检索结果与人工核验图入 `data/asset_library.json` 沉淀复用，
    curated 常量池降级为缓存；assets.yml 改为每日自动补充。
11. 需求⑧⑨：钩子公式库+故事弧模板接戏剧性检测器；卡片封面真实照片主视觉+
    大字钩子、统计页对峙布局、情绪色调系统。

**P3（工程线）**
12. 媒体产物出库止血 git 膨胀；状态写入原子化+提交队列；`cmd_digest` 拆
    pipeline 模块补测试；README 对齐现实；ci.yml 修 paths-ignore。
