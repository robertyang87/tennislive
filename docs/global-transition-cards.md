# 全栏目转场卡：内容决定布局，布局决定动效

账号所有者 2026-10-23 确认：“把这个落实到全局的路径里，后续所有视频里有转场卡片时候都要参考和复用”。适用赛场之上、网球有故事、赛后开麦及后续栏目。保留既有深蓝、字体、语义分行、字幕、品牌和比分板规则；本次不重渲或重推历史影片。

## 唯一共用入口

- 核心：`src/tennislive/video/transition_cards.py` 的 `plan`、`build`、`render_clip`。
- 原生视频：`tools/build_match_reel.py` 的 `title_card` 默认渲染为静音动效素材，随后沿原有配音、字幕、溶解接缝路径合成；不能再给转场另写一份静态蓝底。
- 图文解说：`ExplainerSegment.visual.layout = "transition"` 使用同一 HTML 与渲染器；预览保存 `.transition.json`，合成时按实际配音窗口生成同一动效素材。
- 其他产线如果出现转场卡，调用同一组件。证据图、完整统计表、封面、片尾和真实比赛画面不是转场卡，不因本规则自动重排。

独立预览也使用同一入口：

```bash
PYTHONPATH=src:tools python tools/render_transition_card.py --text '重新出发' --kicker '宁波首轮' --seconds 4 --out /tmp/transition.mp4
```

可用 `--content facts.json` 传下述内容关系；`--band` 沿现有带式画面区输出。预览不等于影片发布放行。

## 内容先行

编辑模型先读已核实的比赛资料与当前文案，给出完整语义标题、一个主要关系及真实来源。组件从内容结构选择布局，不根据栏目名或某个人名套固定模板，也不凭关键词推测比赛事实。普通短转折不需要数据；不能为了画图塞入无关统计。

| 内容关系 | 内容字段 | 布局与动画 |
| --- | --- | --- |
| 简短转折 | 标题，可选 highlight | 两行以内居中大字，整行错峰入场、重点短线展开 |
| 比分变化 | scores | 明确盘次的完整比分依次入场，推进线展开 |
| 同一指标对照 | comparison.metric、nodes | 双方并列进入；非负数值可用同尺度比例条，不画时间推进箭头 |
| 人物经历或事件经过 | events | 按已核实的时间顺序展开；时间线及较多节点用纵向排列 |
| 人物章节 | photo | 正式照片完整等比显示，图文分层进入，照片轻推进 |

所有数据节点必须写 `label`、字符串 `value`、已核实的 `source`。`winning` 只能用于确有胜利含义的节点。不得滚动生成虚假中间比分、推断未证实的逆转、拼凑因果或补造照片。对照数据的单位和全场/单盘范围写清楚。

## 自适应边界

- 编辑负责语义与事实，确定性代码负责尺寸、横纵排列、留白和动画时钟。现有演示的词面匹配原型不作为任意文案的理解器投入生产。
- 显式语义分行优先，一到两行共用字号；不得拆人名、固定词组、比分或出现孤字行。先改写，再适度同档缩字号，仍不适合就拆卡。
- 标题、辅助节点、实际字幕和底部品牌各有空间。保留既有故事角标；有冲突时预检/浏览器报错，不移动比分板或把品牌抬回正文。
- 照片缺失、显示空间不足或清晰度不足时，记录原因并退回简洁转折卡。正式图片来源规则不变；默认完整 contain，不能自动猜人脸裁切。
- 动画围绕当前关系选择。背景球场线和柔光保持低对比；整句进入后稳定阅读。不能全片每张卡同时堆上全部效果。
- 时长由实际旁白窗口决定；动效结束后稳定停留，不能为动画截句、加速配音或删减完整关键过程。原声、配音质量和发布闸照旧执行。

## 原生稿示例

```json
{
  "title_card": "从首盘3比3\n到第二盘4比0",
  "kicker": "跨盘连赢七局",
  "seconds": 5.2,
  "narration": "这里沿用已核实并完成审查的实际旁白",
  "transition_card": {
    "highlight": "4比0",
    "scores": [
      {"label": "首盘", "value": "3–3", "source": "同场事实包中的首盘三比三"},
      {"label": "第二盘", "value": "4–0", "source": "同场事实包中的第二盘四比零", "winning": true}
    ]
  }
}
```

上例数值来自本轮已经核实的伊埃拉—帕里宁波首轮示例，不能复制到别的比赛。新比赛必须重新绑定自己的来源。旧 `title_card` 不加新字段也会得到简洁转折动效。`transition_card` 的数据字段会进入既有渲染输入指纹，改动后重新核验。

对照写法：`{"comparison":{"metric":"全场非受迫失误","nodes":[{"label":"球员甲","value":"9","source":"同场全场统计"},{"label":"球员乙","value":"25","source":"同场全场统计"}]}}`。`metric` 应同时成为内容小标题或出现在标题中，保证观众知道比较什么。

图文解说在 `visual` 内写 `{"layout":"transition","headline":"完整第一行\n完整第二行","kicker":"内容小标题","content":{...}}`，content 与原生 `transition_card` 使用同一契约。

## 质检、效率和参考

1. 预检核实关系、来源、节点数、完整标题和图片声明；一张卡只表达一种关系。
2. 实际浏览器等待字体和图片就绪，核对文字溢出、实际包围盒、字幕和品牌/故事角标安全区。
3. 看实际编码后的入场、信息展开、停稳和回实拍接缝，确认没有闪字、错序、画面拉伸或遮挡。素材解码和动画时钟检查不冒充完整观感或听审。
4. `render_clip` 缓存绑定 HTML、内容、尺寸、帧率、完整时长与实际 MP4 SHA。相同输入复用；动效稳定后复用静止帧，避免为长旁白重复浏览器截图。不恢复任何响度或源声增益扫描。

本次确认的 27 秒视觉参考 SHA256：`36f0bb571be780d0fc2a33d28e06beb03268081f4b13d5220eba6b731ccbd26f`。包含短转折、比分推进、数据对照、经历时间线、人物图文五类；是视觉参考，不是其他比赛的事实或发布凭证。实现和后续改良均走上述共用入口，不能依赖本机会话的 scratch/tmp 文件。

## 2026-10-23 完整 Demo 确认后同步主线

账号所有者看过伊埃拉宁波首轮完整 Demo 后确认：“开头的冷开场不要拿掉，其他 ok”，随后要求“同步到主线”。另外确认正片不显示封面左上角标题，照片卡下方不显示“WTA巡回赛女单正赛 图片 宁波网球公开赛官方”这一行小字。

执行范围：

- 保留比赛原声冷开场，并在正文保留完整赛点、反应、握手与谢场。动效只是中段解释，不能取代冷开场或挤掉结尾落点。原有 `cold_open_problem`、原声与字幕检查继续执行。
- `wants_watermark("赛场之上")` 继续关闭正片封面台头的整组叠加；封面台头仍由原封面入口绘制。任何新 Demo 或包装层必须读这个共用开关，不能直接调用角标绘图函数强贴。
- 图文卡只展示标题、正式图片、必要赛果和实际旁白字幕；不在图片下方加来源/范围等小字行。图片与事实来源保留在 `transition_card`、输入指纹和审查记录中，不清除原图自己的标识。

同一 `transition_cards.build/render_clip` 已升级到 GSAP 3.15.0 与 D3 7.9.0 的离线实现。依赖固定在 `assets/vendor/motion/`，带上游许可证说明；不在渲染时加载 CDN 或安装 npm。标题分层入场、比分节点依次推进、逐组统计条形图、时间线和照片赛果浮现共享一个可寻址时钟。入场结束后复用停稳帧，长旁白照原时长播放。缓存包括最终 HTML 中的库字节和完整画面输入，库或内容变化就重新生成相应卡片。

新增可复用内容契约：

- `comparisons`：1–3 组 `{metric, scope, unit, nodes}`，每组仍要求每个节点带 `source`。各组使用同一球员顺序；非负有限数值由 D3 同尺度展示，禁止从全场与单盘混拼数字。放不下就拆卡。
- 比分卡可加 `summary: {value, label, source}`，例如经核实的“三局＋四局＝七局”。总结由事实包提供，组件不推断某场比赛连赢多少局。
- `photo` 可加 `result: {value, source, label?}`，以照片上的赛果卡收束。照片继续完整 contain，不猜裁人脸，不显示下方小字。
- 旧 `comparison`、`scores`、`events`、`photo` 和无数据的转折卡保持兼容；完整 `stat_card` 仍是完整统计证据，不能为做动画擅自删列。

HyperFrames 使用同一份 HTML、字体、实际 GSAP 主时钟和 D3 数据绑定导出，无需重写另一套场景：

```bash
PYTHONPATH=src:tools python tools/render_transition_card.py \
  --text $'赢球的另一面\n把失误留给对手' --kicker '全场统计' \
  --content /tmp/verified-comparisons.json --seconds 13.4 \
  --out /tmp/comparison.mp4 --hyperframes /tmp/comparison-hyperframes
```

`--hyperframes` 生成可编辑的 `index.html` 与 `reference.json`；原生产线继续使用已有 Playwright/FFmpeg 渲染器直接消费相同页面，避免为每张卡额外启动第二条编码链。可选用 HyperFrames CLI 打开或渲染导出的工程，不能把导出成功当作影片通过质检。

四类完整、带真实来源的参考在 `data/visual-reference/approved-motion-20261023/cards.json`。这是视觉学习与审查参考，`reference_only: true`，新比赛必须换成自身事实与正式图片。
