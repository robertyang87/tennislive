# 赛场之上：把返工移到启动前

月亮姐这期从首次 dispatch（06:07:44Z）到 PushPlus 接受单次推送（09:12:45Z）经过 **3 小时 5 分 1 秒**。最终原生 render 记录为 **241 秒**；此前编辑、备料、证据修复、排队和重复 CI 占了大部分时间。这个区间包含人工制作与等待，不能当成连续机器运行时间，也不能用本轮局部测试宣称端到端已缩短到几分钟。

实际发生过的返工：下载源片的容器字节变化；读音参考合成沿用旧连接和盲目重试；修改章节旁白后漏更新原声审听计划；正式成片才发现英文姓名拆行；中间提交反复触发包含核心渲染器的完整 CI。

## 本轮修复与实测

| 环节 | 改动 | 可验证结果 |
|---|---|---|
| 读音参考合成 | 使用共享 Edge 端点、代理和失败分类；保留原始参考文本与精确缓存 | 一次独立短句合成 0.511 秒，精确缓存命中 0.000111 秒；MP3 与词边界相同，解码成功 |
| 合成失败 | 不可恢复失败立即返回；暂时失败最多三次请求，等待 2 秒、6 秒；清除半截临时文件 | 受控失败测试中，不可恢复失败从四次请求及 26 秒盲等变为一次请求、零等待；暂时失败用尽后不再等 |
| 审听计划 | `reel_review_files.py --rebind-plan` 显式核验全部当前窗口与原始证据，再原子写索引 | 本期六份真实包：正常核验 0.00437 秒；过期计划 0.000170 秒拒绝；完整重绑定提案 0.00116 秒；测量不写库、不下载、不合成 |
| 姓名拆行 | 根据 `cover.matchup[].name_en` 给显示文本中的完整英文姓名加不换行空格 | 真实 libass 像素测试复现旧拆行，并证明修复后名字在同一物理行；原始 quote、标点、显式换行与时序不改 |

这些数来自单次有限探测，不是稳定性能保证。缓存命中提速已存在，本轮修正参考合成的传输与失败路径，让审音不必另外排查旧入口。端到端收益需下一条真实制作重新记录。

## 下一条的执行顺序

1. 核准故事线、事实、名字和章节文案后再冻结声音。官方源片一旦用于审听，保存该文件 SHA 与精确归档；后续正式渲染用匹配的 `source_fallbacks`，不把同 URL 的重新下载视为同字节。
2. **dispatch 之前**运行当前 spec 的便宜检查。原声索引过期先解决，不把已知失败投进 runner 等它报错：

   ```bash
   PYTHONPATH=src python tools/reel_review_files.py --slug <slug> --require-review
   PYTHONPATH=src python tools/production_preflight.py --spec specs/reels/<slug>.json --column 赛场之上
   ```

   仅因章节旁白或字幕排版改动使计划过期时，可显式运行：

   ```bash
   PYTHONPATH=src python tools/reel_review_files.py --slug <slug> --require-review --rebind-plan --stage
   ```

   此命令只在原包字节、完整审听状态、源身份、窗口覆盖、完整句和双语字幕全部通过后更新计划哈希。证据不确定、缺包、改源、切断句子或缺字幕均拒绝，失败不写索引、不暂存。不生成新审听结论。正式下载的源 SHA 仍由原生 `bind_sources` 检查。
3. 用实际冻结 MP3/WordBoundary 做原生字幕画面预览，先看长英文、姓名和球场覆盖，再正式编码。`preview_reel_captions.py` 的结果仅供预览，不是成片 QC 或发布证明。
4. 修改一条旁白只复核改变的声音请求；固定片尾和其余声音字节完全相同时复用已绑定证据。未确认的读音不能因缓存而记为通过。
5. 编辑期间本地跑对应检查。把最终代码、spec 和全部证据一次提交后，再跑当前 head 的完整检查；不要用多轮完整 CI 逐项发现准备阶段能拦住的错误。
6. 最终电影 SHA 与抽帧 PNG 未变时复用该帧审查；真实变化的帧重新审查。保留发布门、电影指纹与唯一回执。此次效率修改不重渲、不重推已经完成的影片。

本轮没有更改编码画质、居中裁切、3:4 画布、原声策略或既有设计风格，没有删减读音、字幕、事实或发布检查。机器可读证据见 [实测记录](../data/evidence/production-speed/reel-speed-review-2026-10-14.json)。
