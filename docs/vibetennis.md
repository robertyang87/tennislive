# vibetennis 科普视频制作流程

参考样片：《网球为什么现场看比电视上快》（vibetennis-live-faster-2026）。代码模板：复制仓库里最近一集 `tools/vibetennis/episodes/<slug>/`（目前 EP05 `vibetennis-court-speed-2026` 最全；旧路径 `/workspace/tennis_ep/v2` 已不存在。`r3d/` 是 Three.js 渲染，`overlay.py` 负责字幕和品牌标，`assemble.sh` 负责合成，`sfx/` 是音效）。发布工具在 tennislive 仓库的 `tools/vibetennis/`（`cover.py`、`qc.py`、`finalize.py`、`release.py`、`publish_gate.py`、`push.py`）。

## 0. 栏目使命
账号所有者 2026-10-30：内容**精确且详实**、**深入浅出**让普通人都能看懂、用**动画特效**抓住注意力、让人**持续看下去**、能**引爆共鸣和二次传播**。六条各自怎么检查，见 `skills/vibetennis-production/SKILL.md`「栏目使命」。
选题加一条硬标准：**这件事今天的比赛里还在发生吗？**（来路：「司线为什么总判出界」——现在都是电子司线了，这个题过时。）

## 1. 选题与脚本
- 选题库（已发、制作中、候选，以及每个候选的证据状态）见 [vibetennis-topics.md](vibetennis-topics.md)。
- 先整理资料、后做视频（所有者 2026-11-01）：数据、理论和要用的素材先整理成 `papers/<slug>/sources.md`，所有者看过再开渲。
- 数据交叉验证（所有者 2026-11-01）：每个上屏数字至少有一个官方来源，再加一个独立来源（论文、报道、第三方数据库）辅助验证；只出现在一个网址里的数字不上屏。
- 可视化按内容设计（所有者 2026-11-01）：每一集按它的机制设计新的场景和呈现方式，不局限于前几集已有的素材。
- 选大众都有共鸣的网球现象，背后要有可靠的科学解释（经典理论、实验或论文）。数据要准确，来源存档到 `papers/`。
- 时长跟着内容走，大约 3 分钟。结构：钩子提问，拆解机制，用证据验证，最后给结论。讲清楚、讲充分，但不啰嗦。
- 每一句旁白都要有画面直接、直观地表现它，观众不读字也能看懂。

## 2. 画面（对标 许先森Ai）
- 16:9 横版，1080p，30fps。
- 3D、大场面、科幻质感：发光、景深、粒子、运镜。不做平面的简单动画。网球场用蓝色。
- 字幕跟着画面内容走，放在所讲的东西旁边，不固定在底部。
- 品牌：左上角是网球时差 logo 加文字，用 `overlay.py` 里的 `brand()`，logo 和文字对齐，前面不加竖线。不出现「VIBE 知识」字样。
- 右上角标注沿用 tennislive 的规范：字体跟品牌标一致，右对齐，和品牌标在同一高度。

### 光晕标准（全栏目，2026-11-05 起）

所有者 2026-11-05：「我感觉所有动效里的光晕都很亮，你要统一复查下，同时设定好一个全局标准」（之前分别说过「字体的光晕太亮，看不清楚真正的文字」「多股线的光晕太亮了」）。
**发光是质感，不是主体**——字、数据、物体本身要先看得清，光只在边缘提一点亮。

| 管什么 | 上限 | 在哪儿 |
|---|---|---|
| 泛光（UnrealBloomPass） | strength ≤ 0.25、radius ≤ 0.35、threshold ≥ 0.92 | `scene.js` 里的 `GLOW.bloom` |
| 叠加发光（光点精灵、光环、`AdditiveBlending` 的件） | 颜色一律乘 `GLOW.k`（≤ 0.5） | `glowSprite()`、`flatRing()` |
| 自发光 `emissiveIntensity` | 彩色件 ≤ 0.35，白／近白件 ≤ 0.15；深色底色（亮度 < 0.15）只提暗部、不限 | `GLOW.emissive` / `GLOW.emissiveWhite` |
| 3D 文字精灵 | 光晕透明度 ≤ 0.45、模糊 ≤ 14 px，加 7 px 深色描边，字色压到泛光阈值以下，永远压在物体上面 | `textSprite()` |
| 大面积白色物体 | 不用纯白，压到浅灰蓝 | 例：显微镜镜头的主线 `0xaec4d6` |

**量化判据**（`tools/vibetennis/glow_check.py`，门槛按 EP07 定标准那一轮实测取：改前 24 帧里 14 帧超标，改后 0 帧）：

- 同一帧开／关泛光各渲一张（`VT_QS="&bloom=0" node tools/vibetennis/engine/still.js …`），`--pair` 相减：平均增亮 gain ≤ 1.0、被提亮 > 20 的面积 ≤ 1.5%、> 40 的面积 ≤ 0.5%
- 单帧：任一通道 ≥ 250 的像素 ≤ 0.4%，亮度 ≥ 200 的像素 ≤ 5%——量 **3D 层**（叠字幕之前；白色字幕本身就占 0.4–0.7%）
- 段落切换和「禁」章那种刻意的闪白（≤ 0.45 s）不算

**怎么执行**：每集 `scene.js` 开头抄 `const GLOW={bloom:[0.22,0.3,0.93], k:0.5, emissive:0.35, emissiveWhite:0.15};`（数值可以更暗，不能更亮），泛光写 `new UnrealBloomPass(…, ...GLOW.bloom)`，场景要认 `?bloom=0`；
`tests/test_vibetennis.py::test_光晕全局标准_新一集的scene都按GLOW常量来` 静态把关（定标准前已发的五集挂豁免表，只许减）；
审片包和整片渲之前跑一遍 `glow_check.py --pair`，超标先改再渲。

### 大字标准（全栏目，2026-11-05 起）

所有者原话：「视频里的大字字体也很 low，不精致，出现的时候也没特别的动效，比如粒子汇聚之类的效果」。量出来的根子：机器上思源黑体只有 Regular／Bold，写「900」退成普通 Bold；字先画在 120～150 px 的 canvas 上再放大到半屏，发虚；3D 数字用 Three.js 自带的示例字体；出场只有淡入。

共用模块 `tools/vibetennis/engine/typefx.js`（各集 `r3d/typefx.js` 软链接它，`r3d/fonts` 软链接 `assets/fonts`）：

| 级别 | 用在哪 | 字体 | 出场 |
|---|---|---|---|
| 一级大字 | 钩子问句、公式、「三样」、段落结论、片尾问句 | 思源黑体 Black（`NotoSansSC-Black-sub.ttf`，GB2312 子集；和封面 B 同一款）；英文 Inter Display Black | **粒子汇聚**：约 6000 个粒子沿弧线从四周飞来、从左到右逐字汇聚（1.25 s），落定后实体字淡入、一道光扫过；退场散成粒子 |
| 数据大数字 | 39.5%、95%、66.8%…… | Inter Display Black 3D 挤出（`TTFLoader`，`reversed:true`——OTF 的 CFF 轮廓方向反，不设就是空心字） | 原 t3d 淡入 |
| 标签小字 | 出处、注释 | 不变 | 淡入 |

- 用法：`bt(key, 文本, {size, glow, accent})` 建一级大字，`obj.update(u, 开始汇聚的时刻, 开始散开的时刻)`；`accent` 把重点字换品牌金（同封面「是【线】」）
- 字先在 300 px 高的 canvas 上画（竖向渐变＋深色细描边＋很淡的辉光），字边要锐
- 粒子是叠加发光，亮度乘 `GLOW.k`（光晕标准）；汇聚是连续运动，`motion_check.py` 不会当成跳变
- 只给一级大字和大数字加动效，标签不加，免得满屏乱飞
- 选字过程：2026-11-05 出过三选一样片（得意黑／思源宋体 Black／思源黑体 Black），所有者让我定，定思源黑体 Black（和封面 B 一致）；`?type=A|B` 仍可切回去对比
- 判据 `tests/test_vibetennis.py`：`test_大字标准_新一集的scene都按TYPE来`（不许再加载 `typeface.json`、必须接 typefx、READY 之前 `loadTypeFonts()`）；定标准之前已发的五集挂豁免，只许减不许加

### 转场与运镜（全栏目，2026-11-05 起）

所有者 2026-11-05：「动画的转场和运镜要做的丝滑且有吸引力」。

| 管什么 | 标准 | 在哪儿 |
|---|---|---|
| 镜头切换（段落之间、段内换机位／换物体） | 一律 **0.6 秒交叉溶解**（先慢后快再慢），旧画面边淡出边推近 4%；**不许硬切、不许闪白**（「禁」章那种刻意的冲击闪 ≤ 0.12） | `scene.js` 的 `MOVE.xf` / `xfPass` |
| 切换点 | 载入时按机位跳变**自动**找（粗扫 10 fps、细到 1/240 s），再并上段落起点——新加镜头不用手登记 | `findCuts()` |
| 运镜 | 每个镜头在自己的机位上再缓缓推近 6%、绕目标转约 3.4°（相邻镜头方向交替），**不许有静止的机位** | `MOVE.push` / `MOVE.orbit`，在 `look()` 里统一加 |
| 循环动画（慢放撞击这类一轮轮重复的） | 每一轮首尾**淡入淡出**（球、光环、箭头），不许从终点瞬移回起点 | `impact()` |
| 闪白、抖屏 | **一律不用**。闪白在线性空间里混，0.1 到屏上就是三成多的亮度跳变；冲击感交给物体本身的动作（盖章落下 0.6 s、光环收拢） | — |

**量化判据**（`tools/vibetennis/motion_check.py`）：成片按 30 fps 逐帧算相邻两帧平均绝对差（0–255），任何一帧 > 12 就是硬切／跳帧。
定门槛那一轮：EP07 改前成片 49 处超标（闪白和硬切冲到 30–150）；改成交叉溶解后，跨切换点逐帧差最大 1.9。
第一版交叉溶解的成片又抓到 6 处：循环撞击的球瞬移回起点（15.5）、切换点二分精度 1/240 s 让一帧先硬切（24.5）、「禁」章抖屏＋闪白（90）——修完逐帧最大 4.7。

**怎么执行**：每集 `scene.js` 抄 `MOVE`、`findCuts()`、`xfPass` 那一套（EP07 拍线篇是第一集）；
`tests/test_vibetennis.py::test_转场运镜全局标准_新一集的scene都按MOVE来` 静态把关；成片出来跑 `motion_check.py`，`qc.py` 之前过。

## 3. 声音
- 中文版自 EP03 起有 TTS 旁白（见 SKILL.md）；旁白加音效，音效要和画面动作同步（击球、出现、转场），不能只有背景音乐。
- BGM 要有授权，确认不了就先不放，标注出来请 Robert 定。

## 4. 自检
- **整片渲之前**先跑 `tools/vibetennis/engine/review_pack.py <集目录>` 出静帧总览，发给所有者看过再整片渲（2026-11-03 起；EP05 的画面问题全是渲完才发现的）。
- 出片后 `qc.py` 自动查：背景声铺满全片、有旁白的中文版配音齐全不重叠、多音字已换字或认领（`voice_check.py`）。
- 抽帧做 contact sheet 检查：画面和旁白是否对得上，字幕有没有越界，品牌标位置对不对。
- 自己发现的问题自己先修，再交给 Robert。

## 5. 导出
- 母版：高码率，存档用。
- 推送和分享用的版本：H.264 High，1080p，约 7.5Mbps，AAC 音频直接拷贝，加 `-movflags +faststart`。文件大小不设上限，内容充实超过 200MB 也可以。发布链接只放这个版本，母版码率太高，手机边下边播会卡住。

## 6. 封面（独立 3:4 高清图，每期出多个方案）
- 封面不放进视频，也不和视频合成在一起，只作为推送封面。
- 封面不能只做一种：每期至少出 3 个不同风格的方案，让 Robert 挑选或混搭。
- 风格参考库，每期从中选取并组合：
  - **比特新语风格**：画面本身直观表现核心概念。以样片为例：蓝色全场竖向透视，球从对面飞向观众，球要小。
  - **小作坊风格**（小红书）：黑底，一个金色发光的主视觉直接表现概念；顶部一句问题，关键词高亮；中间大号字距拉开的标题配英文小字；底部一行副标题和一个公式或核心数字。
  - **许先森风格**：3D 大场面，电影感光效和景深。
- 共同要求：标题是完整的问句，左上角放网球时差 logo 加文字并对齐；不加分类标签（比如「视觉科学」），不加装饰性的黄色竖条；配色以金色为主，可以加醒目的强调色。
- 先出全部方案给 Robert 看，他选定后再推送。
- Robert 以后发来的新参考也补进这个风格库。

## 7. 发布（tennislive 仓库）
- 新建一集：`tools/vibetennis/episodes/`，输出放在 `output/<日期>/vibetennis/<slug>/`。
- 推送标题格式：`EPNN.vibetennis|四字主题`（两位集数＋点，不写日期；例：`EP01.vibetennis|现场更快`、`EP03.vibetennis|上旋下坠`）。集数在 `data/vibetennis_episodes.json` 里按 slug 登记，新一集先登记下一个号；`EP01.vibetennis|` 占 16 个字，主题正好 4 个字。正文风格和其他子栏目一致。按钮文字是「▶ 打开横版成片」。
- 正文 tag：必带 `#vibe知识大赏` 和 `#网球时差`，**不带** `#网球中国赛季来了`、`#网球时间到` 两个中国赛季活动 tag，总数 ≤5。由 `src/tennislive/render/hashtags.py` 的 `COLUMN_REQUIRED_TAGS` / `CAMPAIGN_EXEMPT_COLUMNS` 在推送正文和复制页两处统一处理（只对 vibetennis 生效，其他栏目不变）。
- vibetennis 是新流水线，只要满足基本的业务流程要求就行，老栏目的检查项不能卡住它。
- 通过 QC 后直接推送到微信，不用再问。推送完把 PushPlus 链接发给 Robert。
- PushPlus 发出去的页面改不了。要换封面或文案只能重新推送，推之前先说明会多发一条消息。

## 8. 英文版（每集都有）
- 所有者 2026-10-31：每集都出英文版。英文版**没有配音**，只保留 BGM 和音效（不再给人声让位，整片 -14 LUFS / 峰值 ≤ -1 dBTP）；画面上所有文案、数据卡、字幕、参考页都换成英文，旁白内容用英文字幕放在原来字幕的位置和时间。数字和物理一个都不能改。
- 品牌名英文写 **Tennis Jetlag**（Jetlag 一个词）：左上角 logo 文字、封面、推送正文里都用它，logo 图形不变。
- 英文字体要覆盖所有符号（×、≈、°、—、“”），逐帧抽查不能有方框（tofu），不能残留中文。
- slug 是原版加 `-en`（如 `vibetennis-live-faster-2026-en`），spec 写 `"lang": "en"` 和 `"variant_of": "<原版 slug>"`；集数跟原版同一个，不在 `data/vibetennis_episodes.json` 单独登记。
- 成片作为第二个附件 `<slug>-en.mp4` 传进**原版那一集的 Release**，和中文附件并列；中文附件不动（`release.py` / 上传工作流的 `release_tag`）。
- 英文版单独推一条微信：标题 `EPNN.vibetennis|英文主题`（仍是 ≤20 字符、无空白，英文主题最多 4 个字符），正文英文，按钮「▶ Watch the video」指向英文成片，tag 带 #vibe知识大赏 和 #网球时差。封面用原版选定的那张、文字改英文。
- ⚠️ **中英两版的 `render.json` 不能在同一次合并里进 main**：`auto-push-vibetennis` 的闸是「一趟最多一条」，一次带两条就**两条都不发**（EP04 #1414 撞上，run 41300377665）。做法：成片、凭证和复制页可以一个 PR 一起合；如果已经一起合了，就各开一个只改那一份 `render.json` 的小 PR（加 `_push_why`，QC 凭证不钉这个文件），依次合并，一条推完再合下一条（EP04 #1415 / #1416）。

## 9. 视频内置横版封面 + 竖版封面（每集、中英文都要）
- 所有者 2026-10-31：每一条 vibetennis 视频（中文版和英文版）都要内置 16:9 横版封面，免得平台缩略图是黑的：
  - 用和推送封面同一风格做一张 1920×1080 横版封面（同一套画面，文字重排；英文版写 Tennis Jetlag），单独存一份 jpg（YouTube 等平台上传封面用）；
  - 嵌进 mp4 作为封面图（`attached_pic`）；
  - 片头加 3 帧（约 0.1 秒）这张横版封面，抓首帧做缩略图的平台也能显示；音频同步在前面补 0.1 秒静音，其余不变。
- 另出竖版封面给短视频平台：3:4（推送海报本身）和 9:16（1080×1920）各一张。
- `film.cover_in_film` 仍写 false：它指的是 3:4 推送海报不拼进片子；片头那 3 帧横版封面是成片自带的。
- 改完重新跑 `tools/vibetennis/qc.py`（真峰值 ≤ -1 dBTP：重编码 AAC 后峰值可能上浮，必要时整体降 0.5 dB 左右）。
