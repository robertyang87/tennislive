# Jev 生产辅助分流

`oncourt-interviews.yml` 每轮采集导出尚未分类的新素材，独立 `jev` job
使用固定模型 `jev-1.13.0` 生成建议。出片矩阵仍只依赖 collect，Jev 慢、
不可用或报错不会阻塞转写和渲染。采集器保留现有网球门禁、拒绝名单、
已有人审结论、来源规则与片尾采访规则；库存不重新分类。

生产模块来自 PR #976 已验证的 HTTP 客户端和缓存实现，不依赖 demos 目录。
请求仅包含标题、来源和固定分类问题；不发送 URL、库存标签或人审结论。
标题无法证明画面场合，因此即使建议 interview，也只进入 artifact 内的
`review_queue`，必须经过现有视觉复核才能入库，不自动放行或否决素材。

## 启用与回滚

在 GitHub 仓库 Actions Secret 保存 `TYPESAFE_API_KEY`。没有 Secret 时
显式记录 `missing_secret`、发 workflow warning、零 API 调用。
仓库变量 `JEV_ENABLED=0` 可立即停用后续班次的网络请求；默认开启。
无需改变 DeepSeek、MiniMax 或发布配置。不应为验收手动派发整条采集任务，
因为原工作流含推送与制作动作；等待正常班次即可。

## 成本与失败控制

- 每轮最多 5 次、每 UTC 日最多 20 次尝试；失败也计入预算。
- 24 小时请求内容缓存；模型版本变化会使缓存失效。
- 单次 socket 超时 8 秒，无自动重试；401/402/403/429 立即熔断，其他错误连续 3 次熔断。
- Jev 步骤最长 2 分钟，job 最长 5 分钟；独立并发锁串行保护账本。
- SQLite 账本用 Actions cache 保存。缓存被清理/驱逐会重置调用预算，
  因此这不是供应商账户的硬支出上限。不要把无绑卡视为无限免费。
- 超时请求可能已在供应商侧计费，报告独立记录 `unconfirmed_billing_calls`。

## 验收

每个正常班次的 Summary 显示启用状态、候选量、API 尝试和缓存命中。
`jev-production-review` artifact 保存完整结果及待视觉复核清单，保留 14 天。
候选为空、缺少 Secret 和 API 成功是三个不同状态，不能只看工作流绿灯。
初始目标是补充发现与积累质量证据，尚未证明准确率提升、净成本节约或出片提速。

本次目标回归涵盖 collector 导出、硬门禁、人审保护、无密钥/关闭时零网络、
工作流隔离，以及缓存、预算与熔断。全量仓库回归由 PR CI 运行。
