# 人物故事的视觉层级

本文是 story_visual_policy 的配置与使用说明。结构检查不证明视听质量或传播效果，
也不设置切点频率、变速倍率、音乐或转场参数。

## 制作时执行

- 普通叙述优先真实影像＋短字幕。训练、看台、场馆、人物反应必须对应所讲事件，
  不把没有查到素材当成没有素材。照片与档案也要留来源和年份。
- 只有时间地点改变、关键转折或不可替代的事实证据才加重文字。强调词提炼重点，
  字幕保持完整表达。沿用现有字号、配色、品牌、序号和安全区，不照搬黄字红描边。
- 正文收尾优先人物动作或真实场景呼应主题，再接既有品牌片尾。
  知识解释、原话、数据与规则证据需要字卡时允许保留；没有合适实拍不能硬换无关画面。
- 第一人称句子须有原话证据，不借人物画面虚构其心理或发言。

## 实际入口与边界

`build_match_reel.validate_spec` 对“网球有故事”默认运行同一检查，
`--dry-run`、旁白检查和正式 render 均经过它。连续 title_card、
纯 title_card 收尾、标题与整句旁白完全重复、明确标为 narrative 的 title_card
会在下载/合成之前报错。不会自动删除段落或更改字幕。

段可选 `visual_role`：narrative/context/emphasis/evidence/ending。
确有必要的例外在对应段写 `visual_exception`，解释必要性、来源和替代方案；
检查将例外单独列出，不能冒充已通过画面审查。单纯加一个布尔 true 无效。
现有 `_why` 继续记录镜头来源、事实对应和选择理由。

每次正式渲染在 `render.json.story_visual_review` 记录策略版本、段落类型、
例外及待审清单。静态 spec 无法识别 PNG 是照片还是文字卡，因而所有图片都标为
`image_unreviewed`，必须在原有成片视觉 QC 中逐段查看。没有视觉回执不能声称
这些软性要求都已兑现；没有后台数据不能声称留存提升。

例外示例：一段引语证据必须与上一张法规卡对照时，在后一段写：
`"visual_exception": "两张分别为原规则和原话，需逐条对照；来源见 _why，合并后字小不可读"`。
不得仅写“通过”“已批准”或借例外跳过事实、版权、结尾与字幕硬约束。

## 验证与撤回

行为测试覆盖实际 validate_spec 调用、正确故事、错误卡片、显式例外和非故事栏目。
同一素材做对照时一次仅改变文字强调方式，其他变量保持不变；
完整成片视觉 QC 后再收集相同观察窗口的观看数据，当前效果状态为 not_measured。
需撤回时回退本改动；已有片子不自动重渲、不重新发布。
