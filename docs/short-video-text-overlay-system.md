# 网球时差：短视频屏幕文案设计系统

> 2026-08-24 定稿；同日依据手机端终审升级字号与配色。服务 3:4（1080×1440）真实比赛画面，覆盖「网球有故事」
> 和「赛场之上」的补充信息层。它不是封面模板，也不是旁白字幕模板。
> **2026-09-05 配色并进品牌系统**（账号所有者「文字贴图也要重新设计好看些」）：一个强调色，见 §2 第 4 条；
> 同日起**换到另一场球的那一段要贴一张「哪场球、几比几」**（「转场没交代具体比赛和比分」），见 §6。

## 1. 研究结论

公开资料能证明“屏幕文字有效”，却不能证明“越大块、越花越有效”。因此这里把
平台可验证结论、优秀体育内容观察和本账号实片问题分开：

- TikTok Creative Accelerator 写明：字幕能改善观看时长、理解、记忆与好感；
  text overlay 用来**强调关键信息**。同一份指南同时要求首段钩子与主叙事一致，
  并把重要信息放进 safe zone。它不是让一屏塞进更多字，而是让重点更明确。
  来源：<https://ads.tiktok.com/business/creativecenter/quicktok/online/tiktok_creative_accelerator/pc/en>
- YouTube Shorts 编辑器会在文字靠近边缘、点赞/评论/简介覆盖区时提示 non-safe；
  官方同时建议用时间轴控制每条文字何时出现、何时消失。来源：
  <https://support.google.com/youtube/answer/16215842?hl=en-GB>、
  <https://support.google.com/youtube/answer/13380879?hl=en>
- Meta 的 Reels 指南将“竖屏、声音、关键信息在 safe zone”作为一组有效创意条件；
  其广告拆分测试里，这组创意比静图广告的单次结果成本低 34.5%。这个数字来自
  广告，不直接外推为本账号播放增幅；只采纳 safe-zone 原则。来源：
  <https://www.facebook.com/business/ads/facebook-instagram-reels-ads>
- W3C 的保守可读性基线是：普通文字与背景至少 4.5:1，大号粗体至少 3:1；
  复杂图像底上可用遮罩或文字 halo 保持对比。视频底色持续变化，因而本系统
  使用紧描边和软投影，不靠一整块不透明底板。来源：
  <https://www.w3.org/WAI/WCAG21/Understanding/contrast-minimum.html>
- WTA 的 TikTok 增长案例把运动员本人、胜利瞬间、巡回赛生活和轻量幕后内容列为
  核心形态；17 个月粉丝由 2.9 万增长到 92 万。它说明人的动作和表情是主体，
  信息层不应遮住主体。来源：
  <https://www.guptamedia.com/case-study/womens-tennis-association-social-growth>
- ATP 的 `This Is Tennis` 以短促口号、真实人物和情绪叙事连接年轻观众；值得学的
  是“一个画面、一个情绪落点”，不是复制英文广告字体。来源：
  <https://www.atptour.com/en/news/this-is-tennis-2024-atp-tour-season>

本账号旧版郑钦文片的人工复盘：864×232 的深色圆角板以 62% 画幅宽贴在右上，
与底部字幕同时出现；标签、主标题、证据三行都装在同一块 UI 面板里。连续 13 张
同形面板会把人物故事变成“后台数据卡轮播”，也是账号所有者所说“没有设计、乱”
的直接原因。另有全角竖线 `｜` 不在子集字体中，成片显示成方框。

## 2. 设计原则

1. **一屏一个记忆点**：名字、关键数字或转折句只选一个做主标题；完整解释交给
   旁白，逐字内容交给字幕。
2. **真实画面是第一层**：不使用大面积矩形底板。用短双色竖轨、白字、暗色紧
   描边与投影建立可读性，让人物和击球仍然占画面主导。
3. **信息角色不混用**：封面负责让人点开；底部字幕负责“听懂”；屏幕文字只负责
   让观众记住一个硬事实。屏幕文字不得成为第二套逐句字幕。
4. **一个强调色，而且是品牌那一个**：品牌绿 `#c6f65a`（封面比分板赢盘数字、
   章节卡、片尾同一支）只用于标签、短轨和硬数据；姓名与事件用暖白 `#f4fbf7`，
   证据用冷灰白 `#d5e2db`；描边和阴影用墨绿 `#04120d`。不按关键词随机换色，
   不做彩虹字。⚠️ 2026-09-05 之前这儿是球场蓝＋网球黄**两个**强调色——它们和
   片子里别的任何一样东西都不是一家，压在品牌绿的封面、章节卡之间读起来像
   一张别处贴来的贴纸。账号所有者「文字贴图也要重新设计好看些」之后收成一个
   （判据 `test_story_info_band_uses_the_brand_green_as_its_only_accent` 钉在
   渲出来的像素上）。
5. **出现即有意义**：只在人物第一次出现、关键身份变化、硬数据或叙事转折时上屏；
   同一事实不反复出现。

## 3. 四种语义变体

| variant | 主焦点 | 例子 |
|---|---|---|
| `timeline` | 伤病、复出、缺席等节点 | `右肘手术` / `退出2025美网` |
| `player` | 对手姓名；排名或武器作次焦点 | `尤晓迪` + `世界第198` |
| `stat` | 一个可核实的硬数字 | `世界第127`、`20记ACE` |
| `chapter` | 故事结构上的门槛/转折 | `三轮  三道门` |

四种变体只改变主标题**字号**（stat 134 / chapter 126 / 其余 122，1200 宽画布），
不改变网格、位置、固定颜色分工和动效，因此有变化但不乱。主标题一律得意黑
（`SmileySans-Oblique`，和封面钩子、章节卡同一副脸）；描边收到 1~2px，可读性主要
靠整层高斯模糊过的软阴影——2026-09-05 之前是 6px 硬描边＋硬偏移黑影，压在球场上
像贴纸。

## 4. 固定规格（1080×1440）

- 源 PNG：1200×340 RGBA；成片用 Lanczos 缩小。
- 成片占宽：`0.60`（648px）；离画布边缘：`0.085`（约 92px）。
- 字号：标签约 30px，主标题约 70px，统计主标题约 78px，排名/指标约 41px，
  证据行约 32px。
  这是手机端实片终审后的目标字号；长姓名可在限定范围内自适应，超长内容改写。
- 展示：`3.8s`；入场 `0.28s` 淡入 + `14px` 上浮，随后淡出；不弹跳、不旋转。
- 字数预算（混排按视觉宽度折算）：kicker ≤18、headline ≤10.5、metric ≤11、
  detail ≤23。每个字段只能一行。
- **比分/数字串走 `TL Score`**（和封面比分板、视频顶栏同一支），汉字走 Noto；
  两种字共用一条基线。headline＋metric 一行装不下**当场拒绝**，不静默伸出画布
  （第一版「决胜盘 1-5 赛点」就被切成了「赛」）——metric 写短，后半句挪进 detail。
- **画常驻角标的栏目（网球有故事）里，顶角贴图自动让到角标块底下**：spec 的
  `pad` 照旧写 0.085，`build_match_reel.inset_top_clear_y()` 按这条片子真实的
  角标几何算下限（两行角标、没顶栏是 y=151），`_overlay_chain` 只往下推不往上拉。
  合同 2026-08-24 定的 0.085 落在 y=92，而角标（2026-09-01 起）两行字占到 y≈125
  ——照合同贴，标签那一行正压在副标题上。
- 禁用 `｜`/`|` 拼字段：语义必须拆进 `headline`、`metric`、`detail`；同时避免
  子集字体缺字。
- 默认不贴底部和最右边；底部留给字幕，最右边留给平台操作 UI。当前郑钦文片
  仍用右上角，但通过 92px 外边距和 PNG 内部留白把真实文字收进安全区。

生成命令：

```bash
python tools/render_story_info_band.py \
  --variant player --kicker "第一关" --headline "尤晓迪" \
  --metric "世界第198" --detail "六安W100冠军 · 擅长苦战" \
  --out assets/beatcards/demo/info-you.png
```

spec 使用设计合同：

```json
{
  "inset": {
    "image": "assets/beatcards/demo/info-you.png",
    "kind": "story_text",
    "corner": "tr",
    "width": 0.60,
    "pad": 0.085,
    "show_for": 3.8,
    "motion": "editorial"
  }
}
```

`parse_segments` 会拒绝超出宽度、时长、边距或错误动效的 `story_text`；
`test_story_info_band.py` 会拒绝大面积实色底板、超长文案、换行和竖线字段；
`test_inset_animation.py` 真渲验证出现/淡出，并锁定编辑型轻动效。

## 5. 发布前人工一眼检查

- 缩到手机宽度，主标题能否在一秒内扫懂？
- 文字是否盖住球员脸、击球点、记分牌或赛事关键信息？
- 去掉旁白后，这条屏幕文字是否仍是一个完整、可核实的事实？
- 它是否只是把底部字幕又抄了一遍？若是，删掉。
- 人物卡出现时，画面中是否就是这个人？
- 明场、暗场各抽一帧，文字是否都清楚且没有方框缺字？

效果不凭主观宣布“更传播”。以后同体裁至少积累 5 条，再比较 2 秒跳出、平均观看
时长、完播、转发/收藏；时长不同的片子不能只横比完播率。

## 6. 换到另一场球，先贴「哪场球、几比几」

账号所有者 2026-09-05（`comeback-five-love-down`，四场球剪在一条片子里）：
「**转场没交代具体比赛和比分**」。一条片子里第一次切到某场球的那一段（含冷开场），
右上角贴一张 `player` 变体的 story_text，3.8s 淡出：

| 字段 | 放什么 | 例 |
|---|---|---|
| kicker | 年份 ＋ 赛事 ＋ 轮次 | `2026 美网第三轮` |
| headline | 主角 vs 对手（**主角在前**，和旁白的视角一致） | `郑钦文 vs 凯斯` |
| metric | **这一段画面上那一刻**的比分（哪一盘 ＋ 局分） | `决胜盘 1-5` |
| detail | 一句证据：谁发球、几比几的分、几号种子 | `凯斯发球胜赛局 40-30 赛点` |

- 比分**逐帧读转播记分条**（`ffmpeg -ss <t> -frames:v 1` 裁左下角放大），不按旁白
  写——旁白讲的往往是「这一局从几比几开始」，画面上已经是下一分了
- 章节卡（`title_card`）自己就写着赛事和对阵，前后不再贴
- 写进 spec 的 `_inset_why` 要带上读的是成片第几秒、记分条原样是什么
