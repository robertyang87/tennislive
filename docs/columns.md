# 栏目

> 栏目名印在每张卡的片头（`网球时差 · ⟨栏目⟩`）、封面小标签、小红书标题和落款上。
> 它是**对读者的承诺**，不是装饰——所以哪条片子归哪个栏目，是内容问题，不是排版问题。
>
> 解说视频那三个登记在 `src/tennislive/video/explainer.py` 的 `COLUMNS` 里；片子在
> `_OPENINGS[slug]["column"]` 声明自己属于哪个，不写＝`网球有故事`。别的生产线各自
> 带自己的常量（如 `daily_point.py` 的 `_COLUMN_LABEL`）——**代码里出现的栏目名，
> 必须能在这份文档里找到**，见 `test_栏目名不能只活在代码里`。

## 全部栏目：握手是分界线

账号对外可见的栏目不止解说视频那两个。把它们排在一起看，锚点只有一个动作——**握手**：

| 栏目 | 相对握手的位置 | 承诺 | 单位 | 生产线 |
|---|---|---|---|---|
| **开球之前** | 之前 | 一场还没开打的比赛，把两边这几年的来路摆在一起；不猜比分 | 一场 | 解说视频 |
| **赛场之上** | 打到握手为止 | 比赛本身：集锦画面 ＋ 配音讲清走势、转折和回应 | 一场 | 集锦视频 |
| **赛后开麦** | 话筒递过来 | 打完的人自己怎么说 | 一句话 | 采访视频 |
| **昨日好球** | —— | 昨夜官方剪出来的那一个回合 | 一分 | 单分视频 |
| **网球有故事** | —— | 一个人人见过、没人讲得清的网球现象，讲清它的来历和现在 | 一个现象 | 解说视频 |
| **历史上的今天** | —— | 这一天发生过的那件事 | 一个日子 | 图文知识帖 |

**曾经还有一个「握手之后」**（之后 / 这场对两个人各意味着什么 / 解说视频），和
「赛场之上」的界线按握手划。撤了，理由见下面「撤掉过的」——一年下来没有一条片子
真的需要那条界线。**留下的教训是那条界线的划法**：按**时间**划，不按深浅。
一度想按"快/深"分，那是条守不住的线——同一场比赛讲得深一点浅一点，读者分不出是
两个栏目还是一个栏目手抖。现在「赛场之上」和「赛后开麦」还是按握手划：
打到握手为止 vs 话筒递过来之后。

**「赛场之上」命名的是地点，不是单位**，这是知道并接受的取舍。「昨日好球」那条球也发生
在赛场之上，名字本身划不开两者——**靠的是窄的那个名字守住"一分"，宽的那个自然就是剩下
的整场**。单位由窄的一方承担，宽的一方不必自证。换来的是这一路十个候选里唯一一个不像
"功能说明"的名字（试过的都记在下面）。

「赛后开麦」的采访其实也在赛场之上，但「赛后」两个字把时间标出来了，不冲突。

### 「赛场之上」的整改内容合同

从 2026-08-06 起，新做的「赛场之上」按**原创比赛复盘**执行。这里的“原创”指本号
对比赛走势提出并讲清一个可核验的问题和判断，不是声称拥有比赛原始画面的版权，也不
承诺平台一定恢复流量。视频不能只靠裁切、标题、比分字幕或背景音乐制造变化。

每条新片在 `specs/reels/<slug>.json` 里写 `editorial`：

- `mode: match_review`；
- 一个 `question`，明确这场球要回答的问题；
- 一条 `thesis`，说明走势变化和本号判断；
- 至少三个 `beats`，分别覆盖前段走势、中段转折、结局/回应；
- 一份 `human_context`，记录这场独有的新闻、人物或现场切口，以及事实来源。

“场外补充”不是固定的菲律宾球迷、售罄门票或任何单一模板。每场根据选手和当天语境选择
一两个最相关的方向，例如主场压力、家乡球迷、里程碑、复出、宿敌、票房、赛程背景、采访
金句或球员个性；没有可靠热点时不硬塞。旁白要解释“为什么变化”，同时让观众感到这是一场
具体的人正在经历的比赛，而不是按记分条把每一局念一遍。新闻事实、战术和心理判断都必须有
官方赛报、采访、统计或画面依据。默认保留现场声、不加背景音乐；真人录音优先，语音合成
版本先作为待审核成片。

#### 比分顶栏版式

比赛顶栏继续保留，且只从封面结束显示到比赛画面结束：封面不挂，`关注网球时差` 片尾
不挂。第一行用标题字体 `得意黑`，第二行用正常中文字体 `Noto Sans CJK SC`。第二行
固定写成“赢家 + 完整比分 + 对手”，并且必须和 `cover.winner`、`cover.result`、
`cover.matchup` 一致；不要手写一份与封面不同的赛果。

整改期的新片先 render 和人工验收，不自动推微信；得到账号所有者认可后再恢复常规发布
流程。详细执行闸门和示例见 `CLAUDE.md` 的「平台整改后的『赛场之上』」章节。

## 解说视频的两个

| 栏目 | 承诺 | 保质期 | 例子 |
|---|---|---|---|
| **网球有故事** | 一个人人见过、没人讲得清的网球现象，讲清它的来历和现在 | 常青 | 鹰眼、黄球、挑球、25 秒发球计时 |
| **开球之前** | 一场还没开打的比赛，把两边这几年的来路摆在一起；不猜比分 | **开球即过期** | 郑钦文 VS 伊埃拉：华盛顿站首轮 |

两者并行，谁也不是谁的子集。

「开球之前」和「赛后开麦」是一对：两个名字都指一个**时刻**，不是一段时间——
第一球之前，和话筒递到场上的那一下。（原来配对的是「握手之后」，它撤掉之后这个
位置由「赛后开麦」接上——都在握手之后，只是它不由我们讲，是当事人自己说。）

（原来叫「开赛之前」，后来改的。「开赛」听着像一段时间，「开球」是一个动作，
和「握手」正好对上——这一对的整个道理就建立在「都是一个时刻」上。**改名之后，
已经推送出去的三条前瞻没有重新生成**：卡上印的还是「开赛之前」。这是有意的取舍，
改的是以后，不动已经发出去的。）

## 为什么解说视频只有两个——而全账号有六个

这两件事不矛盾，分界在**按什么分**。

- **按题材分会糊**：人物志、低谷之后、Challenge / Off Court……读者拿到一条片子，
  没法从内容本身看出它该归哪个，只能记名字。记不住就白设。
- **按位置和单位分能记住**：赛前 / 赛中 / 赛后 / 话筒，一分 / 一场 / 一句话——
  这些差别**在内容里看得见**。点开是一个回合还是一整场，不用记，一眼就知道。

所以下面这些是撤掉的（全是按题材分的），上面那张表是留下的（全是按位置和单位分的）。
新开栏目之前先问一句：**读者能不能从内容本身看出它属于哪个？** 不能就别开。

试过第四第五个。设计、命名、渲卡确认字体，最后连注册表都写进去了，还是撤了——
理由只有一条，但它压过所有设计上的漂亮：**栏目多了，读者记不住**。

栏目是承诺。一个号能让人记住的承诺就两三个；到第五个的时候，读者不会觉得"这个号
分得真清楚"，只会觉得"这些名字是什么意思"。多一个栏目，每一个都薄一分。

撤掉的和绕过的，连理由一起记在这儿，免得过一阵又重来一遍：

| 试过 | 是什么 | 为什么没留 |
|---|---|---|
| `First Serve` / `Second Serve` | 讲一个人：第一次被记住 / 又一次被记住 | 设计成对、名字也贴，但**加起来就是五个栏目**，读者看不懂 |
| `人物志` | 讲一个人 | 太普通，每个号都有一个；而且只是分类标签——另外几个名字里「开球之前」「赛后开麦」有画面、「网球有故事」有承诺，它两样都没有 |
| `低谷之后` | 讲复出 | 太局限。「握手」是看得见的动作，「低谷」是个判断，有人是伤退不是状态跌 |
| `回来的人` / `久等了` | 讲复出 | 都指**处境**，一指处境就会把人排除掉 |
| `Top Seed` / `Baseline` | 讲巅峰期的巨星 | 巅峰期的人没有「中间那几年」，他的故事就是正在发生的比赛——已经有 `赛场之上` 和 `网球有故事` |
| 把 `网球有故事` 拆成 Challenge / Off Court 等 | 按题材细分 | 同一个毛病，而且它已经印在十一条**发出去的**片子上，拆了老卡新卡对不上 |

**讲一个人的片子现在归哪儿**：夺冠、复出、告别，本身都是一场刚打完的比赛，归
`赛场之上`，只是讲的重心往前推到他这些年。真到了「三条都塞不进去」的那天再开第四个，
那时候形状也看清楚了；设计和取舍都在 git 历史里，不用重想一遍。

### 「赛场之上」定下来之前试过的十个

十轮里前九个都被同一句话否掉：**太平淡**。回头看原因是一致的——它们描述的都是
**做法**（看完、讲完、不止、背后），而这个号最好的两个名字（`开球之前`、`赛后开麦`）
描述的是**位置**。

| 试过 | 为什么没留 |
|---|---|
| `一场看完` / `讲完一场` | 承诺的是"省时间"，是功能说明不是承诺；而且「看完」的主语是读者，不是我们 |
| `怎么赢的` | 问句有钩子，但主角输球那天镜头被迫对到对手身上 |
| `你错过的那场` | 接住了账号定位（"你睡着时"），但五个字 |
| `补一场球` | 「补」的网络语感对，整体太普通 |
| `一场好戏` | 和「好球」成对，但不承诺赛果，且"好戏"本身是烂大街的词 |
| `比分背后` / `不止比分` | 方向对（比分装不下的那部分）、中立，但仍是在交代内容边界 |
| `比分骗人` | 这个方向最响的四个字，**但站不住**——6-0 6-0 那种场次比分就是全部真相。`CLAUDE.md` 那条「煽得起来但站不住的话比平淡的真话更糟」正好管它 |
| `听一场球` | "球是用听的"这个意外足够抓人，**但和真实看法对着干**——静音刷是默认状态，整套字幕就是为它做的 |
| `战至握手` | 自带整场、还顺手划了界线，但「战」对一场没分量的首轮撑得慌 |
| `昨夜错过` | 和「昨日好球」结构完全对仗，**工整反而成了缺点**：两个都以"昨"开头，读者会记混 |

## 怎么选

**先问：这条东西是多大一块？**

- 一个回合 → `昨日好球`
- 一句话（球员自己说的） → `赛后开麦`
- 一整场 → 往下走
- 都不是 → 跳到最后两问

**再问：这场比赛打到哪儿了？**

- 还没打 → `开球之前`
- 正在讲这场怎么打下来的（集锦＋配音） → `赛场之上`
- 讲这场对两个人各意味着什么 → 也是 `赛场之上`，把意义讲进配音里。**讲他这些年的
  片子同样归这儿**——夺冠、复出、告别都是一场刚打完的比赛，只是重心往前推
- 想让当事人自己说，不加解说 → `赛后开麦`

**再问：这一天有没有锚点？**

- 有，而且是今天 → `历史上的今天`（见 `docs/column-operations.md`：命中当日压过所有候选）

**最后问：明年还成立吗？**

- 成立 → `网球有故事`。这类片子讲的是规则、器材、习惯的来历，时间不会把它讲错。

混用的代价是实打实的：前瞻挂在 `网球有故事` 下面，读者会当成常青内容再转发，而卡片上
没有任何东西告诉他这条已经过期了；反过来，知识片挂在 `开球之前` 下面，会被当成蹭热点的
即时内容，看完就划走。

## 易逝栏目的额外一条：必须写出比赛日期

`Column.perishable=True` 的栏目，片子里**必须出现「X 月 X 日」**。测试
`test_栏目是登记过的并且赛前片子写清了日期` 会挡住没写的。

理由很直接：**过期的前瞻和没过期的前瞻，长得一模一样**。卡片会被单独截图、被转发到几天后
的群里，那时候没有任何上下文——日期是唯一能让读者自己判断"这条还算不算数"的东西。
郑钦文那条把日期写在第 ⑤ 屏和折线图脚注上（`7 月 27 日首轮`）。

### 「开球之前」只做巡回赛级别，250 及以上

账号所有者定的选题门槛：「**需要巡回赛级别，250 以上**」。ATP/WTA 250 / 500 /
1000、大满贯、年终总决赛、团体赛做；**WTA 125、挑战赛、ITF 不做**——读者认不出
赛事，两边这几年的来路也摆不出份量。

名单直接复用今日赛程那边的 `TOUR_LEVELS`（`render/webcards.py`），不另立一套：
两处各定一套门槛，迟早会漂开。判据是封面小字里的 `level` 字段
（`test_赛前片只做巡回赛级别的比赛`）——门槛用的那个数，就是印在卡上的那个数。

顺带一条挑选顺序（不是硬规矩）：同一天有多场够门槛的，优先中国／香港球员，
其次是排名落差大到值得讲的对阵。2026-07-30 那天温哥华的 WTA 125 有一场中国球员
的比赛，就是被这条门槛挡在外面的。

### 易逝栏目的封面：问题下面两行小字

日期写在片子里还不够——**封面会被单独截图转发**，那一屏上只有一个大问题，
读者看不出这是哪一场、几点打。所以「开球之前」的封面在问题下面固定印两行：

```
7.30  09:00  ATP250 洛斯卡沃斯  16 强
黄泽林  VS  莱赫奇卡
```

- 第一行是比赛坐标（日期、开赛时刻、级别与站点、轮次），第二行是对阵
- 从 `_OPENINGS[slug]["fixture"]` 的结构化字段拼出来（`_fixture_lines()`），
  **不手写整行**：日期和轮次在旁白、要点、小红书文案里各出现一次，手写第四遍
  必然有一处对不上
- **时刻可以缺**：三条已发的前瞻当时没有记下官方开赛时刻，缺了就不占位置，
  宁可不印也不猜。日期、赛事、轮次、两个人的名字一个都不能少
- **名字查译名表**，和别处一样
- 有这两行时，卡片顶栏那句台头让位——两处讲同一件事，而小字这份还多一个时刻
- 常青栏目**不许**有这两行：它们没有一场比赛可以钉，印上去是噪点
- 判据：`test_赛前片的封面要写清是哪一场`（数据和渲出来的卡都查）

**`赛场之上` 和 `赛后开麦` 不吃这条硬要求**——它们不会过期，「谁赢了这场」「他当时
说了什么」明年也还成立。但它们**仍然该写日期**，理由不同：这类片子会在几天后被翻出来
转，读者要知道说的是哪一场。这是约定，不做成测试；做成测试就等于把两种完全不同的
理由塞进同一个判据里。

## 加一个新栏目

0. 先过一遍上面那句：**读者能不能从内容本身看出它属于哪个？** 不能就别开。
1. 写进本文档最上面那张表：位置、承诺、单位、生产线。
2. 解说视频的栏目还要在 `COLUMNS` 里登记：`name`（印在卡上的字）、`promise`
   （一句话，写给以后的自己看）、`perishable`（会不会过期）；片子在
   `_OPENINGS[slug]` 里加 `"column": "⟨新栏目⟩"`。别的生产线用自己的常量，
   但名字必须和本文档一致。
3. 跑 `tests/test_explainer.py`。没登记的栏目名会被 `column_of()` 直接抛出来——
   这是故意的，防止一个错别字凭空造出一个栏目，而卡片照印不误。

栏目名想好了再定：它会印在每一张已发出去的卡上，改名意味着历史内容和新内容对不上。

## 一个栏目只能有一个名字

「昨日好球」这条线上一度有**四个**名字同时在跑：`docs/yesterday-point.md` 写「这一分，
值回放」、`push.html` 印「这一分，值得回放」、成片第一条字幕是「这一分，值得暂停」、
小红书标题和 commit 用「昨日好球」。四个名字等于没有名字。

所以：**代码里出现的栏目名，必须能在本文档里找到**。`test_栏目名不能只活在代码里`
盯着这条——它扫 `COLUMNS` 和各生产线的 `_COLUMN_LABEL`，有一个对不上就红。
（统一成哪一个是 `docs/column-operations.md` 的 R9。）
