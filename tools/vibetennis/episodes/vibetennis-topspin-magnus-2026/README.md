## 重写方法（事件表怎么来的）

1. 事件类别取自 spec 的 `film.audio.sfx`：击球、弹地、球拼字、芯片、片尾重放。
2. 时间轴取自成片本身：全片每 4 s 抽帧读烧录字幕与章节卡（01 PUZZLE 0.0 /
   02 HISTORY 14.25 / 03 MECHANISM 34.6 / 04 EVIDENCE 111.6 / 05 REAL MATCHES
   188.5 / 06 ANSWER 210.1 / 参考文献 239.2）；飞行段（0–15、110–136、162–188、
   209–240）再以 0.2 s 密抽帧定击球/落点。
3. 原混音（BGM＋音效）做频谱通量与 1.5–9 kHz / 50–400 Hz 包络佐证：BGM 的节拍
   网格（≈0.4 s）盖住多数事件，但落点类事件有明显带内峰——开场落点 13.4×@12.12、
   计数完成 4.2×@98.02、弹跳对比 7.2×@167.41、计时落点 9.6×@184.66、片尾重放
   落点 4.1×@219.24、宽景落点 5.0×@232.01（均为峰值/中位数比）。落点类置信高；
   数字弹出、字幕 blip 按帧采样时刻（±0.7 s）置信中；标题 boom、相机芯片声
   置信低-中、已压低增益。本集是空场演播室美学，不加人声床（与 EP02 不同）。

## 交付链（与 EP02 英文版同一条）

`sfx.py` → `sfx/sfx_bed.wav` → 按视频时长 trim → 本集 `ln.py` 同款两遍 loudnorm
（-14 / TP -2.5）→ +1 dB、alimiter 0.56 → AAC 256k → 与原成片视频流（含
attached_pic 封面流）整段 stream copy 拼合 → `tools/vibetennis/finalize.py` →
`tools/vibetennis/qc.py` → `vibetennis-release-upload.yml` 的 replace 路径换版。
