# tennis-editorial

> 从 `CLAUDE.md` 原样搬来，一个字没改。**规矩本身仍在 CLAUDE.md**，这里是撞上问题时才查的档案。

### ⭐⭐ 轮次写「1/8决赛 / 1/4决赛 / 半决赛 / 决赛」，不写「N 强」

账号所有者 2026-09-08：「**以后比赛不要用什么美网 16 强，应该用美网第四轮或者
用美网 1/8 决赛。或者以后的什么，接着继续用什么 1/4 决赛。和那个 semi final
半决赛以及决赛这种，不要用什么八强、四强什么之类的。**」紧接着又补了一句
「**以后都按着这个策略走，不要再出现什么美网 16 强的比赛**」。

| 这一轮 | 写 | 不写 |
|---|---|---|
| 最后一场 | **决赛** | —— |
| 倒数第二轮 | **半决赛** | 4 强 / 四强 |
| 倒数第三轮 | **1/4决赛** | 8 强 / 八强 |
| 倒数第四轮 | **1/8决赛**（大满贯也可以写**第四轮**） | 16 强 / 十六强 |
| 再往前 | **第一轮 / 第二轮 / 第三轮**（首轮、次轮也行） | —— |

#### ⭐⭐ 同日晚上他自己收窄了一档：**拦的是轮次名，不是「强」这个字**

「**比如说他打进了 8 强或 16 强，这个是可以的，但是比赛不能说是 16 强的比赛，
应该说是……第四轮比赛，或者是 1/4 决赛，或者是 1/8 决赛这种**」。

也就是上面那张表的右列**只管「这一场是哪一轮」**，不管「这个人走到了哪一步」：

| | 例 | |
|---|---|---|
| **成绩**（这个人走到哪一步） | 「打进 8 强」「进 16 强」「首次晋级四强」「从资格赛打到十六强」 | ✅ **可以** |
| **轮次名**（这一场是哪一轮） | 「16 强的比赛」「美网 16 强」「男单八强」「下一轮八强，对手是」「四强对手是」 | ❌ 写 1/4决赛 / 1/8决赛 |

⚠️ **两者在语法上分得开，所以判据也分得开**：到达类动词（打进／进／晋级／
闯进／打到／止步／到／离…）或次数标记（第 N 次／首次）**紧挨在 N 强前面
10 字以内、中间不许有句读** → 放行；其余一律拦。量出来的账：赛场之上存量
32 个文件 82 处命中，收窄之后剩 **15 个文件**，放出去的 17 个全是成绩说法，
**一处误放都没有**；留下的全是「2026 美网 女单16强」「洛斯卡沃斯 ATP250，
男单八强」「二〇一九年澳网八强，普利斯科娃对小威廉姆斯」这种真的在给一场球
起轮次名的。采访线同形，16 条降到 9 条。

⚠️⚠️ **判据因此不再是一条裸正则**：`STRENGTH_ROUND` 改名成
`STRENGTH_ROUND_TOKEN`（它只认「N 强」这个词），闸是
`spec_wording.strength_round_hits()`。**名字带 `_TOKEN` 是故意的**——直接拿
它当闸用会把账号所有者点名允许的那一类全判成违规，而那种收紧不吭声。
两条线、教材扫描、`slam_feed` 的产出扫描四处全走这个函数。

⚠️ **闸收窄了，两张豁免表就要跟着缩**（34→17、16→9）：留着一个已经不违规的
名字，它会一直静静地绿着——`missing = 表 − 命中` 那道自检正是为它写的，
不缩的话它当场红。

⚠️⚠️ **而教材（`draft_spec` 的 prompt ＋ `skills/`）故意没跟着放宽**，别来
「同步」它：闸定的是**下限**（什么不许发出去），教材定的是**房子的写法**
（我们怎么说），后者可以更窄。教材仍然只教那一条阶梯（冠军／亚军／半决赛／
1/4决赛／1/8决赛／第几轮）——理由是同一份教材开头那句话反过来用：
**给模型看的每一个词它都可能照着产**，教两种写法的下场就是同一个账号把同一
件事说两个样子。这个取舍记在
`test_喂给模型的教材里不许出现会被措辞闸拦下的写法` 的 docstring 里。

⚠️⚠️ **这条规矩一年里翻了三次，而且是同一个人在同一件事上来回改口径。**
所以三次都记下来——「我记得他上次说的是……」在这一条上**已经错过两回**：

| | 口径 | 判据当时叫什么 |
|---|---|---|
| 2026-08-02 | 不要四强八强，用半决赛 / 1／4 决赛 / 1/8 决赛 | `test_轮次要写半决赛不写四强` |
| 2026-09-01 | 反过来：8 强 / 4 强 / 决赛，不要分数式 | `test_轮次写N强不写分数式` |
| **2026-09-08** | **又翻回 08-02 那一套** | `test_轮次写分数式不写N强` |
| **2026-09-08 晚** | **同一天收窄：只拦轮次名，成绩照旧可以说「8 强」（当前）** | ＋`test_打进N强是成绩不许被轮次那道闸拦下` |

**规矩的形状一个字没变，主语每次都倒过来**——和 2026-08-04 那次「solo 从要写
`_layout_why` 的例外翻成默认」是同一个动作：**闸原样翻面，不是新增一条**。
⚠️ 引用这一节之前先看一眼上面那张表的最后一行是哪个日期，**别照着中间那一行
去写 spec**。

⚠️ **输出取不带空格那一种**（`1/4决赛`，语料里 297 : 96 压倒性）。
「决赛」三次都没变；**「再往前写第几轮」那半条三次都没被推翻**。

⚠️ **R16 那一档有两个合法写法，各按自己知道的东西选**：`round_display()`
只拿到一个轮次名、算不出这是第几轮，给的是 `1/8决赛`；而
`slam_feed._ROUND_BY_CODE` 知道自己在大满贯的 128 签上，`"4"` 给的是
`第四轮`——正是账号所有者点名的那个写法。

判据落在 `test_轮次写分数式不写N强`（reel 和 interview 各一条），
正则和豁免表的单一出处是 `tools/spec_wording.py` 的 `strength_round_hits()`——
它坐在 `validate_spec` 的座位上，所以 `--dry-run` 0.2 秒就报，自动链在发布前
也过同一道闸。五个细节是踩出来的：

- **只查会发出去的字段**（旁白、封面印的字、推送那几栏、小红书文案）。
  `_source` / `_why` / `_match` 这些是写给下一个人看的注解，里面正引着账号
  所有者**三次**原话（含两套被废掉的叫法）——连它一起扫就会把「把规矩记下来」
  判成「又违反了规矩」。同一个错这个仓库里犯过三次
- ⚠️⚠️ **正则只认真的轮次名（2 的幂），不认排名和形容词。** 第一版按裸的
  `\d+强` 扫，34 个命中里 **5 个是误伤**：「从第 540 冲到**十强**边缘」是排名、
  「防守能力**最强**的一批」「延续**强势**」是形容词。所以只收
  四/八/十六/三十二/六十四这几档，**「十强」一律不收**——世界上没有「十强赛」
- ⚠️ **翻面之后豁免表整张换了主语，这是第三次**：08-02 挂「用了强字」的 11 个、
  09-01 挂「用了分数式」的 173 个、09-08 又换回「用了 N 强」的 **34 个**
  （interview 线 16 个）。表的大小每次都跟着倒过来，因为**旧写法本来就是
  上一版规矩要求的**。已发的片子不为措辞重渲（消息收不回来，`push.summary`
  还要和已发的 `copy.html` 逐字相同——`wong-brooksby` 的「黄泽林首进ATP四强」
  就在里面）。**只许减不许加**
- ⚠️ **「四强」这类中文写法也在拦的范围里**，尽管他点名的是「16 强」。
  不拦它的话同一个账号会把同一轮叫两个名字，而那是本文件反复要避免的
  （「同一个账号不能把同一个人叫两个名字」是同一条）
- ⚠️ **interview 线曾经手抄过一份正则**（`bad = re.compile(r"[四八]强|…")`），
  09-01 翻面时才发现——「一个数写两处必分叉」，而分叉的样子是**同一条规矩
  两条线松紧不一，不报错**。现在两条线都 import `STRENGTH_ROUND`；
  ⚠️ 09-08 又抖出**第三份**：`slam_feed._ROUND_BY_CODE`（大满贯的
  roundCode → 中文）。它的键不一样所以没合并，但**输出词汇必须一致**——
  判据不再手写「不许出现的词」那种会过期的名单，改成**直接拿闸去扫这张表的
  产出**，闸翻面它自己跟着翻
- ⚠️ **`_ROUND_DISPLAY` 要收两个方向的键。** 内部那两套产的是「四分之一决赛」
  「16强赛」，而 09-01～09-08 之间落库的代码和草稿产的是「8强」「4强」——
  翻面之后只收前一种，后一种会**原样透出去然后撞闸**，而那正是这张表存在的
  理由（下面「自动链会被这道闸卡住」那节）
- **翻面要两个方向都验**：新写法（1/8决赛 / 1/4决赛 / 半决赛 / 决赛 / 第四轮 /
  第一轮）必须放行，旧写法（16 强 / 8 强 / 4 强 / 八强 / 四强，带不带空格都算）
  必须拦下。只验拦得住的那一半，等于没验它有没有误伤新写法

#### ⚠️ 而翻面之后才发现，这条规矩最该盖住的那一面本来不在扫描面里

`topbar.line1` 写的就是「\<年\> \<赛事\> \<轮次\>」，**整个比赛段一直烧在画面

也就是说翻面之后 `promote_reel_draft` 往 line1 写一句轮次**照样过闸**。

补它的代价当场量过是**零**：46 条 topbar 带旧写法的 spec **全部已经在豁免表
里**（它们的 `cover.topic` 写着同一句），「爱局」在 topbar 里零命中。
判据 `test_轮次那道闸要盖住烧在画面上的顶栏` 钉两头（topbar 真的在面里 ＋
`_` 开头的注解不许被扫），两个方向分别反向验证过。⚠️ 2026-09-08 再翻面时
**这条判据自己的正反例也要跟着对调**——它的样本是硬编码的两句 line1，
不跟着翻的话它会变成一条恒真的绿灯。

⚠️ 顺带量到一处不一致：`voiced_texts`（几成几／写秒／报到分那三条的面）
**不过滤 `_` 开头的键**，而 `outward_deep` 过滤。当时判成「休眠的、量不出
收益」所以没改——理由是「全库 topbar 只有 `line1`/`line2` 两个键、一个注解
都没有」。

`zheng-swiatek-us-open-2026-r4` 重渲那趟第 90 秒红在

⚠️ **当初那次量漏了半边：只量了 `topbar`，没量 `push`。** 而

（`_summary_why` / `_lead_why` 就住在那儿）。重新量：**全库 128 个 spec 的

⚠️ 「今天量不出收益」这个结论本身没错，错的是**量的范围**。下次给一个缺口
判「休眠」之前，先问一句：**我量的那个面，是它全部的面吗？**

`test_push和topbar里的注解不算文案` **钉两头**：注解不许被扫到、**真的会

另一条走真入口 `check_spec_wording`，拦「函数收窄了而闸从别的面又把注解扫

#### ⚠️⚠️ 更贵的一条：不转换的话，**自动链会被这道闸卡住，而它长得像「今天没有候选」**

内部有**两套**轮次名——`zh.terms.round_zh`（SF→半决赛、QF→四分之一决赛）和
`oncourt_feed.parse_round`（同一套词）——它们经这三处流进**会发出去的字段**：

    promote_reel_draft       cover.topic ＝ f"{event} {round}"
                             topbar.line1 ＝ f"{year} {event} {round}"
    promote_interview_draft  cover.sub   ＝ f"{event} {round} 赛后场上采访"

而 reel 侧那道闸对**新 slug** 没有豁免、interview 侧**整个零豁免**。所以翻面
之后不转换的话，**自动链产的每一条草稿都会被拦下 → 转不了正 → 链子静静停住**，
而「草稿转不了正」和「今天没有候选」在报表上长得一模一样。

修法是 `tools/spec_wording.py` 的 `round_display()`（**闸的建设性那一半**，
和判据同一个出处）：**当前**是 四分之一决赛/8强/八强→`1/4决赛`、
半决赛/4强/四强→`半决赛`、十六强/16强赛/16强→`1/8决赛`，认不出的**原样透
出去**（资格赛、第几轮、英文原文都从这条走——别在转换器里猜写法，让闸去拦）。

⚠️ **只转换出口，不改内部的键。** 「半决赛」在 `KEY_ROUNDS`、`oncourt_feed`
的排序表、`oncourt_match_coverage` 的签表、`render/rating` 的 `LEAD_ROUND_PTS`
里是当**标识符**用的——跟着改是拿一条文案规矩去动一批不相干的判据，而那种
改动坏起来不吭声。`draft_interview_spec` 那张 `rnd_slug` 表（半决赛→`sf`）
同理不动：它拼的是**文件名**，不是给人看的字。

判据 `test_自动链写进封面的轮次要先过对外写法那张表` 钉三头，缺一头都是恒真：
**两套内部名的产出转完都过得了闸**（拿 `round_zh` / `parse_round` 真跑一遍，
不手抄一张名单）、**两个出口真的调了它**（AST 找 `round_display` 的调用——
只钉转换表的话，出口忘了调照样绿，「一个数写两处必分叉」的老账）、
**认不出的原样透出去**。两头分别反向验证过，红在不同的断言行。

#### ⭐⭐ 走到哪儿的阶梯，最后一格是**亚军**——不是「打进决赛」

账号所有者 2026-09-01，紧接着上面那条：「**决赛如果没有得冠军，就是亚军呗。**」

上面那张表管的是**这场球是哪一轮**（轮次名）；这一句补的是**一个人走到哪儿**
（名次），两件事差着一层。合起来是一条阶梯：

    冠军 → **亚军** → 半决赛 → 1/4决赛 → 1/8决赛 → 第一轮 / 第二轮 / 第三轮

⚠️ 阶梯中间那三格的写法**跟着上一节走**（2026-09-08 翻回分数式），
「亚军」这一格三次翻面都没动。

⚠️ **「决赛」是场次名，不是名次名。** 说「他打进决赛」把结果含糊掉了——赢没赢
读的人不知道；而中文本来就有那个词。**没夺冠就是亚军**，别绕。

⚠️ **这一条没有做成硬闸，是故意的。** 「打进决赛」本身不是错的：赛前说、
说「打进过三次决赛」（输赢混着）都对，**只有已知输了的那一次**该写亚军——
而「已知输了」在背景叙述里没有结构化数据，机器分不出来。硬凑一个正则会在
前两种合法用法上误报，而**一个天天误报的闸会把人训练成不看它**。

#### ⚠️⚠️ 而查这一句的时候，抖出**上面那个洞的另一半，我漏了**

上一轮修了闸、扫描面、两条机械拼串的路——**独独漏了「模型自己写的字」这条路，
而那才是旁白和文案的主要产出口**。当时的实况量出来是：

| 喂给模型的东西 | 教了什么轮次叫法 |
|---|---|
| `skills/tennis-reel-production/**` | **一个字都没教** |
| `draft_spec.py` 的 SYSTEM prompt | 只有断句那条的例句：「打进**半决赛**」 |

也就是说模型**没有任何地方学得到新叫法**，而 prompt 里唯一的轮次例句用的是
旧写法。它照着产 → `check_spec_wording` 拦下 → 草稿转不了正 → 链子静静卡住，
**而它长得像「今天没有候选」**。和上面那条 ② 是同一个洞的两半。

⚠️ **教材里这条只写正例**（「只能写 决赛/半决赛/1/4决赛/1/8决赛/第N轮」），
**不列反例**——两个理由：列反例会被下面那条判据当场拦下；而且**给模型看的
每一个词它都可能照着产**，把要禁的词印在 prompt 里本身就是在教它。

判据 `test_喂给模型的教材里不许出现会被措辞闸拦下的写法` **自己从闸推**，

### ⭐ 「三个盘点都没救下来」——救的人和拿到点的人不是同一个

#### ⭐⭐ 「三个赛点只兑现了一个」——这个比例锁死在 1/N，不是选手的短板

账号所有者 2026-08-19，看完 `bouzkova-jovic`：「三个赛点只兑现了一个，这种文案
是有问题的，以后杜绝类似的弱智文案」。

这条钉的不是语法——「拿到三个赛点，只兑现了一个」这个句式本身是通的，上一节的
表里明写着「兑现的是自己的点」，主语没有换人。问题在于**这个数字本身没有信息量**。
那条片子的钩子、`push.summary`、开场旁白全用了它：

    "hook": "三个赛点\n只兑现了一个"
    narration: "三个赛点摆在她面前，她只兑现了最后一个。"

**赛点／盘点这类"转换即终止"的点，一旦被数成一段连续序列，赢家永远只能兑现
最后一个——这不是这一场独有的结果，是这类点的定义本身决定的。** 赛点的意思就是
"转换它，比赛立刻结束"；所以序列里排在前面的每一个，按定义必然没有被转换
（要么被对手救下，要么被打丢），不然比赛早就在那儿结束了，不会有后面那些点。
也就是说，"N 个赛点只兑现了 1 个"这句话对**任何**一场靠多个赛点才拿下的比赛
都成立，跟这一场打得多胶着、对手多顽强完全无关——它算不出任何信息，读起来却
像在暗示"她效率低"，实际上什么都没说。

**真正会变化、真正有戏剧性的数字是对手救下了几个**（这条片子里是「约维奇连救
两个」）：这个数从 0 到 N-1 都有可能，0 代表对手一触即溃，N-1 代表对手拼到了
最后一刻——这才是能区分"这场好看不好看"的那个轴。CLAUDE.md 早有的好例子
（`shang-rublev` 钩子「决胜盘二比五落后，五个赛点，一个没给」）用的正是这个
框架：主语是**扛住压力的那一方**，数的是他救下了几个，不是数进攻方兑现了几个。

| 框架 | 主语 | 这个数变不变 | |
|---|---|---|
| "N 个赛点，对手救下 M 个" | 扛住压力的那一方 | **变**（0~N-1，衡量对手多顽强） | ✅ 有信息量 |
| "N 个赛点，只兑现了 1 个" | 进攻方自己 | **不变**（任何 N≥2 的赢球序列恒为 1） | ❌ 读起来像短板，其实是同义反复 |

⚠️ **这条只管"赛点／盘点／这一局的局点"这类转换即终止某个单元（整场比赛／这一盘／
这一局）的点，不管整场比赛里分散、互不相连的转化率。** 破发点不是"转换即终止"——
赢下一个破发点只结束当前那个发球局，不妨碍选手在后面别的发球局里再拿到、再转换
别的破发点。所以"全场六个破发点，兑现两个"横跨好几个不同的发球局，是会变的、
真实的效率数字，`bouzkova-jovic` 的 `.xhs.txt` 正文里那句「破发点兑现（5/9 对
5/8）」就是这一类，没有问题。判据是**这几个点是不是同一个终止单元里的同一串**，
不是看用的是"赛点"还是"破发点"这两个字。

⚠️ **这条没有做成硬闸，是故意的**——和「有吸引力」「钩子要有剧情的跌宕」同一个
理由：判断"这几个点是不是同一串"要理解比赛进程，机械挡不住，硬凑一个关键词
正则会在"全场六个破发点只兑现两个"这种合法用法上误报，而误报比没有更糟。写之前
问一句：**这个"只兑现了 M 个"，换成任何一场打了同样多个这种点才赢下来的比赛，
答案会不会一模一样？** 会——就是同义反复，换成"对手救下了几个"。

⚠️ **`bouzkova-jovic` 不重渲，也不改 spec 里已经烧进封面／旁白的那几处**——
成片的封面文字和配音已经把这句念出去了，改 spec 只会制造"spec 说一套、成片是
另一套"的新分叉。这条规矩管的是以后新写的片子。

### 小红书正文卡在 1000 字，而且要「提炼在前、原话在后」

**这不是编辑口味，是平台的硬限制**——那一格就是 1000 字，超了**粘不进去**。
而它**不吭声**：文案照样渲、复制页照样发、按钮照样在，只有真去粘的人才发现
粘不上。整条推送的出口就这么没了，而消息已经发出去收不回来。

> 「你不要把所有的内容都复制在正文里，你可以**提炼一些关键点**，然后适当做一些

于是正文分两段，顺序不能反：

| 位置 | 放什么 |
|---|---|
| **前** | 提炼过的关键点、总结、给读者的启发——**我们的话** |
| **后** | 最值得抄的那几句**原话**（英文 + 中译），少而精 |

### ⭐ 平台整改后的「赛场之上」：从高光剪辑改成原创比赛复盘

账号在 2026-08-06 收到过「疑似对他人/网络素材简易加工、二次创作信息增量不足」
的处理结果。平台提示是这次整改的**风险信号**，不是一条可以证明算法因果或保证
流量恢复的官方定律；项目采取的改法是把「我们为什么这样剪、这场球为什么这样变」
真正放进视频，而不是只在小红书正文里写几句解释。

整改期新做的「赛场之上」必须先认领一份编辑合同：

```json
"editorial": {
  "mode": "match_review",
  "question": "这场球最值得复盘的问题？",
  "thesis": "一句可被比赛画面和资料支持的中心判断。",
  "beats": ["前段走势", "中段转折", "结局与回应"],
  "human_context": {
    "angle": "这一场独有的场外切口，不套固定模板。",
    "facts": ["一到两条能核验的新闻、人物或现场事实。"],
    "sources": ["官方新闻、赛报、采访或赛事页链接"],
    "voice_label": "可选的口语化概括，不冒充官方称号。"
  }
}
```

- `question` 不是标题换一种写法，而是整条片子要回答的一个比赛问题；`thesis`
  不是「很精彩」这种空评价，要说清谁改变了什么、对手怎样应对、最后怎样回应。
- `beats` 至少三个，按「先发生什么 → 哪里换手 → 怎么收」排列。它们是选段和旁白
  的骨架，不是把每一局比分逐局念一遍。
- 每条片子还要做一次**本场专属的场外/人物/新闻补充**：从主场压力、家乡球迷、
  里程碑、复出、宿敌、票房、赛程背景、采访金句、球员个性等方向找一两个真正和
  这场比赛有关的切口。不同选手、不同比赛必须换角度，禁止把“菲律宾球迷”“门票售罄”
  之类的例子复制成固定模板；没有可靠热点就不硬塞，宁可写有来源的人物或赛事细节。
- `human_context.facts` 必须有来源，优先官方赛事新闻、WTA/ATP 赛报、赛后采访和赛事页；
  `voice_label` 只是本号的口语化表达（例如“带票女王”），不能写成选手的官方头衔。
  场外事实进入旁白时要像人在讲现场见闻，不能变成新闻摘要或数据清单；最好用对应的
  看台、球员表情、入场、庆祝等画面承接。
- 开头默认先给一个**人会想听下去的场景、反差或问题**，不要用“北京时间＋赛事＋比分”
  作为机器式开场；时间、赛事和轮次由顶栏持续交代，旁白负责把观众带进这场球。
- 每个战术或心理判断都要能回到记分条、官方赛报、统计或按帧画面；「她故意这样发」
  这类意图没有证据时只能写成谨慎的观察，不能把猜测当事实。
- 画面负责证明动作、人物和比分；旁白负责解释变化、意义和回应。禁止用「画面里是」
  之类话术复读观众已经看见的内容，也禁止只把比分换成中文再读一遍。
- 默认保留现场球声和观众声，**不加背景音乐**；旁白是叙事主线。用户提供真人录音
  时优先用真人录音；没有真人音频时，现有语音合成只能作为待审核版本，不能把“有配音”
  本身宣称成已经完成原创。

####### ⭐ 收干净之后还剩 0.27 秒，而它是**采样分辨率**不是判据

亮度那条补上之后再渲一版，全片扫下来只剩一处：第 13 段板淡出的尾巴，

**根子是格子太粗**：在场扫描 2 fps、区间两头各往外放半格 → 边界误差 ±0.25 秒。
而这不是判据的问题——判据在那一刻是对的，它只是**上一格才采到**。

⚠️ **想加密采样，会撞上同一条时间线的另一半**：右缘是投票选出来的
（`segment_board_edge` 要「两票起步」才算可信），**票多了会改变可信度的分档**
——本来只有孤票的段，三倍采样之后轻易凑够两票，于是从「按后面段的下确界补」
变成「按自己那一票」，而那一票往往正是球员贴着板时读出来的噪声。

**所以拆开**：`BOARD_SCAN_FPS = 6` 管在场（误差 ±0.083 秒），
`BOARD_EDGE_EVERY = 3` 让右缘投票每隔 3 格取一个——取到的时刻和原来 2 fps
**逐个相同**（`fps=6` 出 0、1/6、2/6…，隔 3 个就是 0、0.5、1.0…）。
一趟解码，代价只有管子里多两倍的字节。

⚠️⚠️ **加密的同时必须把两个容差从「几格」改成「秒」**（`BOARD_GAP_BRIDGE = 0.8`
／`BOARD_FULL_TOL = 0.5`）：原来写的是 `step * 1.6`，加密之后它从 0.8 秒收到

`BOARD_SPAN_MIN` 各自丢掉，**结果是加密采样反而少贴**。判据第 ④ 头钉这一条，
反向验证过（换回 `step*1.6` 当场红）。

⚠️⚠️ **而给这次改动写的第一条判据是恒真的，反向验证才抓到。** 它要钉的是
「隔格取的是每组**中间**那一格」（时间轴记的是格心 `(k+0.5)/fps`，取第 0 格会

    picked = [t for k, t in enumerate(stamps(FPS)) if k % EVERY == EVERY // 2]

⚠️ 这是「查源码文本的断言只能防有人把它删了，防不住它从来没工作过」的
**更隐蔽的一种**：那一类至少还看着源码，这一类连源码都不看，拿常量自己

######## ⚠️⚠️ 验收这一类要量**贴片矩形的下沿**，别量右缘——右缘会认错成板自己的边

加密之后重渲，我写的验收脚本报「全片 0.00 秒」，**而打开图看，第 13 段那一帧的
鞋还是切成两截的**。脚本量的是「板明确在的帧里最强的那一列」，取到的是 **x=446
——板自己的右边框**；而贴片矩形的右缘在 **x≈489**。板不在的时候板缘自然消失，
于是那一列读数很低，脚本就报「没在贴」。**一个量错了列的判据，和一个真绿的判据
长得一模一样。**

**下沿那道横缝才是「这一刻在不在贴」最干净的探针**（`y = oy + sh`，量它和上一行
的差）：贴片和底下的画面横向差 **221px**（源片 249px × 0.8896），所以下沿必然
断开，而**竖直方向本来就是连续的**（贴片和居中窗口用同一个纵向映射），所以
不贴时那道差就落到底噪。实测很干净：

    在贴（板在）    46 ~ 55        在贴（贴的是球场）  也明显高
    不贴            0.5（第 12 段修好之后）／2.0~3.4（第 13 段 115.6s）

⚠️ **右缘那条不是没用，是要取「最右那道常在的边」而不是最强的那一道**——板缘
比贴片缘强得多（74 vs 20），`argmax` 必然取到板缘。而即便取对了列，一条球场白线
正好横穿它就会给出假阳性（115.62 那 0.12 秒就是这么来的，下沿一量就否掉了）。

**所以这一类的判据是一对**：下沿横缝定「在不在贴」，右缘那一列只用来定位矩形有多宽。

⚠️ 顺带修掉一处 **docstring 和实现打架**：`board_present_spans` 的说明写着
「往窄里收，不往宽里放……宁可少贴」，而代码一直是**两头各往外放半格**。
现在按代码写并说清为什么——多贴和少贴都是可见的坏（一边是接缝把人切成两截，

视觉样式带回来**，学的只是**内容组织方式**（上面那张对照表）和**剪辑节奏**。

⚠️ 剪辑节奏这条，量出来的结果和"快剪快切"的第一印象**正好相反**。拿
`ffmpeg select='gt(scene,0.35)'` 对「林林林妹668」那条 233 秒的片子做真实的
镜头切点检测（这是仓库里 `scene_cuts` 本来就在用的同一套阈值），**全片只有
4 个真实镜头切点**，切出来的五段分别是 5.3s / 58.2s / 33.0s / 63.2s / 73.3s
——**没有一段短于 5 秒，中段甚至长达一分钟**。而联系表上看着"每格都有新字幕"
的密集感，来自**同一段连续转播画面上滚动叠加的多句短字幕**，不是频繁切镜头。

**结论是：别学"剪得快"，那不是真的——该学的是"一段长镜头上能压几层信息"。**
我们自己的分段（`build_match_reel.py` 的 `segments`）目前一段配一句旁白；
这条参考提示的方向是**同一段画面窗口内，字幕可以比旁白语速更密、分多句
先后叠现**（类似他们「首盘伊埃拉迅速进入状态」→「以6:3顺利拿下」这种
前后两句压在同一镜头上），而不是逼着去多切镜头。这条目前没有落成判据——
是不是要在同一分段里叠加多句短字幕，属于编辑判断，先记下来，下次写 spec

#### 第三个账号：这次是真快剪，而且"证据"不止真实赛场画面

2026-08-11，账号所有者甩来「2发网球」讲加拿大公开赛（为什么分属多伦多和
蒙特利尔两座城市）的抖音链接，要求同样是「你看看别人怎么做网球有故事的」。
这条和上面「林林林妹668」正好是**反例**——那条量出来只有 4 个真实切点、
密集感全来自叠字幕；这条**真的是快剪**：`scene_cuts` 阈值 0.35 量出来
**135 个切点／288 秒 ≈ 每 2.1 秒一切**。上一条的结论（「别学剪得快，学
一镜压几层信息」）不能当成放之四海皆准的判据——**剪辑节奏是不是真快，
每条都要量，不能因为学过一次「原来是叠字幕」就默认下一条也是**。

这条片子和我们同一天刚发的 `cincinnati-story` 是**同一个体裁**——都是
"赛事本身的故事"（不是球员个人故事线），直接可比。它比我们多用了三类
"证据"，而这三类我们的 `cincinnati-story` 一个都没有（`cincinnati-story`
全片只有源片集锦画面 + 旁白，没有任何一屏是"另一张图"）：

| 证据类型 | 这条片子怎么用的 | 我们现在有没有 |
|---|---|---|
| **历史实物照片当论据** | 讲"长期依靠烟草资本扩张"时，画面直接切一张 Rothmans 香烟包装的实拍照片（配 `2003` 年份角标）——这不是网球画面，是佐证这句话的原始材料 | 没有。`_facts` 里核过的事实全部只靠旁白口述 |
| **官网截图 + 高亮标注** | 讲场地便宜时，截一张官方购票页原图，把关键数字（"室外硬地1小时约合人民币50元"）用黄色描边圈出来，旁白同时点出"超过6万小时的低价场地" | 没有。我们有同类的数字（`_facts` 里的费德勒七冠、鏖战3小时49分钟），但从没在画面上"亮出信源截图" |
| **新闻引语配来源署名** | 一段引语配着屏幕角落的 `Voice of Maite Ormaechea / CBC News`，把"这话是记者说的"这件事本身摆在画面上 | 没有。我们引用 WTA/CNN 的事实只写进 `_claims`，不上画面 |

**这三类都不是"编出来的"——都是可核实的原始材料**，和 CLAUDE.md 别处「图片
必须打开看过、四道闸门」那套要求完全兼容，只是**它们不是网球画面**。
我们的选题库（`_facts`/`_claims`）已经在按同一套证据标准核实事实，只是
产出的时候全部压缩成了旁白一句话，没有把"证据本身"也做成一屏。

第四处技术：**片头那句标题从头到尾常驻画面**（「加拿大公开赛 / 为什么分属
两座城市？」在 288 秒里没有消失过），和我们"封面钩子只停 ~~1.8~~ **1.2** 秒、之后
画面上就没有标题"的做法是两条路。这条**不建议照抄**——常驻标题会一直
占掉画面上方一块，而我们的字幕本来就要求"留够安全边距"；两者叠在一起
挤占空间会更紧。记在这儿是给"要不要试"留一个真实参照，不是建议照做。

⚠️ **同样"不许学"的部分**：这条账号的字幕仍然是通栏白底黑字、贴底，
和上面「边界」那条一样，**只学证据类型和剪辑节奏，不学字幕位置和配色**。

#### 第四个账号：同一场球，别人怎么写「赛场之上」——三条能直接搬，两条不学

2026-08-24，账号所有者甩来「网球青春」（抖音号 tennislife1314）讲高芙胜佩古拉

**这条和我们同一天发的 `gauff-pegula-cincinnati-2026-final` 是同一场球**——
前三条参考都是不同赛事/不同体裁，这条第一次能逐句对着同一场比赛比。

**三条能直接搬进已有的写法里：**

- **收尾把不同维度的成就数字连着堆，不只用一个。** 收尾五连击是
  「第37次击败世界前十」→「第四次斩获1000赛冠军」→「19岁到22岁」——
  三个**互不重复维度**的数字（对手实力、赛事级别、生涯跨度）叠在一起，
  才有"这不是一次孤立的赢球"的分量。CLAUDE.md 早有「排名只当收尾的重量，
  不当全部内容」（`shang-rublev` 那条），这条只是把它从"一个数"扩成
  "几个不同维度的数一起堆"——落笔前多问一句：除了这场比赛本身的数据，
  还有没有第二个、第三个维度的成就数字可以在收尾一起摆出来
- **两个年龄/年份做书挡，收束生涯弧光。** 「从19岁一鸣惊人，到22岁再次
  加冕」——两个具体的年龄卡在收尾，读者一秒钟接住"她从新星走到今天"这条线，
  比一句"她成长了"具体得多。核实过：高芙2023年19岁时拿下当年美网冠军，
  今年（辛辛那提这一冠）22岁，两个年龄都是真的。以后收尾想要"她一路走来"
  这种意味时，优先找**两个具体年龄或年份**做锚点，不写"多年来""一路成长"
  这种没有数字的空话
- **转折前先给一句技术性归因，再进比赛细节。** 「经历了整个赛季的相对
  低潮后／大幅减少双误次数的／高芙终于找回了自己」——先摆"这个赛季不顺"
  的背景，紧接着一句**具体的技术指标**（双误减少）解释"为什么这一站行了"，
  再进首盘逐局。这正是「旁白要有技战术拆解」那条要的东西：不止说"她反弹了"，
  要说清"靠什么反弹的"。核实过：高芙近两年双误确实是她被反复讨论的弱项，
  这条片子把"季初低潮"接到"双误减少"这个具体技术点上，是可核可用的归因，
  不是空泛的"状态回暖"

**顺带核实了一处会被当成"编的"的事实，结果是真的**：「面对曾经的双打搭档
佩古拉」——高芙和佩古拉 2022 年圣地亚哥站、2023 年迈阿密站搭档拿过双打
冠军，也一起打进过 WTA 年终总决赛双打正赛，是真的former doubles partners。
**这条本身提示一个可以用的写法**：把"曾经的搭档""曾经的对手"这类关系背景
直接编进旁白（不是只写进 `editorial.human_context` 自己看），但**这条视频里
的任何一句具体事实，照旧要按「查得够深、查得够广、两个源对得上」那条自己
核一遍再用**，不能因为别人发过就直接引。

**两条不学，和已经定过的规矩正面冲突：**

| 这条参考视频怎么做 | 为什么不学 |
|---|---|
| 封面纯事实堆叠（年龄＋比分＋对手），零悬念 | 「钩子要有剧情的跌宕」那节账号所有者原话点过同一种毛病——「只靠排名，这个太机械化、固定化了，没有把剧情的跌宕说出来呀」。封面仍然按「过程+落点」写，不按"结果先说" |
| 收尾是陈述句抒情（"也捧起了无限可能的明天"），没有问号 | 「末屏那个问题，旁白必须问出来」是账号所有者亲口定的硬规矩，为的是换评论区互动。末屏仍然要留一问，不能换成纯抒情收尾 |

⚠️ **字幕位置和配色同样不学**（通栏白底、贴底、无双语）——和前两条账号一样，
这条只学文案结构和归因写法。

#### ⭐⭐ 第六个账号：同一场球的标题——**小红书首行是标题，不是正文的开头**

账号所有者 2026-09-02 甩来「Tennis 网球记」讲伊埃拉美网首轮那条（36 秒），

同时**为什么他会有这么多的评论**，你也看」。**和我们同一天发的
`eala-stoiana-us-open-2026-r1` 是同一场球**，可以逐行对着比。

两个标题并排：

| | 那一行 |
|---|---|
| 他们 | 🔥**伊埃拉**78 分钟横扫对手强势跻身**美网第二轮** |
| 我们 | 六个破发点，**她**一个没给 |

##### ⚠️ 而这不是「钩子写坏了」，是**一条规矩被搬到了它前提不成立的地方**

「钩子里不写身份」是本文件明写的规矩，理由也写着：「身份（排名、年龄、国籍）
**海报别处已经印着了**，钩子再写一遍是白占那 27 个字」。我们那句标题正是照
这条写的——**而它依赖的前提在信息流里不成立**。量出来的：

    solo 封面中文名  SCORE_CN_MAX_PX = 52px   画布 1080 宽
    小红书双列瀑布流的缩略图约 170px 宽  →  名字缩到 **8.2px**，钩子 14.8px

**滑到这一屏的人看得见钩子，看不见名字。** 这就是本文件反复记的
「抄了规则，没抄它依赖的前提」——只不过这次抄的是我们自己家的规矩。

⚠️ **首行的身份不是「正文的开头」，是标题**：`push_reel.split_copy()` 把它单独
切出来，小红书信息流里它是缩略图底下那一行字，微信推送里它是单独成块、可长按
复制的那一句。**这条片子在信息流里唯一被读到的一行文字。**

**现在有闸了**（`spec_wording.CAPTION_LEAD_LEGACY`，坐在 `check_spec_wording`
那个 seat 上，所以 `--dry-run` 0.2 秒就报，自动链转正那一刻也过同一道）：
首行必须出现一位球员的名字（整名或**头两个字**的简称——「德约」「中岛」靠它
放行）。存量 177 条赛场之上里 **102 条本来就是这个形状**，剩下 80 个 slug 挂
豁免表，只许减不许加、表自带自检。

⚠️ **判据只机械地管一样：有没有点出是谁。** 「哪一站」「什么结果」故意没有
判据——写法太多，好坏机器分不出来，硬凑一个会被绕过的判据比没有更糟。
那半条靠写的时候自己读一遍：**这一行，一个不认识这两个人的人扫过去，
知道该不该点吗？**

⚠️ **不是「把钩子换成名字」**：钩子留在后半句就行。存量里做对的那 102 条
大多是「谁 + 干了什么」的形状（「德约第一次倒在大满贯首轮」「世界第九十二，
掀翻赛会头号种子」）。

##### ⚠️ 「为什么他评论多」——量完之后答案不是文案，是触达

他那条 36 秒、账号 3386 粉；我们那条 141 秒。**而互动率是可比的**——
他的评论/点赞比 37.6%，我们已发片子在 42% 上下。也就是说**换来评论的那套
东西我们本来就有**（末屏一问、有立场的解说），差的是**有多少人刷到**。

⚠️ **所以别照着「他评论多」去改评论区机制。** 顺手量过一遍我们自己的语料：
**62%（110/177）的小红书正文本来就以一问收尾**，标题本身是问句的只有 4 条，
两头都是问句的只有 1 条、字集重合度 0.07（没有「末屏那一问是封面那一问的
回声」这个毛病）。**这条本来想写成规矩，是数据把它否掉的**——我们已经在做了。

⚠️ 顺带纠正我自己在这一轮里的一个假设：我先以为「文案首行照抄封面钩子」是
系统性的，扫完 177 条发现**只有 6 条（3%）**。**先量再下结论**，那次量出来
的真缺口正是上面那一条（首行不点人）。

##### ⚠️ 抖音那条取数路子变了：`?from_ssr=1` 已经死了

本文件早先记的那条（`iesdouyin.com/share/video/<id>/?from_ssr=1` + 浏览器 UA）
**今天 302 跳到 `douyin.com/video/<id>`**，回来 72914 字节里「伊埃拉」出现
**0 次**——是个空壳。⚠️ 而 302 之后仍然是 **HTTP 200**，只看状态码分不出来。

能用的两条（2026-09-02 实测，都带真 aweme_id 验过）：

    正文/标题  curl -L -A 'Mozilla/5.0 (compatible; Bytespider; spider-feedback@bytedance.com)' \
                 'https://www.iesdouyin.com/share/video/<aweme_id>/'
               → 85 KB，两块 ld+json（name / description / uploadDate）
                 ＋ <meta name="keywords"> 里就有话题词
    评论       https://www.iesdouyin.com/web/api/v2/comment/list/?aweme_id=<id>&cursor=0&count=20
               → StatusCode 0，每条带 **reply_comment_total**（哪几条被追着聊，一眼可见）

⚠️ **`<script type="application/ld+json">` 这个正则抓不到它**：真页面写的是
`<script data-rh="true" type="application/ld+json" ...>`，多几个属性就匹配不上，
**而匹配不上的样子和「这页没有结构化数据」一模一样**——我这一轮就是这么先报了
「ld+json 0 块」，回头一看那 22 处「伊埃拉」明明就在页面里。要写
`<script[^>]*application/ld\+json[^>]*>`。同一个形状本文件在 Gannett 那条记过
（属性不带引号打空了正则）。

⚠️ **aweme_id 别从分享短链猜**：`v.douyin.com/<code>` 要跟到底才拿得到，
我这一轮凭记忆写了一个 id，一路 404——**而 404 和「这条视频没了」长得一样**。
从落地页的 `/share/video/<数字>` 里取。
