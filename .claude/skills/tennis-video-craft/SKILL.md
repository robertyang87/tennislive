# tennis-video-craft

> 从 `CLAUDE.md` 原样搬来，一个字没改。**规矩本身仍在 CLAUDE.md**，这里是撞上问题时才查的档案。

### ⚠️ 加口播时抖出四个 bug，三个被退路吞了真因

| | 表现 | 真因 |
|---|---|---|
| ① | 「口播合不出来」 | `ExplainerSegment` 前三个字段是必填的，只传 `narration=` 报 TypeError |
| ② | 同上 | **`build_interview_clip` 从来没挂过 `localca`** |
| ③ | **整条崩** | `_audio_seconds(path, ffprobe_bin, runner)` 要显式给后两个参数，而它排在 `try` 外面 |
| ④ | `KeyError: 'open'` | 引文闸写死了字段名 |

②值得单记：这条线在解读卡之前**一个字都不合语音**（片尾走的是母版转码，
不跑 TTS），所以从来没挂过代理 CA。加口播时它是「同时要改的第三处」——
而它报出来的样子是 `CERTIFICATE_VERIFY_FAILED`，被退路吞成一句
「口播合不出来」，**看起来像 edge-tts 挂了**。

①②能查出真因，全靠那句「合不出来就退回静音卡，**但两条路都要出声**」——
日志里写着原话。③没被吞，所以立刻现形。**退路要出声，这就是它买来的东西。**

#### ⚠️ 第五个，一周后才现形：runner 上根本没装 `edge-tts`

②修的是**沙箱**那一头（证书链）。**runner 那一头一直是坏的**，而它安安静静地
出了一条片子：`interview-clip.yml` 的装依赖那行写着

    pip install -q -e ".[visualqa]" "yt-dlp[default]" playwright faster-whisper

——**没有 edge-tts**。同一个「加新能力就要同时改三处」，②漏的是本地那处，
这个漏的是工作流那处，而它们是同一个提交该做的事。

**它绿着交付了一条不合格的片子**（run 31151599208，萨巴伦卡那条）：

    [解读卡] close 口播合不出来，退回静音卡：缺少 edge-tts，请安装后再生成解说视频
    [解读卡] close 5.64s（按字数估）

run 是 success，成片时长对、体积对、`验成片` 那一步过了、提交推送一切正常——
**只有量音量才看得见那 5.6 秒是 −91 dB**，也就是数字静音，而账号所有者对这张卡
的原话就是「**但要有配音**」。CLAUDE.md 里那条「两张静音卡那一版前 10.8 秒
峰值 −91 dB」说的正是这个东西，只是这次它绕过了所有的闸。

三处一起改，缺一处这个坑还会再来：

- **装上**（`pip install … edge-tts`）
- **预检里 `import edge_tts`**——让它死在第 5 秒。⚠️ 原来的预检 import 了
  playwright / faster_whisper / cv2 / 字体，**唯独没有它**，所以第 5 秒那道闸
  对这个依赖是哑的
- **判据 `test_会合语音的工作流都要装edge_tts`**，和「工具入口都要挂本地 CA」
  那条是同一个 bug 的两半：那条管沙箱的证书，这条管 runner 的依赖

⚠️ **判据不许递归。** 第一版顺着 import 往下扒，当场把 `frame-grab.yml`（抽帧）
和 `auto-push-explainer.yml`（只推送）也判成「要装」——它们导入的模块里有 TTS，
可它们自己那条路走不到。**扩大化的判据会让下一个人白装一个包，或者干脆把这条
检查删掉。** 收成「这个工具自己提没提 `synthesize_narration`」，和上一条同一个口径。

⚠️ **更该记的是怎么发现的**：不是靠读日志，是**渲完之后逐段量了一遍音量**
（封面 / 原声 / 解读卡 / 片尾各一次）。日志那两行当时就在，可它排在几百行
ffmpeg 进度中间，而 run 是绿的——**没有人会去读一条绿 run 的日志**。
所以「片子做完要抽帧看」这条得加一句：**也要量音量**，尤其是没有现场声的那几段。

#### ⭐ 而「抽帧看」现在**在本地就能做**：成片从 Release 拉得回来

上面那条和本文件里另外几处都在喊「渲完要打开看」，可我一直把它当成一件贵事——
成片只在 runner 上、沙箱下不动 YouTube，于是「看一眼」被默认成「再跑一趟 run」。
2026-08-15 试了一下，**这个前提是错的**：

    curl -sL -o /tmp/x.mp4 \
      "https://github.com/<owner>/<repo>/releases/download/interview-<slug>/<slug>.mp4"
    → 200，31,525,433 字节，ffprobe 读得动

**被挡的是 YouTube，不是 GitHub。** 而 2026-08-13 起成片一律走 Release
（见「100 MiB 是 git 的限制」那节），所以**每一条已发的成片都是本地可取的**——
`render.json` 的 `video_url` 就是那个地址，不用去猜。

##### ⚠️ 拉回来的那份**不许落在 `output/` 里**——下一次 `git add -A` 会把它吃进去

2026-08-17 差 30 秒就把一个 **41.8 MB 的 mp4 提交进了历史**。经过很平淡，
所以更值得记：`check_reel_landed.py` 按产物目录找成片，我图省事就把 Release 那份
`curl -o output/<date>/reel/<slug>/<slug>.mp4` 下到了它要找的位置；验完 0 项不合格，
顺手 `git add -A && git commit` 提交笔记——**mp4 一起进去了**。
`git show --stat` 第一行才看见。

⚠️ **三道该拦的闸一道都没响，而且每一道都「没做错」：**

| | 为什么没响 |
|---|---|
| `test_成片一律走Release不进git` | 它查的是 `git ls-files`，而那一刻文件还**没被跟踪** |
| 全量测试 | 跑在 `git add` **之前**（文件在盘上了，但那条判据看的不是盘） |
| 工作流的「丢掉不进仓库的中间物」 | 那是 **runner 上**的清理，管不到我在沙箱里下的这一份 |

也就是说**「一个躺在被跟踪目录里的未跟踪大文件」是个盲区**：它离进历史只差一个
`git add -A`，而这个仓库的提交习惯就是 `git add -A`。

- **下到 `output/` 外面**（scratchpad），要么**验完立刻 `mv` 走**
- **`git commit` 之后先看一眼 `git show --stat`**。它比「提交成功了」多花一秒，
  而这一秒挡的是一次改写历史——2026-08-13 那次清理花了 17 GB → 789 MB，
  代价是所有 commit SHA 都变了、已发消息里的图片链接可能失效
- 这跟「查产物，不查信号」是一家的：**`git commit` 返回 0 是信号，
  `git show --stat` 列出来的那几行才是产物**

拿回来之后能做的事，都是几秒钟的：

| 想知道 | 怎么量 |
|---|---|
| 封面停了多久 | 逐帧算 `meandiff`，连续为 0 的那一段就是封面（实测 45 帧 ＝ 1.8s，和 `COVER_SECONDS` 对得上） |
| **源片时刻 ↔ 成片时刻** | `源片 = 成片 − 封面长度`。有了它，成片上量到的任何一帧都能换算回 spec 的 `start`/`end` |
| 末尾混进了什么 | 每帧整幅均值，片尾板/台标卡是一帧跳上去（这次 31→71） |
| 字幕压在哪儿、对不对得上 | 拼一面带时间码的缩略图墙 |

##### ⭐ 核成片最便宜的一招：**按段抽一格拼成接触表**，一张图核三件事

2026-09-04 两条带式片子各用一次，13 格一张图、几秒钟，同时核掉了三件事：
**这一格的记分板和这一段的字幕对不对得上**、**写 `score_inset: false` 的段
是不是真的没回贴**、**字幕断行有没有把话切碎**。比逐帧扫便宜一个量级；而且它查的是
**成片**，不是 probe 的 `score_*.jpg`（那是源片）——查产物不查信号。

⚠️⚠️ **算段在成片里的偏移要三项，别拿「片长 − 段合计」当封面长度**：

    段 k 的起点 = cover_seconds ＋ 前面各段长度累加
    片长        = cover_seconds ＋ 段合计 ＋ **outro_seconds**

我第一次就是拿 `162.06 − 157.0 = 5.06` 当封面长度，而真值是
**`cover_seconds 1.2`**（这条没有封面配音，走的是那个常量）——差的 3.86 秒
正是**品牌片尾**。于是每一格都晚了 3.86 秒，「段 9」那一格抽到的是段 10 的画面，
字幕写着下一段的第一句。

⚠️ **它不报错，而且骗得过一眼**：大多数格子仍落在相邻段里、内容读起来也通，
所以看着像「这一段话画对不上」而不是「我抽错了帧」。三个数都躺在 `render.json` 里
（`cover_seconds` / `segments_seconds` / `outro_seconds` / `film_seconds`），
**读它，别减**——又一次「查产物，不查信号」，只不过这次的产物是那份 json。


⭐ **第二个用处：挑封面那一帧不用再猜。** 缩略图墙是 **4.95 秒一格**，照它挑
`cover.frame_at` 本质上是猜——德约那条发布会就栽了：420.8 那一格他坐直、侧头、
脸清楚，渲出来的 421.0 **他低着头、脸在阴影里、眼睛看不见**，0.2 秒之内换了个人。
**「看过缩略图」和「看过那一帧」是两件事，而它们写在 `_why` 里长得一模一样。**
成片一出来就不用猜了：拉回本地按 0.5 秒抽一遍，`源片时刻 = 成片时刻 − 封面长度
＋ 窗口起点`，24 格摆一起挑（那次挑中的是 424.5，坐直、四分之三侧脸、眼睛读得出）。
⚠️ **改封面要重渲整条片子**——成片开头那 1.8 秒就是海报本身，只跑 `mode=cover`
换出来的海报和成片里那一屏会对不上。

⚠️ **这条最直接的用处是「片尾板到底在不在窗口里」**。德约那条 spec 的
`_window_why` 白纸黑字写着「末尾那几秒是 Tennis TV 的片尾板，不收」——**而它就在
窗口里面**，第一版成片最后 1.7 秒放的就是那块板。那句话是**照着源片总长推的**，
不是量的；而它一旦写进 spec，读的人就会当判据用。**又一次「查产物，不查信号」，
只不过这次的产物已经躺在 Release 上，取回来只要几秒。**

##### ⭐ 而「离源片末尾还有 N 秒」**不是**对片尾板的余量——它正好就是片尾板

德约那次的教训我第二天就换了个形状又踩了一遍。诺斯科娃那条（WTA 官方集锦
443 秒）我把窗口收在 **434.0**，`_window_why` 写着「离源片末尾还有 9 秒，
片尾板必然落在那之后，**顺带结构性地躲开**」。渲完拉回来逐帧看——

    源片 432.66   她还在挥手致意（最后一帧真内容）
    源片 432.78   **黑场一帧**
    源片 432.90   **WTA 绿标甩入**（整幅均值 6.6 → 94 → 107，一帧跳上去）
    源片 434.0    绿标定版，一直到源片结束

也就是说那 9 秒的「余量」里，**有 8 秒是片尾板本身**。

**根子是一个很容易漏的前提：末尾那几秒没有字幕事件，不等于那几秒还是内容。**
字幕流在说话结束时就断了，而片尾板**本来就不产生字幕**——所以拿「最后一条字幕
离源片末尾多远」当余量，量的恰恰是片尾板有多长。⚠️ 这跟「空结果 ≠ 不存在」是
一家的：**那一段没有字幕，正说明那一段可能不是人在说话。**

**判据只有一个，而且很便宜：渲完把成片从 Release 拉回来，在窗口末尾前后逐帧
量整幅均值。** 片尾板是一帧跳上去的（这次 6.6 → 94），跟人物画面差一个量级，
扫一遍就看见。**别再用「离末尾还有多少秒」去推。**

###### ⭐⭐ 同一天第三次，而这次翻车的是**我用来否掉正确答案的那个数**

蒂兰特那条（Tennis TV，363 秒）我手上已经有一条现成的推算：

    德约那条 Tennis TV      115 − 104.76 = **10.24 秒**
    诺斯科娃那条 WTA        443 − 432.66 = **10.34 秒**
    照它推这条              363 − 10.3   ≈ **352.8 秒**

**我把它否了**，理由写在 `_window_why` 里：「那会切进他最后一句话」——因为最后一条
字幕事件写着 `tStartMs 352.16 + dDurationMs 3.32 = 355.48`。于是 `end` 写成 355.5，
渲出来**末尾多了 2.9 秒 Tennis TV 片尾板**，正是账号所有者点名要去掉的那个东西。

真去量：

    源片 352.58        均值 88.2，他还在画面里
    源片 352.62        均值 **12.3**，一帧掉下去 —— 片尾板甩入
    音频 352.40–352.60  mean −27.6 / max −12.5 dB，人声还在
    音频 352.60–352.90  mean **−91.0** dB，**数字静音**

363 − 352.62 = **10.38 秒**——**那条推算一直是对的**。

⚠️ **`dDurationMs` 是「这一行在屏幕上挂多久」，不是「他说到第几秒」。**
自动字幕会把最后一行挂到画面结束，所以拿它当语音边界**会系统性地偏长**，
而偏长的方向正好是「把片尾板收进来」那一头。要语音边界就量音频
（`volumedetect` 分窗，数字静音是 −91 dB），几秒钟的事。

⚠️ **更该记的是这次的形状**：我不是没有正确答案，**我有，而且把它算出来了**，
然后拿一个自己没核过的数把它否掉。这跟本文件里「排除了 A 和 B 不等于就是 C」
是一家的，只是这次多了一层——**否决也要有判据**，而「字幕事件写着 355.48」
是一个信号，不是产物。

###### ⚠️⚠️ 而量的时候 `-vf fps=25` 会差一帧——收到 352.6 之后成片里还留着一帧黑闪

同一条片子第二次返工，这次错的是**量法本身**。我一直这么抽帧：

    ffmpeg -ss <T0> -t <N> -i film.mp4 -vf fps=25 out/f_%03d.jpg
    # 然后按 T0 + n×0.04 给每一格标时刻

**`fps=25` 是重采样滤镜，它把帧摊到自己的网格上**，而那个网格的相位由 `-ss` 决定——
换个 `-ss` 起点，同一帧标出来的时刻就变了。同一帧我两次分别读成 **352.62** 和
**352.60**，真值是 **352.60**（源片帧栅格 `227.92 + n×0.04`，`-ss 227.9` 落到最近
的一帧 227.92）。于是 `end` 收到 352.6 → `-t 124.7` → 那一帧相对 pts 124.68 < 124.7
**照收**，成片里留下一帧整幅均值 12.3 的黑闪。

**要真实帧就两样一起用**：

    ffmpeg -ss <T0> -i film.mp4 -vsync 0 -frames:v 12 -q:v 4 out/f_%03d.jpg   # 不重采样
    ffprobe -v error -select_streams v -show_entries frame=pts_time -of csv=p=0 film.mp4

⚠️ **pts 有固定偏移**，别假设它是 0.04 的整数倍：这条线的成片实测是
`0.021016 + n×0.04`。所以「第几帧」要按 ffprobe 报的 pts 数，不要自己乘。

⚠️ **判据是拿另一条片子当对照组，不是盯着这一帧猜。** 诺斯科娃那条同一个位置是
内容 78.9 **直接**跳解读卡 24.8，中间没有黑帧——也就是**渲染器不会自己插一帧黑的**，
那一帧只能是源片带进来的。一帧的东西「是源片的还是我们自己的」肉眼分不出来，
而这个对照一秒钟就给出答案。

### 停顿全部来自标点——没有 SSML break，标点就是唯一的杠杆

账号所有者 2026-08-03 听完 special-exempt：「配音的停顿和断句，需要根据内容
自然区分。」

查下去：`synthesize_narration` 喂给 edge-tts 的是**纯文本**（`speakable(seg.narration)`），
**一个 `<break>` 都没有**。所以「哪儿停、停多久」百分之百由旁白里的标点决定——
写稿的时候标点不是排版，**是配音的节拍谱**。

四类错，那条片子四类全犯了：

| 毛病 | 例子 | 为什么坏 |
|---|---|---|
| **顿号当逗号使** | 「发给那个因为还在上一站比赛**、**所以来不了资格赛的人」 | 顿号在 TTS 里几乎不停，它只该连**并列的词**（「周三、周四」）。连分句就是一口气 24 字冲过去 |
| **长定语前置** | 「他成了第一个**在这个级别打进半决赛的**中国男子球员」 | 书面读得下来，念出来最累。**把主语挪到句末**：「这个级别打进半决赛的中国男子球员，他是第一个。」 |
| **一句串四五个逗号** | ③6 那句 60 字 | 逗号只给短停，连着四个等于没停。超过 30 字就断成两句 |
| **分号用在不并列的地方** | 「…领先**；**晚上九点零六分…」 | 分号暗示并列，而这是两件事。**排比才用分号**（③4 那三条是对的） |

量化判据（`speakable()` 之后，去掉标点数字数）：

- **最长子句**——两个标点之间的裸字数。**超过 20 就该拆**。改前 28，改后 20
- **最长句**——两个句号之间。超过 35 要看一眼。改前 60，改后 39

⚠️ **这条同时改善字幕**：断行本来就是「按标点，不按数满 16 个字」，标点摆对了，
字幕的断行跟着对。反过来，标点乱的稿子会同时毁掉配音和字幕，而**听感和观感
都不会告诉你根因在标点上**。

⚠️ 重排标点时顺手抓到一个事实错误：「佩古拉六比四、一比二领先」——比分记法是
第一个名字在前，`6-4、1-2` 是「赢了第一盘，第二盘一比二**落后**」。
**把两个比分挤在一个顿号里，连错都看不出来**——这也是拆标点的收益之一。

#### ⭐ 切词错了不用靠耳朵猜：`voice_NN.words.json` 就是合成器自己报的切词

账号所有者 2026-08-03 的第二条：「连在一起的词不要分开，本来分开的两个词
不要连读在一起。」

**这个能直接查证。** 字幕时间轴用的那份 WordBoundary 事件，`text` 字段就是
合成器**自己认为的一个词**——把它们用 `｜` 串起来打印，切错的地方一眼就看见，
不用反复听：

```python
toks = [e["text"] for e in json.load(open("voice_01.words.json"))]
print(" ｜ ".join(toks))
```

那条片子扫出来的（左边是它实际念的）：

| 切成 | 该是 | 后果 |
|---|---|---|
| `规则 ｜ 书写 ｜ 得` | 规则书 ｜ 写得 | **「书写」念成 shūxiě，意思全变** |
| `前 ｜ 十胜` | 前十 ｜ 胜 | 「十胜」是个不存在的词 |
| `特殊 ｜ 豁免进 ｜ 的` | 豁免 ｜ 进 | 动词黏进名词 |
| `雨卡 ｜ 在` | 雨 ｜ 卡在 | 同上 |
| `赢斯特鲁夫` | 赢 ｜ 斯特鲁夫 | 动词黏进人名 |
| `佩古 ｜ 拉六 ｜ 比 ｜ 四` | 佩古拉 ｜ 六比四 | **人名被劈开**，尾字黏到数字上 |
| `基茨 ｜ 比 ｜ 厄尔` | 基茨比厄尔 | 赛事名劈三段，中间那个「比」独立成词 |
| `七月二十 ｜ 一号` | 七月 ｜ 二十一号 | 日期从中间断开 |

**修法只有一条可靠：把歧义本身去掉，不是去猜切词器。**

- **加逗号**把边界钉死（「两本规则书**，**写得不一样」）
- **换句式**让黏连的两个字不再相邻（「被这场雨卡在」→「这场雨会把他卡在」）
- **摊开写**（「第一个前十胜」→「第一次赢下世界前十」）
- **动词后面加「了」**把它和人名撑开（「赢斯特鲁夫」→「赢了斯特鲁夫」）
- **人名前后留逗号**，别让动词直接顶着名字

⚠️ **人名内部切错修不了**（`商｜竣程`、`卢布｜列夫`、`布勃利｜克`、`布云朝｜克特`）
——标点插不进名字中间。好在这一类**每个字的读音不变**，只是重音位置偏，
影响远小于上表那几条「假词」。别为它硬改译名。

⚠️ **闭环是重渲之后再读一遍 `words.json`**。改完就宣布修好了，和「写了不等于
跑过」是同一个毛病——切词是合成器那头的行为，只有它自己报的边界能作数。

#### ⚠️ 加逗号**撑得开**两个该分的词，**合不拢**一个该合的词

上面那张表里的例子全是「本该分开的黏在一起」，加逗号确实管用。反过来那一类
它一点用都没有——2026-08-04 王欣瑜那条第 10 段：

    「抢七输掉了。」   →  抢 ｜ 七 ｜ 输 ｜ 掉 ｜ 了     整段五个单字
    「抢七，输掉了。」 →  抢 ｜ 七 ｜ 输 ｜ 掉 ｜ 了     **一模一样**

理由很干脆：**词边界事件里本来就没有标点**（本文件上面那条早写着，我自己没接
上），逗号根本进不了 token 流。「抢七」缺的是**左边的上下文**——它在段首，
前面什么都没有；补上下文（「那个抢七」）要多两个字，而窗口只剩 +0.33s。

- **判它有多严重，看读音变没变。** 真出事的那几条是**音变了**
  （`规则书写得` → 书写 念成 shūxiě）；「抢｜七」拆开还是 qiǎng 和 qī，
  变的是重音不是音，和上面「人名内部切错」同一档
- ⚠️ **但这一句是推的，不是量的。** 没有仪器能判「听着自不自然」——
  它该进那张只有耳朵能结的账（见下一条），不该当成已经放过


#### ⭐⭐ 年份里的 `〇` 会挡住「这是个年份」的识别——沙箱现在能自己量了

账号所有者 2026-08-27：「tts 里 2002 年读音错误」。

旁白按本文件的惯例写「二〇〇二年」（`〇` 是 U+3007，本仓库里它只当数字零用：
年份、赛季、还有比分 `六比〇`）。⚠️ **问题不在写法对不对，在合成器认不认得
它是个年份**——同一把嗓子、同一语速、同一句上下文，只换这一个字，切词完全变了
（edge-tts 的 `WordBoundary`，逐个实测）：

| 旁白里写 | 写 `〇` 的切词 | 写 `零` 的切词 |
|---|---|---|
| 二〇〇二年 | `二｜〇｜〇｜`**`二年`** ← 黏成一个词 | `二零零二年` 整体 |
| 二〇〇五年 | `二｜〇｜〇｜五｜年` | `二零零五年` 整体 |
| 二〇二六年 | `二｜〇｜二六｜年` | `二零二六年` 整体 |
| 二〇二四 | `二｜〇｜二｜四` ← **四个孤立字** | `二零二四` 整体 |
| **一九九九年** | `一九九九年` **本来就整体** | 同 |

**末行是反证**：唯一不带 `〇` 的那个年份本来就被整体识别——所以是 `〇` 把年份
打散成孤立字的，而孤立的字只能逐个猜读音。

⚠️ **2002 是唯一一个把「二年」黏成一个词的**，而那正是「两年」那个量词短语的
形状（其余年份的末位数字和「年」都是分开的）。账号所有者点的正是这一年。

修法收在 `speakable()`（两条线共用：`explainer.py` 和 `build_match_reel.py`
都调它），和「挑→选」「硬地→硬帝」**同一个形状**：**只改喂给合成器那份，
屏幕上不动，而且字数 1:1**——字幕时间轴按字位从合成那份映射回显示那份，
长度一变整段就漂，这是这套办法能用的前提。判据
`test_年份里的圈零要换成零否则合成器认不出这是年份` 钉三头（换干净了 / 屏幕上
没动 / 字数一样），两个方向反向验证过，红在不同的断言行。

⚠️ **非年份的 `〇` 一并换掉是安全的**，验过：`六比〇`→`六比零` 字节数一模一样。
时长只短 0~0.03 秒，往宽里差，不会把哪一段挤成超长。

### 卡上的字少，是因为旁白会讲；那就必须有字幕

上一条成立的前提是"听得见"。可**静音刷是默认状态**——没有字幕，静音的人拿到的就只有
那两三条短句，旁白里的引语、数字、来龙去脉全丢了，而那才是这条片子的内容。

字幕待在**3:4 画面里面**，不在画布的边条里：卡片上下居中（各 240px 黑边），卡上的
文字块往上收（`CARD_COPY_BOTTOM=230`），在卡片内部腾一条给字幕，上锚（`Alignment=8`）。
**永远只排一行**，左右各留 150px。踩点：

- **时间轴取 edge-tts 的 WordBoundary**，所以合成走 `Communicate.stream()` 而不是 `.save()`——
  `save()` 把这些事件扔了。落在 `voice_XX.words.json` 里。拿不到就按字数等比分配：
  不完美，但绝不能因为拿不到时间轴就整条片子没字幕
- **`boundary="WordBoundary"` 要显式传。** edge-tts 的默认值是 `SentenceBoundary`，
  服务端就只发整句的时刻——我只收 WordBoundary，于是 `words.json` 每条都是 `[]`，
  字幕悄悄退回按字数分，产物看起来一切正常。**又一次「空结果 ≠ 不存在」**：
  空列表和「这个声音不报边界」长得一模一样。答案在本地装着的那份源码里，
  一 grep 就看见了默认参数
- **边界事件里没有标点**，所以字位要**在原文里 find**，不能靠累加事件文本的长度。
  真实数据：一段 122 个非空白字的旁白，边界流只有 109 个，差的 13 个全是逗号句号。
  按累加长度算，「他自己说」在原文排第 108、在边界空间只排第 97，查出来的时刻晚了
  1.7 秒——**越往后漂得越多**，最后一句被压成 0.94 秒读 13 个字。~~判据盯「秒/字」
  各行是否接近，见 `test_字幕时间轴不会越往后越漂`~~
  ⚠️ **那条判据现在不存在了，而它守的行为还在**：`explainer.py` 仍然按
  `text.find(spoken, pos)` 拿**原文字位**去对 WordBoundary（那一行上面就写着
  「时间轴是拿原文的字位去对 WordBoundary 的」）。也就是说**代码是对的，检查没了**——
  这跟本文件反复记的「规矩写对了，实现是空的」正好相反，是**实现对了、判据空了**，
  而两者一样不吭声。真要动这段对齐逻辑，先把「秒/字各行接近」这条判据写回来再动
- **屏幕上的数字用阿拉伯数字**（`arabic_numerals()`），但旁白那份不能动——
  「二〇二六」「六比四」是**给合成器定读法**的。所以换算放在切完行之后，
  只作用在显示的那一份上。几个坑：「唯一一次」连着两个「一」，按数字读就成了
  「唯 11 次」；「一场首轮」「两盘」不是在数数；「第二盘」「第三轮」是序数，
  中文更顺，但「世界第四」是排名，要写成「世界第 4」；「七十万」得在「万」处收住
- **字号不等于一个汉字占的宽度。** libass 按字体的 ascent+descent 把字缩到
  「行高＝FontSize」，思源黑体这两项加起来是 1.46 em，所以一个汉字实际只占
  `FontSize/1.46`。烧帧量出来：字号 46 时 16 个字横跨 505px（31.6px/字），字高 30px
  ——手机上偏小，而我一直按「一个字 52px」在算行宽，**两个数都错了三成**。
  现在字号 68 → 一个汉字 46.6px（屏宽 4.3%）。改字号要重量，别按比例推
- **数字和汉字看着不像一家，不是字体错了，是西文本来就画得小。** 拿成片里的
  「6」和 `NotoSansCJK-Bold` 逐像素比对过——**字体本来就是同一个**（DejaVu 的「6」
  浑圆得多，一眼能分）。差在同字号下西文墨高只有汉字的 0.83（52 : 63）。
  所以数字和西文在 ASS 里单独套一档 `\fs78`（汉字 68），墨高到 0.95 才齐。
  **全角数字试过，不行**：思源的全角只是把同一个字形塞进全角框，字没变粗，
  「2026」反而散成「２ ０ ２ ６」
- **行宽要按画出来的那份算，不是原文。** 切行时用的是汉字数字的原文，画出来的
  却是换算后的——汉字数字大多换完更窄，但「一百」两格换成「100」是 2.03 格，
  正好把一行顶出边。`subtitle_lines` 里的宽度判断已经改成先 `arabic_numerals` 再量
- **一个西文字符占 0.68 个汉字宽**（同字号步进 40.1/68.0 = 0.59，再乘放大的 78/68），
  不是 0.5。按 0.5 估，「2026年4月30日」这种一行会比估计的宽出小半个字
- **左右也要留够，不只是底下。** 小红书/抖音在右侧压着点赞/收藏/评论一列，约屏宽 15%，

  **230 / 字幕框顶距卡底 156** 最好——文字整体下移 50px，画面主体让出来，字幕仍在卡内。
  156 这个数是从**两行**倒推的：1524 + 78×2 = 1680，正好贴住卡底不溢出
- **一行两行都从同一个高度往下长**，所以要用上锚而不是贴底：贴底时一行和两行
  会落在不同位置，跳来跳去
- `WrapStyle=0`（自动折行）而不是 2：切行那步已经把每行卡在 18 格内，正常不会超宽；
  但万一漏过一条，不折行是**左右直接切掉**，折行只是往下长一行，而上锚保证多一行
  仍然离底边 240px。坏的方式要选能兜住的那种
- **断行按标点，不按数满 18 个字**。数字数切出来的是「代表亚洲国家打／进大满贯」
  「赢得 ATP 单／打冠军」——字数对，词被劈成两半。先按标点切子句再拼行，
  实在没标点才在词语边界上断（见 `_best_break`）
- **屏幕上不写标点，而且是全站的。** 账号所有者先说「以后字幕里的尽量不要用
  标点符号，可以切换下一页表达」，我只改了解说片，于是又补了一句
  「**字幕要应用到全局里**」——「昨日一分」「视频本地化」「大满贯竖版 v2」
  三条线还在往画面上烧逗号句号，同一个账号出去的片子字幕两种样子。
  规矩和实现收在 `video/subtitle_text.py`，四条写 ASS 的路径共用；
  **常驻角标／台标不去标点**——那不是字幕，去掉等于改水印本身。
  停顿由换页表达，一个逗号在屏幕上只是噪点。
  **只留 `？！`**——换页表达得了停顿，表达不了「这是一问」，末屏那一问少了
  问号就成了陈述句。判据见 `test_字幕里不写标点`。三处配套：
  - **去标点只作用在显示的那一份**。切子句、找断点仍然靠原文里的标点；先去掉
    就没有断点可依，又会退回「数满 16 个字一刀切」
  - **一个子句就是一行，不再把两句拼进同一行**。原来「能装下就接着装」，于是
    「先看一眼签表。这是澳网女单签表的」这种句号夹中间的行到处都是
  - **标点换成空格，不是删掉**。合并短句时删掉会糊成一坨（「WC。它是谁给的」
    → 「WC它是谁给的」）。空格不是标点
- **两个词边界之间要按字数插值，不能沿用前一个标记的时刻。** 一句一行之后行
  变密，同一对标记之间常落进两三行——沿用的话它们拿到**同一个起始时刻**，
  两条字幕在时间轴上重叠，libass 会同时画出来。边界事件本来就稀（122 字的
  旁白只有 109 个），指望每行都压在事件上不现实
- **「——」要当一个整体**，否则一句里就一个可断的地方都没有，只能硬切
- 字幕文本用 `readable()` 不用 `speakable()`：比分照着念的样子写（「6 比 4」），
  但 `speakable` 里那处挑→选是**给合成器纠音**的，屏幕上必须还是「挑球」


### 画出来的那一屏，也要够大够直观

示意图小到看不清，等于没画。踩过的具体数字：`.diagram-wrap svg` 原来是 `width:760px`，
在 1080 宽的卡上只占七成，而 900 单位 viewBox 里一个 `font-size:20` 落到实际画面上约 17px——
显示器上勉强能看，手机举远一点就废了。现在是 `920px`，`top` 从 250 提到 210 给高度让位。

- **字号按 viewBox 比例算**，别按"看着差不多"。900 宽的 viewBox 里，正文别小于 26，标题 34 起
- **列清单可以，但别用文字排成表格冒充图表**。连败那一屏先做成六行"日期 / 赛事 / 对手 / 比分"，
  被一句"不能都用纯文字啊"打回——列比赛是对的，用文字排出来不是。改成**每场一根横条，
  长度＝她在那场里拿到的局数占比，虚线画在一半**：赢的那场越过去，十一场败仗没有一条够得着。
  `2-6 2-6` 是十六局里拿四局，条只填四分之一，观众不用做除法。数字留在右边给想看的人
- **旁白要把关键的几场念出来**，别只念总数

#### ⚠️ viewBox 的**高度**也有上限：高 20px 就撞进序号药丸那一行

上面那条管的是「字够不够大」，这条管「图能有多高」。2026-08-17 `wang-sabalenka`
踩的：第一版写 `viewBox="0 0 900 660"`、落点两行在 y=586 / 628，渲出来
**注脚的头几个字被「② 唯一一次」那颗药丸盖住**。

账算得很干净——SVG 是**按宽度铺满**的（920px），所以它在卡上的实际高度是
`920 × H/900`，每一行的实际像素位置也跟着 H 走：

| | viewBox | 落点 y | 实际像素（相对图顶） |
|---|---|---|---|
| `_ZHENG_EALA_DIAGRAM`（好的） | 900×**640** | 572 | 585 |
| 第一版（撞了） | 900×**660** | 586 | **599** |

**差 14px，而药丸就在那个位置。** 药丸是卡片版式的一部分，**不随 SVG 变**，
所以图越高、底部那两行越往下掉，掉过头就被压住。

- **高度钉在 640，落点钉在 y≈568 / 608**（`_ZHENG_EALA_DIAGRAM` 那张是标定物）。
  内容装不下就往里收间距，别往下加高度
- ⚠️ **四道闸门和全量测试对这个一声都没有**——图本身没有语法错，每个数都是对的，
  只有渲出来打开看才看得见。这条和「⚠️ 而我给这套写的第一条判据，拦的是一个不存在的坑」
  是一家的：**能落测试的和该用眼睛看的，是两件事**
- 顺带同一天同一条片子的第二个：条形图右边的数字**左对齐**排出去会超出 900 的画布，
  「26 胜 2 负」的「负」字被切在画面外。数字一律 `text-anchor="end"` 钉在右边，
  条再长也推不出去


### 一屏只留一个强调色

**"太艳"的正解是减少颜色数量，不是把颜色调灰。** 这条走过一次弯路：郑钦文那张图表被说
"颜色太艳"，我把红绿换成低饱和的莎粉与浅绿；结果同一套色搬到连败图上，被说"配色很讨厌"——
**低饱和的暖色压在深绿底上会发脏**，不是变高级。

现在的做法：**赢的那一条给品牌绿，其余一律中性半透明白**。不用红绿对撞去说输赢——条短就是短，
读者自己看得出来。少了那一片脏粉，唯一的绿反而跳出来了。

- 一屏最多一个强调色；输赢、好坏、正反，尽量交给**长度、位置、明暗**，不是交给色相
- 文字最多两级：主色近白 `#e7f3ec`，次级灰绿 `#a9bcb2`。四种文字颜色堆在一屏就开始吵
- 灰不是"没设计"，是给唯一那个亮点腾出地方亮
- **次级灰别压得太暗**。一度用到 `#7f958a`，反馈是"文字有点模糊"——那不是分辨率问题，
  是对比度不够，眼睛对不上焦就读成"糊"


### 条形图上不要写字，一个字都别写

**文字压在进度条上，字和条互相削。** 局数曾经写在条内（`19 局里拿到 12 局`），挪到标题行
又和赛事名撞在一起——两次都在抢同一块地方。最后一个字都不留：**条只负责长度，说明写在条的
上一行，图例写在标题下面一行**。条上干净了，长度才看得出来。


### 交叉校验只比得上「说错了」，比不到「什么都没说」

赛后开麦那条线上有两道验转写的闸，做得都挺认真：`verify_transcript` 跑第二份
ASR 比全段，`check_human_quote` 拿赛事官网的人工引语比那几句。**两道全绿，
成片里还是有 3.2 秒是空白的。**

伊埃拉那条：主持人说完「话筒交给你」，她接过话筒对着看台上举菲律宾国旗的
球迷开口——而 YouTube 的自动字幕在那一段**连一个事件都没有**。

毛病在两道闸的形状：它们比的都是**词与词对不对得上**。

> **没有词就没有分歧。空白不但过闸，还让分歧率更好看。**

这是「空结果 ≠ 不存在」长到校验环节上的样子，而且更阴——那儿空结果至少
还是个结果，这儿它连位置都不占：逐行核对表一行一行走的是「源说了什么」，
那 3.2 秒在表里**根本不占一行**，翻一百遍也看不见。

所以每条比对型的校验都要配一条**查覆盖的**：

- **判据要是「源自己有没有出声」，不是「有没有词」。** `[applause]` /
  `[cheering]` 这类噪声标记要**算成有事件**——它们是源在说「我听见了，
  只是不是人话」。切行时丢掉它们是对的（那不是台词），在这儿丢掉就会
  把每一次鼓掌都报成漏词，而**一个天天误报的检查等于没有检查**
- **阈值从真实分布量，别拍。** 那条片子一共三个空档：3.24 秒（真漏了）、
  1.91 秒（两头夹着 `[cheering]` 和 `[applause]`，是掌声）、0.28 秒（抖动）。
  2.0 秒落在最大的和第二个之间
- **机器只负责「找出来」，不负责「判断它是什么」。** 空档是什么——没人说话、
  掌声、还是球员换了母语——机器分不出来，**这一步不要再加模型去猜**
  （账号所有者：「不要多语种」）。第二份 ASR 是 `small.en`，它在空档里
  没听出词来**不等于没人说话**：非英语在它这儿同样是空白。所以报告里这两句
  必须分开写，**别让「没听出来」被读成「没有」**——那正是这一整节要防的东西
- **销账留判据，不许抹平。** 空档写进 spec 的 `caption_gaps_ok`，值写的是
  「听过之后的决定」而不是「这里没问题」——伊埃拉那条销账的值第一句就是
  「⚠️ 这一处是真漏了」。把一个已知的洞抹平，比留着它糟得多

判据落在 `caption_gaps` / `probe_gap_speech`，闸装在 `--stage render`
（和 `suspect` 同一个形状：改或听，两条都没走的不许出片）。
`probe_gap_speech` **不下第二个模型、不切音频**——它摊的是 `verify_transcript`
已经跑完的那份结果，这几秒的答案本来就在里面。

#### 但这道闸只是「让你看一眼」，不是「必须查实」

账号所有者 2026-08-03（冠军版那条的两处空档）：「**没人说话很正常啊，可能是
大家在欢呼之类的打断了讲话。不要卡这个。**」

**颁奖致辞这类素材，被掌声打断是常态而不是异常**——那条片子 215 秒里两处空档
（4.8 秒和 3.7 秒），一处是奖杯递过来的那几秒，一处两头夹着 `[cheering]`、
她随后用 `>> So, thank you.` **重新起头**（掌声打断再接上的标准形状）。

所以销账的门槛是**「摆出你的判据」，不是「拿到确证」**：

| | |
|---|---|
| ✅ 够了 | 「两头夹着 `[cheering]`，她随后重新起头」——写清楚推理，并注明是推的 |
| ✅ 够了 | 「⚠️ 我没听音轨，这是从缩略图墙推的」——**标出软硬**，别装成听过 |
| ❌ 不行 | 「这里没问题」——把一个已知的洞抹平 |
| ❌ 不行 | 为了坐实它去加多语种模型（账号所有者：「不要多语种」） |

**闸没有放宽，也不该放宽**——它当初抓到的是一段真丢了的话（见本节开头）。
变的是**销账的成本**：写两句站得住的推理就过，不用停下来等一个拿不到的确证。

⚠️ **别顺手把「两头有噪声标记就自动销账」写进代码。** 看着很合理，但那正好
覆盖掉当初出事的那一类；而且它会把「机器替你判断了」伪装成「你判断过了」，
和这一整节要防的东西是同一个方向。

##### ⭐ 沙箱听不了音轨，但「是不是掌声」是**量得出来 + 看得出来**的

上面那张表说「摆出你的判据就够」，而判据未必只能是推理。萨巴伦卡那条
（片内 18.7–22.6 秒）三条硬的，加起来比「听一遍」还结实，**每条都是本地几秒的事**：

- **画面：话筒被撤走了。** 19.2 秒 WTA TOUR 的话筒还举在她嘴边，20.4 秒落到
  胸口以外，21.6 / 22.4 秒**整个出画**。**采访者收话筒就是「这一答完了」的现场
  信号**——话筒不在嘴边，她不可能还有话被漏掉。同两格里看台成排双手举在胸前。
  ⚠️ 抽 4 张帧、拼一面墙，十几秒
- **响度：有声音，但峰值低一档。**

      空档            mean −36.8 / max −20.3 dB
      她说话（5 秒）  mean −36.2 / max −16.8
      主持人（5 秒）  mean −34.1 / max −14.8

  **均值和说话一个量级 → 不是静音；峰值低 3.5 dB → 不是人话**（宽频连续的
  掌声没有说话的爆破音尖峰）。⚠️ `volumedetect` **不能带 `-v error`**，
  那会把它自己的 INFO 输出吞掉，报出来是一片空白
- **反证：让第二个模型在这几秒上自相矛盾。** 同一段音频喂三个**错开的**窗口，
  `medium.en` 给了三个不同答案，还多出一个整场没出现过的词：

      18.74–22.64  → "Thank you so much."
      19.60–22.60  → "Thank you **very** much."   ← very 全文 0 次
      20.40–22.60  → "Thank you." "Thank you."    ← 重复，whisper 对噪声的标准形状

  **这是「一次结果不算数」的正用**：单跑一次它会给你一句像模像样的话，
  而那正是把幻觉当漏词补进 `en_fixed` 的路。**错开窗口再跑两次，几乎不要钱。**

⚠️ 判据本身照旧要**标软硬**：这四条是**量出来和看出来的，不是听出来的**，
销账那段最后一句就得这么写——别让下一个人读成「有人听过了」。

##### ⚠️ 报告里的数会被印上封面，所以它必须只算**片内**

`interview_takeaway.py` 的词数原来是拿**整份 `cap_*.json3`** 数的，而
`cap_*.json3` 是**整条源片**的转写。萨巴伦卡那条把主持人那句两个模型都听不清的
收场白剪掉了（`end: 63.7`，那一轮从 63.80 起），于是：

| | |
|---|---|
| 工具报的 | 主持人 **143** 词 |
| 片子里真有的 | **119** 词 |
| 而表头印着 | 「采访 **63.7** 秒」 |

**表头说的是片子，数说的是源片**，两者差 24 个词，读的人没有第二个地方能对。
而这个数**正要印上封面**（`主持人问了 119 个词 / 她答了 77 个`）——多算的那 24 个
观众一个都听不到，印出去就是一句假话。

- 这是「查产物，不查信号」的又一实例：**产物是这条片子，不是那份转写**
- 判据 `test_提炼原料只算片内那一段` **两头都钉**：窗外的不许进来、
  **窗内的一个都不许少**（只钉前一头的话，把窗口收成空的也能过）
- 顺带：`spec` 一改 `start`/`end`，封面上那两个数就要**重数**。这条写进了那条
  spec 的 `push._why`——数的出处只有一个，改了要跟着走

##### ⚠️ 同一族的第三个：**两张**报告，第一份/第二份是谁只修好了一张

「报告里第一份是谁要照实写」当年只改了 `verify_transcript`。`probe_gap_speech`
的表头一直写死 `small.en`、发现漏词那一支一直写死「YouTube 漏了英语」——
而萨巴伦卡那条第二份是 `medium.en`，第一份根本不是 YouTube（Brightcove 源没有
自动字幕轨，第一份也是我们自己跑的）。**闸跑的是对的，报告印的是错的。**

抽成 `_first_source_label()` / `_second_model()` 两个函数，两张报告共用
——「一个数写两处必分叉」。判据 `test_两份转写各是谁两张报告都要照实写`
**扫的是裸子串 `small.en` / `YouTube`，不是 `"small.en"`**：写死的那次嵌在一句
中文里（`第二份 ASR 是 \`small.en\`（英语专用）`），带引号的判据抓不到它。

⚠️ 扫之前要**去掉整行注释和 docstring**——这一条的 docstring 里就写着
「表头写死 `small.en`」。**别用 `ast.get_docstring()` 去 `replace`**：
它回的是**去过缩进**的那一份，和源码原文对不上，一个字都删不掉，**而且不报错**
（判据看起来装上了，其实什么都没剥掉）。用 `re.sub(r'"""[\s\S]*?"""', ...)`。

##### ⭐⭐ 2026-09-10 最坏的一种：**第一份源根本不是他说的话**——`en` 是改写轨，`en-orig` 才是原始 ASR

哈恰诺夫那条（`khachanov-blockx-us-open-2026-qf-interview`）栽的。YouTube 对同一条
片子给**两条英文轨**，而 `fetch_words` 的 `--sub-langs "en"` 一直只要那条改写的：

    en-orig  「English (Original)」——原始 ASR，逐词时间戳是量出来的
    en        原始轨再过一遍翻译管线的**改写版**

三个数把它钉死（同一条片子，同一天量的）：

| | `en` | `en-orig` |
|---|---|---|
| 逐词间距**完全等距** | **56 / 56** | **0 / 54** |
| 词数 | 385 | **416** |
| `uh` / `um` 填词 | **0 个** | **14 个** |

⚠️ **等距就是判据**——逐词 `tOffsetMs` 是拿整条 `dDurationMs` 除以词数摊出来的
（442、294、229…每条内部一个间距到底），不是量出来的。真 ASR 的词时间戳不可能等距。

逐处看也对得上，而**两两读音一点不像**：`on the one hand`／`from one side`、
`for that confrontation`／`for that matchup`、`conserve my energy`／
`keep the energy still there`、`I can't even get up`／`I cannot I cannot stand up`
——是同一句话的两种写法，不是 ASR 认错词（ASR 认错是音近：`Khachanov`→`hatch enough`、
`serve`→`surf`，**那两条只出现在 whisper 那一列**）。而 `en-orig` 那一列和第二份
ASR（whisper `medium.en`）**逐句吻合**，也就是他真说的是后者。

### 有原声的片子：说话时压，不说话时放开

#### ⚠️ 淡入淡出 ≠ 淡到黑：转场是**溶解**，中间一帧黑都不许有

账号所有者要「切换或转场的时候要有淡入淡出，不要突然一下切过来」，我做成了
**每段各自淡到黑再淡回来**——于是每个接缝中间都有一小段全黑。反馈：

    t=62.108        50.66
    t=62.191         0.00   ← 整幅纯黑
    t=62.274        24.50
    t=62.398       102.23

**「淡入淡出」在两段之间指的是溶解**（前一段直接化进后一段），不是各自去碰黑。
现在收在 `dissolve_filtergraph`：画面 `xfade`、现场声 `acrossfade`。

**长度账是这个改动的全部难点，也是它唯一容易错的地方。** 溶解会吃掉时间，
而旁白的 `adelay`、字幕的 cue、`check_reel_landed` 那句「画面总长 − 段落总长
＝ 封面」全按 `seg.length` 累加。所以每段**多切 `SEG_FADE` 秒**当下一个接缝的

    accₖ = accₖ₋₁ + (Lₖ+f) − f = … + Lₖ        每一段仍然正好占 Lₖ
    末段不留尾巴 → accₙ = Σ Lᵢ                  总长和硬切时一模一样

**末段那个「不留」是有讲究的**：给它也留尾巴的话总长会多出 `f` 秒，就得在别处
补一刀 `-t`——而「一个数写两处必分叉」。

- 判据 `test_接缝要溶解不许淡到黑` **真跑一次滤镜图**：三段纯色过一遍，量

  0.18 秒跨了切点，溶解里会多叠进一两帧半透明的第三个镜头——和「整句旁白压在

#### ⚠️ 「唯一一个」被写成「唯1个」——docstring 是对的，实现只做了一半

同一天的第二条反馈：「有些字幕没有补全」。两处，都是 `arabic_numerals`：

| 旁白 | 屏幕上 | |
|---|---|---|
| 生涯唯一一个巡回赛决赛 | **生涯唯1个**巡回赛决赛 | **真的少了一个字** |
| 上一个十几岁就走到这一步 | 上一个 **10几岁** 就走到这一步 | 约数被当成了数 |

第一处的根子很刺眼：那个函数的 docstring 第一段写着「『唯一一次』里连着两个
『一』，按数字读就成了『唯 11 次』。所以裸的『一』『两』一律不碰，**多字的串
也必须含十/百/千**」——**而实现里没有「多字的串」那一条**。`_num_value("一一")`
读出 1，配上量词就把两个字压成一个。量词从「次」换成「个」就漏了过去。

**规矩写对了，实现是空的**——和「是不是这一版那道闸恒真了一个月」同一个形状。
所以规矩落进 docstring 不算数，要落进**测试**。

- `十几` / `二十几` 这类：数字后面跟「几」是**约数**，不转
- 顺带把「一号种子」也归到数字那一路：同一条片子里有「7号种子」「3号种子」，
  只有它是中文，半中半洋（老账：「北京时间8月三号零点」）。卡死在「一号种」
  三个字上，为的是不误伤「统一号召」——判据宁可窄，不可宽
- 判据 `test_屏幕上的数字不许把字吃掉` 的下半张表是**不许被误伤的**那些，
  两个方向都反向验证过

#### 旁白写长了怎么查：`mode=narration`，两分钟，不碰源片也不写产物

`render()` 里，于是想知道哪几段写长了就得跑一趟完整 render——而在**通过**的情况下
那一趟会顺手渲出一条新成片并提交，对已经发过的片子就是白多一个几十 MB 的 blob。

现在 `mode=narration` 只合语音、只报数：整趟 **1 分 31 秒**，语音落临时目录，
`output/` 一个字节不动，清理/上传/提交三步全跳过。它**一次列全所有超长的段**，
外加每段的余量（还标「很紧」）——比离线估准得多，见下。

#### ⚠️⚠️ 本地 `--check-narration` 和 runner 上的 render **不是同一个 TTS**，而 runner 那个更快

2026-08-15 在 `wangxiyu-timofeeva` 上踩的，**代价是一趟白跑的 render**：

    本地（沙箱，没有 AZURE_SPEECH_KEY）  → edge-tts
    runner（仓库配了 Secret）           → Azure，日志第一行写着 `[TTS] Azure（风格 无）`

同一段旁白（第 12 段）本地量 **6.96s**、Azure 只念 **6.50s**，**快 6.6%**。于是
本地那道哑场闸报「余量 3.74s，门槛 4.0s，**过**」，同一份 spec 到 runner 上变成
**4.20s，当场红**。

**也就是说本地那道闸对 runner 是系统性偏乐观的**，而且偏的方向正是危险的那一头
（本地放行、runner 拦住）。换算式：

    Azure 余量 ＝ 本地余量 ＋ 本地旁白 × 0.066

所以判据是：**本地余量落在 3.0~4.0s 之间的段，在 runner 上很可能就翻过 4.0**。
那条片子按「Azure 估算余量 ≤ 3.0s」重排，一次就抓出**五段**（本地看只有一段红）。

⚠️ **这跟「『很紧』也要处理」是同一条，只是现在它有了一个能算的数。** 我当时
看见 3.74 离门槛只差 0.26 却放过了——「离门槛只差零点几」不是「过了」，
是「换个合成器就会红」。

⚠️ **别把 `[TTS] Azure` 那行当噪音。** 它是这条线上**唯一**能告诉你「跑的不是
你本地验的那个声音」的地方；本地日志里对应的那行写的是别的。真要在本地量准，
只能配一份 `AZURE_SPEECH_KEY`（加到仓库 Settings → Secrets → **Actions** 那一栏
工作流才读得到，加到 Codespaces 那栏读不到而且不报错）。

#### ⚠️ 砍字的收益**不是线性的**——同一段我连着低估了两次

按「这一段自己的字速」反推该砍多少字，两次都不够：

|---|---|---|
| nishikori-shang 第 10 段砍到 19 字 | 4.02s | **4.75s**（仍超 0.25s） |
| nishikori-shang 第 1 段砍到 49 字 | 10.17s | **10.82s**（只剩 +0.02s） |

那一段原文 42 字是 4.73 字/秒，砍到 19 字只剩 **4.0 字/秒**。收尾那一问尤其慢。

- **估余量要比线性算出来的多留一档**，砍完必须再跑一次 `mode=narration` 复核
- **「很紧」也要处理**。第 1 段 +0.02s 是过了，但换个音色、改一个字就翻——
  这条线的出发点本来就是「别再为返工付一趟渲染」
- **容差里的负数是真超了**：第 9 段 −0.09s 落在 0.12s 容差内所以放行，
  但字幕会被收进窗口**截掉尾巴**。放行不等于没问题

顺带三处纠正离线估（`words.json` 那套）：hewitt-washington 估它超 1.59s，
**实际装得下**；nishikori-shang 估第 9 段，**实际是第 10 段**；最严重的一段
估出来是 −4.91s，实测 −4.38s。**闸按真实段落算，不会错**——离线估只配用来排序。

#### 「有音轨」不等于「有声音」——wong-brooksby 整片没有现场声

同一天查出来的第二条，形状是「补位的静音盖住真音轨」的**反面**：这次补位的
不是我们，是**源片自己**。

`_has_audio()` 只查**音频流存不存在**。wong-brooksby 的源片有流、有码率，
整条却是数字静音——成片按 3 秒一格采样，**29 个窗里 12 个低于 −70 dB**，
其余八条片子是 0/23~0/39。而 spec 的 `_source` 白纸黑字写着「带原声」。
整套 `sidechaincompress` 闪避对它是空转。

**而两条分支一句 print 都没有**，所以「源片是哑的」和「源片正常」在日志上
一模一样。又一次「兜底出事的时候不吭声」。

- **量信号，不量流**：`audio_peak_db()` 跑一次 `volumedetect` 取峰值。
  124 秒的片子实测 **0.81 秒**（只解音频），值这个钱
- 门槛 `SILENT_PEAK_DB = -60`：真实比赛音轨峰值贴近 0，数字静音是 −91，
  −60 离两头都远
- 照 `mixed_fps` 那套做**显式认领**（`silent_source: "为什么可以"`）。
  一律放行等于继续出哑片；一律拒绝会把纯视频轨的源片挡在门外——
  认领这一步是让这个取舍留下判据
- **报错要说出路**（补 `source_audio` / 换源 / 认领），判据把这三条也钉住了
- **判据必须真造两个文件量一遍**：`_has_audio` 对哑轨返回的是 **True**，
  查源码查不出这个差别。反向验证两次：退回「只查流」→ 不报错；
  报错文本删成一句「源片没有声音」→ 出路那三条断言红
- ⚠️ **没有给 wong-brooksby 写认领**。源片渲完就删了，分不清是它自带的音轨
  本来就哑、还是下载只拿到视频轨——**认领是要写清楚原因的，写不出来就别写**。
  重渲会撞上这道闸停下，那时源片还在手上，量一次就知道。
  测量结果记在 spec 的 `_audio_note` 里

#### 上面这两个缺陷，本来都该被拦下——检查脚本一次都没被调用过

`grep -rn check_reel_landed .github/` **零命中**。`tools/check_reel_landed.py`
一直在仓库里，工具自己的 docstring 还写着「只在成功时出声的检查，没法证明
它真的看过」——而**一个从来没被调用的检查比那还弱一档**。

补跑一遍九条已发的成片，它自己就把今天这两个真缺陷全报了出来：

    「音轨 X，比画面短 N 秒」× 7 条    ← 闪避少了 apad
    「封面之后还有 38 秒是数字静音」    ← wong-brooksby 的哑源片

现在收在 render 之后、**提交之前**（`test_查成片的那个脚本要真的被调用一次`
连位置一起钉）。提交进 main 之后 `push-reel` 就会把它发到微信，而那条消息
发出去收不回来。误拦的代价现在很小——上传那一步的 `always()` 保证成片照样
拿得到，重跑一次即可。

⚠️ **装闸之前得先把假红清掉，否则它一上来就是常年红。** `COVER_SECONDS`
一路从 2.6 改到 1.8 再到 1.2，而老片子是按 2.6 渲的；读不到 `render.json`
就退回今天这个常量，于是**八条老片子全报**「画面 X（spec 算出来 Y）」，
差值几乎恒定在 **1.40~1.44s**——而两条带 `render.json` 的一条都不中。

- **那批假红差点把真问题淹掉**：「音轨比画面短」就混在里面。
  一个笼统的解释盖住一个具体的 bug，又一次
- 改法不是调常量（下次再改还会错），是**拿不到就不判这一项**；

- 清完之后：两条片子全绿，其余各条只剩真缺陷（含 7.28 那版 nishikori-shang

### 剪辑：死球之后再切，别在球还在飞的时候走

账号所有者的原话：「**很多球没有播放完成就切到下一个了，建议死球后再切换下一个，
不然让人看的不明不白的**」。

一分打到一半切走，观众不知道这分谁赢了——而**看懂这一分归谁**是回合镜头唯一的
作用。所以段尾必须落在**死球之后**，再留一点尾巴给结果和反应（默认 1.2 秒）。

**「死球」不用靠看球，记分条会说。** 源片烧死的记分条在死球那一刻才翻牌，
它就是判据，收在 `tools/find_point_ends.py`：量记分条那一小块的帧间差，
跳变的时刻就是一分结束。两个坑在实现里挡掉了——

- **镜头切走时记分条整块消失**（近景、慢镜、看台），那也是一次大跳变，但不是
  死球。所以只认「变化之后记分条还在」的那些
- **比分数字面积很小**，整块的平均差会把它淹掉。用「有多少像素变了」而不是
  「平均变了多少」，而且**门槛要在同一个口径下量**：框大了同一次翻牌的占比会
  掉一个量级

工具只给候选，**还要拿缩略图墙对一眼**：这一段是不是真在这儿结束。

#### 而这个工具一直是零调用方——它要的源片渲完就被删了

`git grep find_point_ends` 只有三处：脚本自己、一条「文件在不在」的断言、
以及 wong-brooksby 的 `_editing_why`。**没有任何工作流或代码调用它**，
而它的 `--video` 指的是**源片**——源片在「丢掉不进仓库的中间物」那一步被删，
想用它得自己另下一份 400 MB。于是每一处段尾错都要先付一趟渲染才发现，
那三处修正（`128.0→132.7`、`143.0→147.7`、`173.0` 正好切在赛点那一分中间）
就是这么攒出来的。

现在 probe **趁源片还在**顺手量一遍，写进 `probe.json` 的 `point_ends`
（probe.json 是进仓库的，源片不进）。

- **记分条位置没法自动认**（每家转播不一样），所以要人给 `--scorebox`。
  不给就跳过，**但要说为什么**——「没量」和「量出来一个都没有」长得一样
- 写错格式（少一个数）**要报错**，不许当成「没给」悄悄跳过
- **零命中要自证是真空**：把实测的 `moved` 分布和门槛一起打出来，并指出
  「多半是 box 框错」。不打的话，「门槛卡错」和「真的没有死球」在日志上
  一模一样——成片那条「找球场对称轴」正是栽在这儿
- 和 `--cover-only` 那次同一个坑：**开关也要在工作流里够得着**，
  判据把这一头也钉住了（`test_死球时刻要趁源片还在的时候量出来`）
- 成本：96 秒的片子实测 **7.5 秒**（0.1 秒一采样）

#### ⚠️⚠️ 2026-08-19：猜到的候选只印在日志里，我自己就漏过一次

账号所有者，同一天重申：「这个问题已经出现好几次了，非常影响流程。还有一个
最大的问题就是，剪辑的时候要等死球了再去切下一段视频，**切记**」。

来路：`bouzkova-jovic` 那条片子的 probe 阶段（run 95976088848）我**从没给过
`--scorebox`**。`suggest_scorebox()` 确实猜出了候选并打印出来——

    [记分条] 猜的候选：--scorebox 90,870,416,980（填充率 0.91，只是猜的，
    拿缩略图墙对一眼再填进下一轮 probe）
    [死球] 没给 --scorebox（记分条位置每家转播不一样，认不出来），
    这一项跳过。段尾就只能靠缩略图墙用眼睛定。

**但这句话埋在几百行 ffmpeg 进度中间的 run 日志里**，probe 那趟一结束就没人
会再去翻。`--dry-run`（我改完 spec 每次都会跑的那 0.2 秒）对这一层完全不
吭声——`point_ends` 空着，而「没给 `--scorebox`」和「给了但检出真的是空的」
在 `probe.json` 里长得一模一样，两者都是 `point_ends: []`。

**这不是又一个「工具写出来了没人用」——猜到的候选本来就在，只是没被存进
唯一会被再看一眼的地方。** 修法是让 `suggest_scorebox()` 把猜到的候选**返回**
（不只打印），probe 那一趟把它存进 `probe.json`（`scorebox_guess`），
`--dry-run` 翻出来当提醒：

    源 https://…：死球时刻还没量过——probe 猜过 --scorebox 90,870,416,980，
    还没有人拿它重跑一轮 probe 确认

猜不出候选（可能没有常驻记分条）时说法换一句，别把「猜不出来」和「猜到了
没确认」混成一句话。

⚠️ **仍然只报不拦，不是新增一道硬闸。** `--scorebox` 给了也可能因为记分条
滞后、镜头切走而检出为空——这正是本节上面「⚠️ 死球那条同理不能做成硬闸」
说的那件事，做成硬闸会重复 `crosses_cut` 那次的错（20 条已发 spec 里 72 处
未声明的跨切点，一做成硬闸就成了墙，逼着下一个人把真检查也一起按掉）。
这条改的是**信息该出现在哪儿**，不是判据的松紧——道理和「封面裁图先找官方
高清实拍」那节讲的「认领」不完全一样：那节后来把 `_frame_why` 从「写一句
就能过」升级成了硬闸（因为找官方图**几乎总是做得到**，不做只是偷懒）；
这一条不能照抄那个升级，因为 `--scorebox` 检出为空**有真实的技术原因**，
不是每次都能修好。

⚠️ **`bouzkova-jovic` 不重渲**（已经推送，消息发出去收不回来）。用
`tools/preview_segments_local.py --slug bouzkova-jovic --seg 4,5` 事后抽查过
那两段有争议的窗口，2 秒一格的分辨率判不清是不是切在死球上——这也是「还差
一步才闭环」的部分：`--dry-run` 现在会提醒「有候选没确认」，但确认本身
仍然要人拿缩略图墙或 `find_point_ends.py` 去核，机器不替这一步下结论。

#### 集锦不要为了短而短：关键点要交代清楚，且只在源片完整时才等死球再切

账号所有者 2026-08-12：「**集锦的长度可以不要太短，视频一定要交代清楚具体
关键点，同时要让每一个球完全结束后再切换下一个，如果原视频里是完整的话**」。

前两句是重申，不是新规矩——「片长不设上限」「不要砍片长」（见下面「100 MiB
是 git 的限制，不是内容的限制」那节）和上面这条「死球之后再切」这次被
一起提了一遍，说明这条线上要一直守住，不能因为在别处（比如压体积、赶
返工速度）图省事就悄悄往回缩。

**新增的是最后那个限定：「如果原视频里是完整的话」。** 上面那条「死球之后
再切」的判据（`find_point_ends.py` 靠记分条翻牌认死球）默认源片把这一分从头
播到尾。但**不是所有源片都这样**——有些官方集锦本身只截了击球前后那几拍，
这一分的死球时刻根本不在素材里，记分条翻牌那一刻已经被剪掉了。这种情况下：

那条片子不是音轨短了，也不是片尾页少停一秒。真正的问题更前一层：第一段冷开场

观众当然会觉得视频没做完。

以后凡是从源片后段抽最后一球／赛点／捧杯做冷开场，必须守两条：

- **冷开场可以重复，结局不能省。** 正文仍要按时间顺序重新放到完整制胜分、
  结果确认和第一波庆祝；“开头已经看过”不能当删掉正文兑现的理由
- **品牌片尾只能接在故事闭合之后。** 最后一段可以没有中文旁白，现场欢呼本来就是

硬闸在 `ending_payoff_problem()`：`match_review` 的第一段只要比**后续任一同源片段**
更晚，就按“后段冷开场”处理；不再用“第一、二段至少差 20 秒”这个会漏掉小倒序、
也会被第二段仍在赛后时刻骗过的经验值。没写 `source` 的段按 `sources` 第一条主源
归一化，多源片之间不互比时间码。正文最后一个同源片段必须重新走到冷开场末尾
（0.25 秒切点容差），否则 `--dry-run` 在下载源片之前直接失败。

每一个后段冷开场都必须显式写 `_ending_payoff_required`，不能拿“没有英文 `quote`”
或“这段有中文旁白”替机器猜画面语义：包含最后一球、结果确认或庆祝就写 `true`，

### 转折点不许剪掉

账号所有者：「一定不要把比赛的转折点剪掉，如果有的话，如果集锦里有的话」。

集锦是别人按「好看」剪的，我们是按「讲清楚这场球」剪的，两套标准不一样。
一个漂亮的制胜分谁都会留，**而转折点常常是一个不好看的保发**——0-40 救三个、
连续四次平分才守住，画面上远不如一记穿越，却是这场球换手的地方。

顺序**不能反**：

1. **先从逐分（`df_mh_1`）里认出转折点**，再去看集锦有没有。反过来做就是
   「集锦里有什么就讲什么」，讲出来的是集锦的故事不是比赛的故事
2. 转折点在集锦里 → **它必须占一段**，而且优先级高于任何单纯好看的回合
3. 转折点不在集锦里 → **明说**，在 spec 的注里写清楚哪一段缺了、为什么。
   默默跳过等于让观众以为这场球是顺下来的

怎么认转折点：比分走向掉头的那一局。典型是**落后方第一次破发反超**、
**被逼到 0-40 或 15-40 却守住的发球局**、**盘点/赛点被救**。逐分里
`|B1|` `|B2|` `|B3|` 密集出现的地方就是候选。

**「在不在集锦里」要拿记分条跨着剪辑点比一次，不能看画面像不像。** 伊埃拉那条
第二盘 2-3 那个换手的破发，画面上明明有那一局的镜头，看着就是「有」——
逐格读记分条才发现只剩**第一分**：

    184.1–192.5   `6 2 0 / 3 3 15`   ← 2-3，这一局的第 1 分
    195.4         剪辑点
    195.5         `6 3 30 / 3 3 15`  ← 已经 3-3，而且是下一局的第 3 分

中间八分连同两次占先全被剪掉了。**一格记分条只证明这一局出现过，不证明
决定性的那几分还在**——判据是剪辑点两侧的比分差了几分，差得动就是被剪了。
（同一条片子里第一盘 4-3 那个 0-40 反过来：三个破发点被剪掉了，但**占先
那一分留着**，所以那条算「有」。留没留住关键的那一分，才是分界线。）

### 竖版短片的取景：铺满、钉死、跟着源片的帧率

用真实比赛画面剪的竖版片（`tools/build_match_reel.py`），三条都是量出来或看出来的：

- **帧率跟着源片走，别硬定 30。** 华盛顿那条官方集锦是 25 fps，而滤镜链里写死
  `fps=30`——5:6，每 5 帧复制一帧，一秒卡五次。这帧**查不出来**：裁切位置每帧都在变，
  两帧的像素并不相同（2099 帧逐帧比对，与前一帧完全相同的 **0 帧**），只有把源片和
  成片的帧率摆在一起才看得见。29.97 要保留 `30000/1001` 的分数式
- **默认不横摇。** 窗口只有源片 32% 宽，一摇，画面里本该静止的底线、球网、广告板、
  看台全跟着滑，而 25 fps 下滑动的静止物最容易看出一格一格。真人看下来的结论就是
  「固定中心的感觉更好」。横摇改成按段显式打开（`"track": true`），
  固定中心按整段运动质心的**中位数**自动定（不是钉在 0.5，庆祝那种人偏左的镜头
  会被挤到边上）
- **回合镜头也铺满，不走 contain。** 球飞到两边确实会出画，但竖版在手机上是整屏播的，
  上下留黑边等于把冲击力先折一半

顺带一条查证方法：**「转场瞬移」要先确认那处源片有没有剪。** 五处相邻段交界里只有一处
源片没剪（窗口凭空横移 399px），其余四处本来就是剪辑点，跳了也看不出来。
判断靠 `select='gt(scene,…)'`，**但解析它的输出要小心**——`pts_time:2.63` 按冒号切，
第 3 段是 `40448   pts_time`，不是时间值；我第一次就是这么把五个真剪辑点全判成了
「没剪」。判据见 `tests/test_match_reel.py`。

#### ⭐ 双打是例外：「回合镜头也铺满，不走 contain」只对单打成立

账号所有者 2026-08-18，看 `williams-sisters-cincinnati`（威廉姆斯姐妹双打）：
「因为是双打可能要画面更宽一些」「双打是例外哈」。

上面那条「回合镜头也铺满」是拿单打样本调出来的——`CROP_W=810`（源片 1920 宽的
42%）这个数本来就是按「两个人站得近」定的。**双打四个人分得比单打宽得多**，
同一个 42% 窗口经常把近端或远端某一位球员切在画面外。这条片子逐段抽帧核对
（每个候选段落取 2~4 帧、叠两条竖线比对 crop 42% 与 contain 62% 两个窗口）
才发现：

- **切没切完全取决于这一刻球员站在哪，不是这一段在讲什么。** 同一个连续镜头
  （81.6~101.32 秒）里，90.6~94.6 秒是近景不受影响、94.6~98.8 秒球员正好收拢在
  中央不受影响、82.0~90.5 秒球员却站得贴着边——机位没变，人的站位在变
- **近景／庆祝／握手这类两三人凑在一起的画面通常不受影响**（92.5s、106.5s、
  116.5s 逐帧核过，人都在 42% 窗口以内）；**只有回合进行中、四人站得开的宽景**
  才会撞上边缘
- **同一段镜头的开头和收尾可能不一样**：网前四人握手那段（119.4~125.6s），
  120.5 秒她们刚走近、远端两位还压在窗口边上，122.5/124.5 秒收拢到网前就没事了
  ——整段按需要走 contain，不按「大多数帧没事」抹平那半秒的风险

所以双打不能默认套用单打调出来的 `crop` 窗口：**每一段回合宽景都要单独抽帧核对
是否切到人**，需要就在那一段写 `"fit": "contain"`（`CONTAIN_KEEP=0.62`，62% 宽，
上下垫模糊放大版），别整条片子一刀切。判据是眼睛看，不是机械阈值——和这个仓库里
其他「故意没有测试」的编辑判断一样，缩略图墙叠上两条对比线就能看，几秒钟的事，
方法记在 `specs/reels/williams-sisters-cincinnati.json` 的 `_editing_why` 里。

#### 画幅：赛场之上是 3:4，不是 9:16

账号所有者定的，理由是「**尽可能多保持主体**」。两条，都能量：

- **小红书的视频静态展示就是 3:4**。9:16 的成片在信息流里被裁掉上下两条，
  海报的台头、比分、赛事行首当其冲——而那几行正是让人看懂这是哪一场的东西
- **从 1920×1080 里取窗口，9:16 只有 608px 宽，3:4 有 810px 宽**，多 33% 的球场。
  「球飞出画面」和「窗口中心偏一点就丢半个场」两件事同时缓解

代价是抖音/视频号播放时上下留黑边。**这是口径选择，问过了**。
解说片那条线不受影响，仍是 9:16 画布 + 3:4 卡——两条线的画幅分开，别互相牵动。

顺带一条：**字幕的上锚要跟着画布重算**，不能沿用解说片的 1524。那个数是
「1920 画布里、卡底 1680 往上 156px」；这里整幅画布就是那张卡，同样是
「卡底往上 156」，换算成 1440-156=**1284**。保的是同一个物理位置，量出来的
那组数一个没动。`PlayResY` 也要一起改——写错的话 libass 按比例缩整套坐标，
字幕整体跑位，**而且不报错**。

#### 固定中心：全片共用一个，别一段一个

「不摇」解决的是窗口在段内乱动；**它解决不了窗口整段站错地方**。账号所有者
一眼看出来：「原版横屏视频转成竖屏后，画面中央可能不是球场正中心视角」。
已发那条片子的回合镜头里，左边网柱和奔驰广告板贴着画面左沿，右半场直接出画。

毛病在**逐段取运动质心的中位数**：一段只有几秒、往往就一两个回合，谁那边球多
中心就偏谁。实测九段取出来 0.338 / 0.406 / 0.381 / 0.470 / 0.482 / 0.547 /
0.466 / 0.455 / 0.407——1920 宽里前后差 **400 像素**，而转播机位从头到尾没动过。

**池化到全片就对了**：一整场球的落点是对称于球场中轴的，样本一多，中位数自己
收敛到中轴上（这批数据是 0.455）。同一个机位，本来就该只有一个中心。
个别段要另定，spec 里给 `cx`——那是人看着缩略图墙定的，说了算。

#### 每一段都要待在同一个镜头里，否则中途会换人

郑钦文那条踩了三处，**渲染一次都没报错**：

| 这一段在讲 | 画面实际是 |
|---|---|
| 末屏「你定闹钟吗？」 | 对手握拳庆祝的近景（窗口 144.3–150.0 跨过 148.2 的切点） |
| 「手术之后的每一场球都是往回爬」 | 前两秒是对手走开的背影（跨过 115.76、117.6 两个切点） |
| 「亚洲的第一枚奥运网球单打金牌」 | 整句压在维基奇的中景上——全片最重的一句 |

**画面和旁白对不上不会让 ffmpeg 失败**，只会静静地发出去。而 `probe.json` 里
本来就记着 `scene_cuts` 和 `url`，按 url 认源片就能机检：

```bash
python3 tools/check_reel_cuts.py specs/reels/<slug>.json output/<date>/reel/*/probe.json
```

- **挑段仍然要靠眼睛看缩略图墙**，这一条只拦「窗口中途换了镜头而我没看见」。
  **`scene_cuts` 是下限，不是上限**：阈值 0.35 认不出「宽景回合 → 同一场地的
  中景」这种切换，郑钦文那条源片约 131 秒就漏了一个，于是「她一直带着疼在打」
  压在对手走开的背影上，而检查器全绿。机检过了仍然要抽帧看
- 真要跨（两边都是同一个人，只是机位换了）就在那一段写
  `"crosses_cut": "<为什么>"` 显式挂账
- **probe 给不全时不许假绿**：零命中和「全都合格」长得一模一样，所以没查成的
  源片要单独报。判据见 `test_每一段都要待在同一个镜头里`
- 还有一层机检管不了的：**同一个镜头里近端是谁**。宽景回合里两个人都在，
  读者读到的是「一场比赛」，可以；但替她说话的那句（「沦落这个词用错了」）
  压在对手身上就不行——那要看缩略图墙上的球衣颜色

##### 低门槛那一份也量出来，但它是线索不是判据

上面那句「`scene_cuts` 是下限」现在有了下文。`gea-shapovalov` 那条更直白：
**474.5 秒他还穿着白 polo 在场上，476.5 秒已经换上蓝外套在捧杯**——中间必然有
一刀，而 `scene_cuts` 只报了 473.07 和 482.67。同一块场地、同一个机位、同样的
灯光，帧间差就是过不了 0.35。那次是靠人看缩略图墙看出来的。

所以 probe 另出一份 `scene_cuts_loose`（门槛 0.12，排掉已经在 `scene_cuts` 里的）：

- **不并进 `scene_cuts`**。那是判据——存量 spec 的 `crosses_cut` 是照着它挂的
  账，混进来等于把一批已经想清楚的声明变成噪音。判据里钉了这一条
- **趁源片还在的时候量**。源片渲完就删，事后想查得自己再下一份几百 MB——
  `find_point_ends.py` 就是这么零调用方了一个月的
- 用法是：挑段的时候扫一眼，**落在你要取的窗口里**的那几个自己去缩略图墙上
  看一眼是不是真换了。别直接拿它当切点，0.12 会把镜头内的大幅运动也报进来

#### 排段长按「字数 ÷ 语速」估，那个语速不是一个数

两条线的合成语速差很远，而且**同一条线上还随句读密度变**：

| | 参数 | 实测 |
|---|---|---|
| 知识解说片 | `+28%` | ≈ 6.1 字/秒 |
| 赛场之上 / 开球之前 | `+6%` | 4.5~4.8 字/秒 |
| 同上，**短句 + 句读密** | `+6%` | **低到 3.6** |

拿解说片那个 6.1 去排剪辑片的段，一口气短三成——踩过。而在剪辑片这条线上按
4.4 排也仍然会翻车：「那一年她二十一岁。从那儿到今天，一共两年。」18 个字带
3 个句读，实测 4.94 秒，**3.64 字/秒**。每个句读大约值 0.25 秒，短句里它占的
比例最大。

所以估的时候要把句读单独计一项。**别再手算了**：`speech_seconds()` 就是这件事，
`--dry-run` 会一次把每段的余量列出来（0.2 秒，不联网、不下源片）。

##### 而上面那个 `0.23 / 0.25 / 0.3` 是拍出来的，错得有方向

拿它跟已发成片对了一遍，**长段估得太长、短段估得太短**：`gea-shapovalov`
第 5 段 91 字估 21.4 秒、实测 16.7 秒。照它排段，长段白留五秒空白，短段要等
六分钟的 render 才知道装不下——两头都在制造返工，而这条线的出发点本来就是
「返工比慢更贵」。

现在的系数是**从已发的成片里拟合出来的**。⚠️ **当前值是
`0.166·字 + 0.32·句读 + 0.45`（按 Azure 拟合，见下一节）**，不是这里原来写的
`0.16 / 0.42 / 0.75`——那一组是 edge-tts 时代的，留在这儿是因为下面三个
**取数的坑**跟系数是哪一组无关，换后端重拟合时照样要躲：

- **实测秒数要拿闸自己量的那个数**（mp3 时长），它落在 `subtitles.ass` 里：
  一段的最后一条字幕正好收在「本段起点 + 旁白时长」上。
  ⚠️ **不能用 `voice_NN.words.json` 的末事件**——那是**词末**，比 mp3 短一个
  固定的 **0.83 秒**（min 0.800 / 中位 0.829 / max 0.851，稳得不像话，就是
  edge-tts 结尾那段静音）。照它标定会把整条模型往短里拉
- **voice 文件要按内容认领，不按序号**。「序号不等于第 N 段」这条 CLAUDE.md
  早就记过；这一轮真剔掉了 9 段——事件文本拼起来和这段旁白对不上的，全是
  跨次重渲留下的旧文件。第一版按「个数相等」筛，`nishikori-shang` 那条照样
  混进来，还给出「14 个字要念 8.05 秒」这种荒唐值
- **贴着段尾的那些要剔掉**：字幕被收进本段窗口，量出来是截断值不是旁白长度

**它仍然是估，不是闸。** `--dry-run` 只判「估得再乐观也装不下」
（差额超过 `SPEECH_EST_ERR`），落在误差带子里的一律报「悬，跑一次
`mode=narration`」——那条路拿真 TTS 量，一分半，永远说了算。

判据 `test_离线估旁白长度要对得上真产物` 钉三头：误差都在带子里、**中位数贴近
0**（宽带子谁都过得了，得证明它准不是松）、**带子不许比实测最坏还宽出半秒**
（写成 10 秒那道闸就等于没装）。冻结的样本表里**必须带上两头的极端**——
第一版按字数均匀取样，最坏只到 0.93 秒，于是「带子不许虚高」那条自己红了。

###### ⭐⭐ 2026-08-15：**这组系数漂的不是模型，是 TTS 后端**——按 `narration_backend` 拆开才看得见

上一节说的「本地 `--check-narration` 和 runner 不是同一个 TTS」，在**离线估**
这头也有一份账，而且更贵：`test_离线估旁白长度要对得上真产物` 那条
`abs(中位数) <= 0.4` 这天报红（**−0.40，正好压线**）。

在这之前 `SPEECH_EST_ERR` 已经被一路调宽过四次（1.44 → 1.5 → 1.63 → 1.75 →
2.07），**每一次的加注都写着「中位数仍贴近 0，不是模型系统性偏差」**——那句话
当时都是真的，只是没人问一句「这批样本是哪个后端渲的」。按 `render.json` 的
`narration_backend` 把 718 段实测拆开，一眼可见：

| 这批产物 | n | 中位误差 | 最坏 |
|---|---|---|---|
| `narration_backend: azure` | **580** | **−0.48** | 1.93 |
| 没记 backend（edge-tts 那批老片） | 138 | **+0.04** | 1.42 |

**老系数对 edge-tts 一直是准的**（中位 +0.04），它只是从来没对 Azure 校过；
而 Azure 现在占 81%，池化中位数就这么被拖过了线。

⚠️ **控制变量做完了才敢动系数**：同一把 `YunjianNeural`、同样 `+6%`，
**edge-tts +0.13 / Azure −0.49**；而跨音色（Azure 的 Yunjian vs Yunxi）只差
0.06。所以分界线是后端，不是音色——**这一步不做，改出来的就是「按一个混着两台
机器的样本拟合的系数」，两边都不准**。

重拟合（只取 Azure 那 580 段）之后 **中位 −0.004、最坏 1.64**，
`SPEECH_EST_ERR` 因此**第一次往下走**（2.07 → 1.64）。

⚠️ **不做「两个后端各留一套系数」**，因为 **edge-tts 那套没有消费者**：
`speech_seconds` 只服务 `--dry-run`，而 dry-run 预判的是**这一段到 runner 上装
不装得下**，runner 走 Azure；本地 `--check-narration` 跑的是真 edge-tts，
根本不读这个估算。

⚠️ **偏长的方向就是「少报哑场」那一头**，而这一轮正为它白烧过一趟 render：
本地估「余量 3.74s、门槛 4.0s、过」，Azure 上是 **4.20s 当场撞哑场闸**
（`wangxiyu-timofeeva`）。系数估得比实际长 → 以为说得满 → 哑场报不出来。

⚠️ **换后端要连三样一起换，少一样就是假绿**：

| 换什么 | 不换会怎样 |
|---|---|
| 三个系数 | 中位数偏一整档 |
| `SPEECH_FITTED_BACKEND`（判据按它挑产物） | 拿另一个后端的成片来校，量到的是后端差不是模型差 |
| **冻结样本表** | 它才是 CI 上的判据（`output/` 不在稀疏检出里）。2026-08-15 那 17 条里 16 条是 edge-tts 渲的，在新系数下中位 **+0.60**、最坏 **2.37**，两条断言一起红——**而模型对今天的产物是准的** |

最后那一行是这次真正的坑：**改系数会让冻结表反过来红**，而那一红看起来完全像
「新系数不对」。表必须跟着系数走。

##### ⚠️ 改 spec 不重渲，spec 会悄悄坏掉——`wong-lehecka` 坏了三天没人知道

这道离线估装上的**第一分钟**就抓到一条：`wong-lehecka` 第 10 段画面 7.5 秒、
估旁白 10.25 秒。查下去是这么来的——

    7.30  成片发出去，那时旁白 22 字：「排名差九十六位，生涯排名最高胜。」
    之后  「收尾要落在一问上」这条规矩追认，把那一问补进旁白，涨到 48 字
    结果  **从那天起这条 spec 就渲不出来了**，而没人再渲它

**真闸（TTS 那道）要跑一趟 render 才出声**，所以它一直躺在仓库里假装是好的。
`voice_09.words.json` 里存的还是旧的那句——这也是上面「voice 文件要按内容认领」
那条的又一个用处：**产物和 spec 对不上，本身就是一条线索**。

- 改 spec 不重渲是常事（措辞、注解、规矩追认），所以要有一条**每次 CI 都跑**的
  检查：`test_每条spec的旁白都还估得下`，只吃 `specs/` 和 `tools/`，不联网
- 修的时候**两头一起动**：窗口 199.5 → 201.6（下一个切点在 201.64，没跨过去），
  旁白收到 37 字。只砍字会把内容砍没，只拉窗口拉不够
- 顺带一条口径：**7.5 秒的画面装不下 7.5 秒的话**。同期实测，9.5 秒的窗口配的是
  6.6 秒的旁白——窗口要给现场声和反应留出一截

##### ⚠️ 而这个通用常数偏保守三成——要排稿就拿这条片子自己的数回归

给霍达尔那条补旁白时，按上面那个常数估，**十九段里有九段「要超」**；实际上
`mode=narration` 用真语音跑下来**一段都没超**，最紧的还剩 0.77s。

差别在于常数是跨片子拍平的，而**同一条片子里音色、语速参数、句读密度是固定的**。
拿这条片子**已经量到的那些段**回归（`spoken ≈ a·字数 + b·句读数`，最小二乘），
jodar-fritz 十九段解出来是：

    0.190 s/字 + 0.379 s/句读     均方根误差 0.30s
    （通用常数 0.23~0.26 / 0.25，对云见 +6% 这把嗓子偏保守约 30%）

「每段说了多久」从**已发成片的字幕时间轴**就能量出来（首条起点到末条终点），
不用另跑语音。所以：**第一版排稿用常数，改稿用回归**——改稿的时候手里已经有
上一版的实测了，不用它是浪费。

真跑起来全垮：

- 修掉门槛的 bug 之后重新量，108 张真源片帧估出来的轴**从 0.0 散到 0.85，
  没有任何聚集**；把成片反解回去，同一个机位解出 0.29~0.51

什么都没有——没有广告板、没有记分条、没有观众、没有影子。

- **合成数据过了不等于成立**。它验的是"我的实现符合我的假设"，不是"假设成立"。
  假设本身错了，合成数据只会陪着一起错
- **门槛的数要在同一个口径下量**。我最早那批阈值是拿 9:16 的成片帧量的，而
  `cv2.resize(frame, (640, 360))` 写死了 16:9——**图被横向压扁三倍**，量出来的
  占比全是假的。16:9 的源片没事，所以本地怎么试都试不出来
- **门槛卡错时，日志里的「没找到球场」和「真的没有球场」长得一模一样**。
  源片只在 runner 上有，所以判据的数值必须跟着打进日志，否则又是"空结果
  当成真空"

### 字体名写「正规」的那个，等于写一个不存在的字体

给 ASS 换品牌字体（得意黑）时踩的，**反直觉而且完全不报错**：

| ASS 里的 `Fontname` | 渲出来的 md5 |
|---|---|
| `得意黑` | `c80c7f79e9a4` ← 认 |
| `Smiley Sans` | `d75e3012a8d0` |
| `NoSuchFontXYZ` | `d75e3012a8d0` ← **和上一行一模一样** |

PIL 的 `getname()` 报的是 `Smiley Sans`，看着才是「正规」的 family 名——
可 libass 认的是本地化的那个。**写英文名和写一个根本不存在的名字效果完全相同**：
静默回退到别的字体，画面照样出得来。

配套三条：

- **libass 读不了 woff2**。浏览器那条路（`webcards._font_css`）用 woff2，
  ASS 这条路要 ttf；仓库里两份都留着，ttf 从 woff2 解出来
- **`fontsdir` 是追加一个目录，不是替换**。指到 `assets/fonts` 之后，
  系统字体照旧走 fontconfig
- **缺字画的是 `.notdef`，不是空白**。判「这个字体有没有这个字」不能断言
  「墨迹为空」——实测 `.notdef` 有 32×35 的墨，那正是那个豆腐块。
  要拿一个**必定缺失的码位**（私用区 U+E000）当对照比
- **`.ttc` 是字体集合不是字体**（思源黑体一份文件里装着 SC/TC/JP/KR 好几张脸）。
  解析器不认集合头的话整份读出来是**空的**，而空集合和「名字对不上」
  在断言里长得一模一样

**同一行里换字体／颜色，每一段都要先 `\r`。** ASS 的覆盖是**粘连的**：顶栏
那道绿竖条设了 `\c`，下一段不复位，**后面整行标题跟着变绿**。渲出来一眼看见，
代码里一点异常都没有。复位写 `\r`（回到本 Style 的默认值），别逐项写回去——
逐项要列举颜色、字重、间距、字号…，以后加一项忘一项就又回到这儿。

#### ⚠️ 例外：这一行上有 `\t()` 动画时，`\r` 会把动画一起清掉

##### ⭐⭐ 而这次真正的教训：**改一个全库都要走的算法，只拿四个例子对比过就合并了**

四条都更好，于是合并**。全库跑一遍 before/after 才看见真账：

    54 条子句的断点挪了位置，其中 7 条从词边界挪到了非词边界，
    而那 7 条里**真把词劈开的有 4 条**——

        贝莱克一路稳扎稳打建 ｜ 立起5比1的领先    「建立」
        本西奇熬了3小时20 ｜ 四分钟才拿下汤森德   「二十四分钟」劈成 20 和四
        首盘她一度让汤森德打 ｜ 出5比2的领先      「打出」
        一记救球让整个蒙特利 ｜ 尔一起站了起来    「蒙特利尔」

⚠️ **那四条一条都不在我看过的四个例子里**——「我抽查过」和「我验过」在这种
改动上差着一个量级：改的是**全库 176 条 spec、5991 行字幕都要走的那条路**，
而抽查的分母是 4。

**根子是量级**：`score = bonus * 100 + i`，而孤行罚分 −95 会把 `bonus=1` 的
候选从 100 拉到 5，此时它和 `bonus=0` 只差 5 分——`+ i` 最多 20 但**跨不过
一个边界档**（100），90 分的均分项跨得过去。**这几个分数是一个调好的平衡，
不是三个可以各自调的旋钮**。`_best_break` 已整个回退。

⚠️ **「孤行好过把词劈开」这条账是这么算的**：10 处孤屏换 4 处劈词——孤屏只是
一屏停短了，劈词是屏幕上出现一个不存在的词。方向不对等，所以不换。

**防线装成两条判据，缺一条都不够**：

| 判据 | 钉什么 | 边界 |
|---|---|---|
| `test_断点不许让非词边界赢过词边界` | 不变量：**还有 bonus>0 的合法候选就不许选 bonus==0 的** | 四个手挑的句子——上面四条劈词里**只盖住两条** |
| **`test_断行的硬切不许悄悄挪位置`** | 全库每条超宽子句今天断在哪儿，冻结在 `tests/fixtures/subtitle_hard_cuts.json`（128 条） | **把那次手工全库 diff 变成机器做的** |

⚠️ **后者按「子句原文」认领，所以它是一条算法闸不是内容闸**：新写一条 spec
（新子句不在表里）、改一句旁白（老子句消失）**都不红**，只有动了断行算法、
表里的句子断点挪了位置才红。这是故意的——CLAUDE.md 早定过「超宽子句只报不
拦」（做成硬闸会把一批已发的好 spec 挡住），这条判据一个字都不许去管新内容。

改对了要重新冻结，**先 `--diff` 逐条看过**：

    python3 tools/freeze_subtitle_cuts.py --diff     # 只看会变什么
    python3 tools/freeze_subtitle_cuts.py            # 看过了，认了

⚠️ 报告里那个 `❌ 从词边界挪到了非词边界` **只是提示不是判决**：`_SUB_AFTER`
那张词尾表很粗，7 条挂 ❌ 里真劈词的只有 4 条，另外 3 条（「北美 ｜ 硬地赛季
的状态」这类）断得其实挺好、只是表认不出来。**逐条读，别照着标记数数。**

⚠️ 顺带一个**没做成的判据**，记下来别再想一遍：本来想装「全库劈词数不许涨」
的棘轮。量完否掉了——那 20 处 bonus==0 的硬切里一多半是词尾表的盲点
（「多伦多国家银行公开赛女单 ｜ 1/8决赛」断得没问题），而且**新写一条 spec
就可能让它涨一个**，于是它会在正常加内容时变红，把人训练成「红了就把数字调
大」。**棘轮盯的是语料，而我要防的是算法**——冻结表按子句原文认领，才不随
语料漂。

**机器改不掉的两条进 dry-run 软报告**（写 spec 那一刻看见，不是渲完才看见），
和 `overwide_clauses` 同一个口径**只报不拦**——一句话的落点本来就常常是短的，
做成硬闸会把一批已发的好 spec 挡住：

    [断句] 1 处同一句被切成「一行贴满 + 一行三两个字」，后半读起来是半截话
      第 9 段「第四盘 纳沃内从1比2连赢5局」（14 格）／「6比2」（2 格）
    [断句] 1 句串了四个以上逗号——逗号只给短停，连着四个等于没停

同一套约束也写进了 `draft_spec` 的【配音断句】——自动链的模型在**起草那一刻**
就该躲开这两个形状，而不是等 dry-run 报出来再改。

⚠️ 判「隔没隔着句号」两处共用 `crosses_hard_break`（`subtitle_lines` 拿它决定
能不能跨句合并、报告拿它分「半截话」和「一句短话」）——写两处必分叉，而分叉
的样子是「报出来的和实际切出来的不是同一批」。

判据 `test_分行整句一起挑最优不许贪心把尾巴挤成孤屏`（三个方向分别反向验证
过，各红在自己的断言行）＋ `test_断句的两条软报告接在dry_run上`
＋ 上面那两条防线。⚠️ **dry-run 的超宽子句报告现在把切出来的样子也印出来**
（`第 3 段（21 格）「科斯秋克照样4比6比6比2逆 ｜ 转拿下了这场比赛」`）——
只报「这一句超宽」的话，读的人还得自己去想它会被切成什么样。

⚠️ **报告里故意不再判一句「切在词中间」**：拿 `_break_bonus` 当那个判词试过，
全库 135 处硬切里它对 20 处喊劈词，而逐条读下来**真劈的只有五处上下**
（「送出17个 ｜ 非受迫失误」这种断得挺好的也被它喊）。**一条四次里错三次的
提示，只会把人训练成不看这个报告**。切出来的样子本身就是判据，读一眼就知道
要不要加逗号——⚠️ 这和上面 `freeze_subtitle_cuts.py --diff` 里保留 `❌`
不矛盾：那儿比的是**同一条子句改动前后**，标记的意思是「这一条变成了表认不出
的断法，去读一眼」，不是「这一条错了」。
已发的片子**不重渲**，这套只管以后。

### 哑场那道闸：拿真实产物判，别在离线估阶段死磕

账号所有者 2026-08-21：「哑场的时长判断也不用太苛刻。」

`--dry-run` 阶段的离线估（`speech_seconds()`）本身**允许偏保守**——它的职责
是「提前让人看见」，不是拍板。真正说了算的是 render 用真实 TTS 合出来之后
量到的数（4.0 秒硬闸）。**别在离线估阶段就反复裁剪窗口去凑一个"看起来更
安全"的余量**——那不但拖慢交付，离线估本身还偏保守（同一批样本对比 Azure
实测普遍快 3.5%~6.6%），裁得越狠越可能把画面裁得比需要的还紧，反而伤了内容
完整性（和「片长可以商量，画质不商量」「不要砍片长」是同一条底线）。

判据：`--dry-run` 报「悬」或「哑场」只是提醒，**渲一次拿 `render.json` 或
`mode=narration` 的真实结果做决定**，不要凭离线估计的数字反复回去改 spec。

⚠️ **这三条不是降低质量的门槛，是把力气用在真正决定质量的地方**——精准、
四道选图闸门、贴近比赛事实这些硬标准一个字都没有松；松的只是「同一件事重复
验证几遍」这类不产生新信息的动作。判据是问一句：**这一次多花的时间，换回来
的是一个新的、之前不知道的事实，还是只是把已经知道的事实再确认一遍？**
前者值得做，后者是过度校验。

### ⭐⭐ 赛后采访片**从比赛结束那一刻开头**，不从第一个问题开头

    237.44  `He takes down the three-time champion here, Novak Djokovic.`
    241.68  `>> Thiago, huge congratulations…`  ←  采访从这儿才开始

**为什么它更好，三条都不是文风问题：**

- 刷到这条的人**不用先搞清「这是谁、赢了谁」才听得懂采访**。采访本身从第一句起

- 开场第 ① 格因此是**全片最强的那一格画面**（赛点／庆祝），而不是一个人站着
  说话——「⭐ 开场三格的顺序」那条本来就这么要求，只是一直没在这条线上用
- 那句分量是**转播自己说的**，比我们替他说硬（同一条线上「画面自证」的老规矩：
  来源自己写下的东西 > 我们的转述）

**现在有闸了**（`check_opening`，排在 `main()` 第一行，只读 spec、0.2 秒报）：

    "opening": {"kind": "match_end", "lead_in": 13.8,
                "why": "227.9 起：赛点落地 ＋ 解说报出「他掀翻了这里的三冠王」"}

是可预见的：**从第一个问题起是最省事的写法**（第一条字幕事件就在那儿，`start`
抄过来就行），所以不认领的话每条都会自然滑回去，而**漏掉那一段不会报错**——
片子照样出得来，只是开场从「赛点落地」变成「一个人站着开始说话」。
和 `interview_kind` / `mixed_fps` / `silent_source` 是同一个形状。

事实**（发布会背板、演播室、话筒样式），不是一句随口的免责——写不出来就说明
**还没打开源片看过**，而那正是这道闸要拦的。

「赛场之上」了，而那是另一个栏目。

画面仍然是赛后的庆祝和握手，但每一秒都有字幕。
**「更早」和「更好」在这条线上不是一回事。**

⚠️ **WTA 逐场集锦那一档天然最好收**：采访就接在集锦尾巴上，赛点就在采访前几秒
（`noskova-boulter` 我从第一问前 0.24 秒起，**完全可以再往前收**，那条已发不重渲）。
反倒是发布会和演播室专访那一档收不到——那就是 `none` 的正当用法。


### ⭐ 烧进画面的英文里不许有语气词——而它只能**在切行之后**去

账号所有者 2026-08-15：「**以后把英文字幕里的语气词去掉比如 uh en 之类的**」。

自动字幕忠实记录每一个 `uh`／`um`，而这条线发的是**英语学习素材**：
「Um, honestly, I don't know.」印在画面上，读者学到的第一个词是 `Um`。
实测这批素材里只有两种真的出现过——**`uh` 264 次、`um` 247 次**
（26 份自动字幕全扫过；`ah`／`eh`／`mm`／`hmm`／`erm` 一次都没有）。

现在 `drop_hesitations` / `strip_hesitation_lines` 自动去，**420 行**会变。

#### ⚠️ 位置是这条改动的全部风险：切行**之前**去是对的，但会砸掉存量

切行之前去才是「更对」的位置——语气词不该参与断行、也不该占宽度。
**可我先量了一遍**：切行前去掉，**25 条 spec 里 16 条的行数会变**
（`swiatek-rybakina-…-presser` 234→228、`shelton-mensik` 232→227）。

而 `zh` 是**逐行手写的**、`en_fixed` 是**按行号挂的**——行数一变这两样全部
对不上，`write_ass` 那道「中文 N 行、英文 M 行，对不上」当场红。**已发的片子
不为措辞重渲，可 spec 还在仓库里、CI 每次都校**。

所以只改**这一行的文本**，一个字都不动断行。代价照实说：断行仍然是按带语气词
的原文排的，偶尔比理想的松一格；换来的是零存量破坏。判据
`test_去语气词不许改行数否则存量的中文全对不上` 钉两头——**切行那一步不许去**
（去了行数就会变）、**去完之后行数一个不许少**。

⚠️ **「先量再决定」是这条唯一做对的地方。** 按「哪儿更对」写，当场砸掉 16 条
已发 spec；而那 16 条会红在 CI 上，不是红在我手上。

#### ⚠️ 这个模块里已经有**三份**口头语名单，宽窄不同，别互相搬

| 名单 | 干什么 | 宽窄 |
|---|---|---|
| `_COMPARE_FILLERS` | 两份 ASR 逐词比对时**两边都去掉** | **最窄**，去多了会掩盖真分歧 |
| `_FILLER` | 跟记者写的人工引语比对时去掉 | 最宽（记者不会写 `ah`／`mm`），只影响比对不影响产物 |
| 烧字幕（复用第一份） | **从画面上真的删掉** | **风险最高**：删多了观众就少看到内容 |

烧字幕**只能用最窄的那份**，而且是从 `_COMPARE_FILLERS` **推**出来的不是抄的
（判据用 AST 认，注释里提到那个名字不算数）。谁哪天为了比对方便把它放宽，
`test_烧进画面的语气词名单只许最窄的那一档` 当场红，逼他显式把两份拆开——
而不是让画面上的字悄悄少几个词。

⚠️ **别以为这三份是嵌套的。** 我写过一条「窄的必须包含在宽的里」，当场红：
两份在**两个方向上**都各有各的（`_COMPARE_FILLERS` 多 `uhh`／`umm`，
`_FILLER` 多 `er`／`ah`／`mm`／`hmm`／`mhm`）。**听起来很合理，而合理不等于量过。**

#### 两个细节

- **整行只剩语气词的，原样留下并出声**。实测 2226 行里有 5 行是这样（光秃秃一个
  `Uh`／`Um,`）。去空了画面上就是「有中文、没英文」，而那一行的中文还在——
  真要处理得人来定（改 `en_fixed`，或者把中文一起改），**机器不替他决定**
- **大小写要补回来**：`Um, honestly, …` 去掉之后是 `honestly, …`，句首小写看着
  像漏了个词。只在原文那一格本来就是大写时才补
- **去在 `en_fixed` 之后**：`en_fixed` 是手写的整行替换，而这条规矩管的是
  「烧进画面的英文长什么样」，手写那几行同样算数——存量里就有 **8 处**
  `en_fixed` 自己带着 `um`／`Uh`


### 三道闸，都只吃 spec 不读产物

CI 的稀疏检出把 `output/` 挡在外面——拿产物当主语的判据在 CI 上会静静地
变成一盏恒真的绿灯（这条本文件里栽过一次）。所以 `check_takeaway` 只看
spec 和常量：

| 闸 | 拦什么 |
|---|---|
| 有没有 `takeaway` | 漏掉的样子是「片子照常出，只是又变回一条纯搬运」 |
| `open.point` 引的话在不在 `zh` 里 | **这张卡唯一致命的错法**，而它渲出来一点异常都没有 |
| ~~自有画面 ≥ `MIN_OURS_RATIO`（10%）~~ | ⚠️ **2026-08-08 撤销**，只报数不拒渲——见「`MIN_OURS_RATIO` 拒渲那道闸撤销了」那节 |

⚠️ **闸排在下载之前**，判据钉了位置（`test_解读卡那道闸要排在下载之前`）——
只测行为的话，闸排在 `yt_download` 后面照样全绿，而真实代价是每次写错字段
都要先等几百 MB 下完。

⚠️ **门槛跟着版式改过一次，这件事本身就是它该有的用法。** 原来 15% 是按
**两张**卡定的；砍掉落点卡之后只剩 12.6%，**恰好压线**——一条 80 秒的采访
就会红，而那不是它想拦的东西。重定在 **10%**：

- 仍是被判那条（0.8%）的 **12 倍**，「整段搬运 + 一张封面」照样过不去
  ——217 秒那个形状按新版式算只有 **5.5%**
- 一条 60~100 秒的正常场上采访，只靠收尾卡就过得去
- 两分钟以上的仍然会红，**那正是该按落点剪的信号**

⚠️ 改门槛要**连它的前提一起改**。15% 这个数在两张卡的世界里是对的，在一张卡的
世界里是一条常年红——**判据要跟着结构走，不是跟着当初那一版的数走**。
同一天里 `tk["open"]` 那道引文闸犯的是同一个错（写死了字段名，落点卡变可选
就 `KeyError`），现在两张卡都查。


### ⚠️ 加解读卡时，「两支各拼一次」这个坑要第三次发生

`render()` 原来按「有没有封面」分两支、各 `concat` 一遍。加片尾时只改了一支
（判据 `test_采访片两条路都要接片尾` 就是为那次写的），加解读卡是同一件事
第三次。所以这次把清单收成**一份** `parts` 列表：每一段只有一处决定它进不进去。

- 老那条判据的**主语没了**（`body.split('if not spec.get("cover"):')` 当场
  `IndexError`）。**主语没了就得换判据**，留着它就是一条常年红——现在钉的是
  「片尾只有一处 append，而且缩进是 4 格（没嵌在任何分支里）」
- ⚠️ 换判据时第一版写的是「前面最近的那个 `if` 不许是 cover」，**当场误伤**：
  `if spec.get("cover"):` 确实排在前面，但那是往清单里加封面的**单行块**。
  又一次「判据宁可窄，不可宽」——只不过这次糊的不是范围，是**层级**。
  判嵌套就用缩进，它就是嵌套本身
- 静音段的 ffmpeg 参数收进 `_still_segment`，判据要求全文件只出现一次
  `anullsrc`：这条线走 `concat` + `-c copy`，声道数差一项就静默丢流


### ⭐ 2026-08-08：`MIN_OURS_RATIO` 拒渲那道闸撤销了——完整性优先于占比

账号所有者：「就不该有限制时长的这个闸」「要保证原始内容的完整性啊」。

**来路**：`eala-mcnally-toronto-2026-r3-presser` 是一场**完整**的赛后发布会
（462 秒），而 `check_takeaway()` 第③道闸要求「自有画面（封面+解读卡+片尾）
÷ 全片 ≥ 10%」——解读卡字数有上限（`TAKEAWAY_MAX_CHARS=34`），撑死也就
17 秒左右自有画面，倒推出**全片不能超过约 171 秒**这道硬顶。为了过这道闸，
我把这场完整发布会硬挖成了一段 150.5 秒的问答，账号所有者问「为啥裁剪了
这么多」，答案本质是「为了凑一个跟内容完整性无关的比例」。

**这道闸原来是故意这么设计的**（见 `MIN_OURS_RATIO` 上面那段旧注释：
「两分钟以上仍然会红——那正是该按落点剪的信号」）——但那个设计假设本身就是
现在被推翻的部分：**片子该多长，由这段内容本身决定**，不该被一个和内容完整性
无关的比例倒逼着剪短。

**现在的处置**：`ours_ratio()` 照旧算、`check_takeaway()` 照旧打印这个数，
但**不再拿它 `raise SystemExit`**。解读卡本身该有的两道闸（有没有解读卡、
引文是不是他真说的）**一个字没松**——撤销的只是「占比够不够」这一条，
不是把「别人的画面+我们的字幕、连一句解读都没有」那种真的纯搬运也放行了。

⚠️ **这不等于「越长越好」。** 完整性说的是"这段内容该有的长度"，不是鼓励
无谓拉长——单段连续裁剪仍然是这条线的技术边界（见上面「为什么只收
40.5–191.0 秒」那段 PR 描述里的道理），选段仍然要选一段完整、连贯的问答，
只是不再为了凑占比而人为砍短。

判据在 `test_自有画面占比低不再拒渲只报数`：217 秒占比 0.8%~3.4% 这种
过去必挂的形状，现在不许再抛 `SystemExit`，只许在日志里报数；反向验证过
（把 `raise` 加回去，测试当场红）。

#### ⭐ 2026-08-12：进一步定死——采访片**没有时长上限**，别过度剪辑

账号所有者，就在这条线上：「不要过多剪辑，需要保留原视频主要内容」
「采访视频没有时长限制」「记住了」。

**这句话比上面那条 08-08 的走得更远**：08-08 撤的是「占比不够就拒渲」那道闸，
末尾还留了一句「单段连续裁剪仍然是这条线的技术边界，选段仍然要选一段完整、
连贯的问答」——读起来像是在说「还是要挑一段，只是不用为了凑比例砍短」。
**这条把那层暗示也否掉了**：不是「挑一段完整的问答」，是**保留原视频的主要
内容**，而且**没有时长限制**——账号所有者要的默认不是「剪出一段」，是
「这条采访本来讲了什么，就留住什么」。

- **别再把「片子短一点更抓人」的直觉带回采访片。** 那条直觉对「赛场之上」
  成立（本文件「片长可以商量，画质不商量」那节讲的是另一个栏目），对「赛后
  开麦」这条线现在是反的——408、508 秒的完整发布会/采访，只要内容本身
  站得住，不用为了「怕太长没人看」去挖短
- **`start`/`end` 单段连续区间那条技术边界没变**（工具本来就不支持拼接
  非连续片段），但**在这个技术边界内，默认取值要偏向「多留」不是「少留」**：
  拿不准某几分钟要不要剪掉时，不剪
- 仍然要剪掉的：**不是采访本体的部分**（片头的比赛集锦/解说、片尾的场务
  空镜、长时间的技术故障静默）——「保留主要内容」说的是访谈这一段，不是
  连集锦也不让剪


### 让当事人自己说：`quote`

采访原声那一段**不配旁白，但必须出中文字幕**（spec 里写 `quote`，和
`narration` 互斥）。

字幕那条线原来只认 `narration`，没有旁白就没有字幕——于是原声段在成片里对
**大多数人是彻底空白**：听不懂英文的看不懂，而「静音刷是默认状态」，静音的
人连声音都没有。两头都丢，**而且不报错**。

- `quote` 不合成语音，所以闪避不会把他的话压下去（现场声开在 `BED_LOUD`）
- 字幕按字数等比铺满整段——拿不到词边界时本来就是这么退的
- **断行要渲出来比**，不能想。休伊特那条第一版「我也不确定。主持人说，」被并进
  同一行，读起来成了「我也不确定，主持人说」——**他的话和旁人的话粘在一起，
  意思全反**。排三版比断行，选每行正好一个子句的那版

值不值得为它多跑几趟：休伊特那条的落点就是他自己讲那个庆祝动作
（「他从来没给它取过名字，他就是一直那么做。我小时候看见了，从来没问过。」）——
用他的声音比我们替他转述强得多。


### 多源剪辑：尺寸没有出路，帧率要认领

一条片子跨几条源片时，`check_sources_match` 在下载完就判，**两样的严重程度
不同**：

- **尺寸**对不上就是裁错（裁切窗口按源片宽高算）。没有出路，一律红
- **帧率**对不上是重采样，成片跟**主源**走。50 → 25 是整数倍，隔帧丢得整整
  齐齐，看不出来；30 → 25 是六帧丢一帧，**静态说话头几乎无感，回合镜头一眼
  看得出一顿一顿**

所以帧率要在 spec 里**显式认领**（`mixed_fps: {源键: 为什么可以}`）。一律红会
把采访这类素材整个挡在门外（采访多是 30，赛事集锦多是 25/50）；一律放行又回到
「兜底出事的时候不吭声」。认领这一步是让这个取舍**留下判据**。

**探测要把下游会用到的每一个量都报出来。** `probe.json` 原来只记尺寸，帧率要
等 render 下完两条源片（一分半）才算——休伊特那条的两条官方集锦
**同一个频道、同一周，一条 25 一条 50**，按原样 render 必炸，而这件事本可以
在探测那一刻就知道。加进 probe 的当天就抓到了。
