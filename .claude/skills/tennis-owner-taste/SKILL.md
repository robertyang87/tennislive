## 2026-10-03：所有视频的过程与情绪要求（账号所有者原话）

“我希望以后你要多剪辑一些，要把过程讲清楚且转折点和关键点要完整画面，同时要内容充满感染力，能引爆网络传播，以后的所有视频都要这个要求。”

- 全栏目持续适用。时长由故事与真实素材决定，不为短时长删掉必要前情、转折或收尾，也不靠重复/拖长字卡凑长度。
- 比赛视频逐个列清关键转折：此前局面、完整发球/回合、得分结果、比分变化与人物反应；关键点不可只留最后一拍。比赛画面只用官方素材；缺关键素材先补找可用官方来源，仍缺时按 2026-10-04 新口径用原生字卡与旁白事实说明，明确缺口；说明文字不冒充已取得完整关键画面。
- 文案与剪辑一起呈现进程和情绪，保留现场声、真实反应、完整终局；技战术与人物故事必须有证据，传播感染力不靠夸大赛果、编造心理或替对手诊断。
- 制作阶段按当前缺口重新分配代理：故事编辑、关键回合与原声、素材补全、成片制作、独立质检。已完成的检索任务结束，不沿用闲置旧分工。
- 开工前记录关键转折的素材覆盖；发布前逐点核实完整画面与解释对应。算法热度/传播量不是可预先保证的质检结果。

## 2026-10-04：全部栏目使用官方素材，关键点缺口用文字说明

账号所有者原话：“都用官方素材，如果实在缺少关键点就用文字说明”；随后明确：“把这个要求落实到全局”。本条适用于全部栏目未来制作，补充并覆盖 10-03 口径中缺关键画面必须补齐才能继续的解释。

- 比赛画面只用赛事、巡回赛、球员等可核验官方账号/平台发布的素材，记录源链接与本场身份；不把转载账号标成官方，不为补关键点改用非官方比赛画面。
- 先查可用官方来源、逐点记录覆盖；仍缺关键点时，允许使用原生 `title_card` 与旁白事实说明继续制作，简短交代当时比分、发生的事件及结果，并明确“官方集锦未收录这一关键点的完整过程”。按真实缺口描述，不假称已经完整覆盖。
- 有完整官方关键回合就从发球/动作开始保留到结果及真实反应；不能拿其他回合冒充缺失关键点，也不靠重复片段或长时间静卡凑时长。
- 比分、转折和人物行为仍须核实；统计、原声审听、双语字幕、成片质检及发布凭据要求不豁免。发布前检查文字说明与缺口、已有画面及旁白一致。
- 封面仍按既有正式来源口径优先本场官方高清实拍，赛事/巡回赛图库及 AP、Getty、Jimmie48 等已允许的正规通讯社或摄影来源继续适用；不收窄为仅 WTA 网站，也不把封面授权扩大为非官方比赛视频授权。

## 2026-10-03：关键时段精彩原声与中英文字幕（全局要求）

账号所有者原话：“同时尽量多的保留原声关键时段的精彩解说，配上中英文字幕。这个成为全局要求。”

- 全栏目持续适用。选材/剪辑时主动寻找关键时段精彩的现场解说、完整语句与真实反应，让原声承担过程和情绪；不要因合成旁白或字幕省事而只剩最后一拍、删掉好解说。
- 为保留的原声逐句核验并配置准确中文和英文字幕，保留句头、句尾、上下文及分屏阅读时间；翻译忠于原句，不能编造球员引语。英文解说用英语原文及中文翻译。
- 自配中文旁白安排在原声段落之间，负责必要坐标、前情和解释。双语仅绑定对应的真实源解说；不把自配旁白伪装成转播原声，也不让旁白覆盖精彩解说。
- 发布前核实际混音、字幕时轴与完整关键回合；ASR交叉核验诚实记录方法，未实际听过不得声称人工听审。

## 怎么用

| 什么时候 | 做什么 |
|---|---|
| 选题定下来 | 过清单 **A** |
| 写 spec 之前、定稿之前 | 过清单 **B**（钩子、封面、旁白结构都在这一段） |
| 发 `mode=render` 之前 | `python3 tools/taste_preflight.py --slug <slug>`：清单带上这条 spec 的实际字段，再跑 main 上已有的口味闸（`--dry-run` ＋ 只在 CI 里的那批判据），红了先修 |
| 推送、返工 | 过清单 **D**；被否过一次之后看 **C4** |

标记：**〔闸〕** main 上有机械闸，`--dry-run` 就红（手写 spec 硬拦；自动 spec 有几道只报）；
**〔CI〕** 判据只在 pytest 里，`taste_preflight` 会替你跑；**〔自查〕** 没有机械闸，靠清单；
**〔推断·只自查，永不做成闸〕** 后面跟着规则编号，只提醒、永不拦（见上）；
**〔提示词〕** 自动链的 DeepSeek／MiniMax 教材里教了。口味规则挖出来、语料上验证过零误伤的
六道文案／结构闸（规则编号 `hook-key-moment-and-result`、`hook-no-jargon-or-allusion`、
`copy-fields-one-source-of-truth`、`narration-match-flow-every-set`、`post-win-celebration-kept`、
`story-info-band-per-match`）判据单一出处在 `tools/taste_gates.py`，坐在 `validate_spec`
（`--dry-run` 就红）和采访线的入口检查链里：手写 spec 硬、已发的按原文冻进
`data/legacy_taste_gates.json`（只许减）、自动 spec 只报。
**〔在途闸〕** 09-27 定的 O2+O3 封面认人＋睁眼，由 `face-eye-checks` 那一包接进
赛场之上抽帧封面（`precheck_cover_face`，源片一到手就查）和赛后开麦封面（`audit_interview_cover.py`）
——合进 main 之前照旧按〔自查〕过，合进之后 `--dry-run` 就红、
`taste_preflight` 跑的那趟 dry-run 自动带上，**这几处的〔在途闸〕要当场改成〔闸〕＋函数名**。

引文前写「转述」的几条（合集门槛、不提彭帅、否过一次给并排候选）是从他的选择或做法推出来的，
不是原话——标着〔推断·只自查，永不做成闸〕（见上），**只按〔自查〕过，没有他的原话之前不许做成闸**。
BGM 走曲库那条不在里面：它是他 08-29 在两个方案里亲口选的「第二种方案」（#645），
`music_problem` 早就在 main 上。

优先级：**新口径盖旧口径**（文末「已被取代」）；**他重申过的就是决定**；他的说法和数据
对不上时摆证据、按数据走（CLAUDE.md「他说的和数据对不上」）。日期都是 2026 年。
